# AI Trader 工程纪律

项目规则以 [AGENTS.md](../AGENTS.md) 和个人通用规则为准；本文保留工程复用、验证选择及发布失败边界，版本历史见 [CHANGELOG](../CHANGELOG.md)。

## 1. 产品边界

Sente 的网页与桌面客户端共用云端 Runtime，支持本站模拟及快期模拟账户：

- 展示国内期货品种、实际交割合约、主力合约、实时行情和 K 线；
- 展示 TqKq 模拟账户、持仓、活动委托和成交；
- 手工三键下单逐张确认；用户明确要求时 AI 在 Runtime 内部执行租约内做受控模拟开仓、撤单、平仓与确定性止损；
- 使用官方历史数据完成可复现回测与历史回放；
- 保持 `liveTrading=disabled`，不接 `TqAccount`、`TqCtp` 或真实期货账户。

实盘保持关闭；结果未知不自动重复提交，撤单/追单通过已有受控模拟委托链。

## 2. 成熟能力复用

| 能力 | 采用方式 | 边界 |
| --- | --- | --- |
| TqSdk 3.10.2 | 直接使用官方合约发现、行情、K 线、账户、持仓、委托、成交、TqSim 和 TqBacktest | 快期事实来自 TqKq，本站模拟来自独立引擎，回放有独立历史上下文；SDK 升级单独核验 |
| TradingView Lightweight Charts | 直接用于 K 线、成交量和权益曲线 | 遵守 Apache-2.0 和署名要求 |
| TDesign / Carbon 工作台模式 | 参考紧凑筛选、数据列表、状态层级和响应式规则 | 不引入整套 UI 框架，保持现有 React 与视觉语言 |
| vn.py OffsetConverter | 作为平今、平昨、冻结仓位的行为和测试参照 | 不引入整个 vn.py，不使用非官方 TqSdk Gateway |
| vnpy_ctastrategy | 仅当 TqBacktest 无法满足分析要求时再评估 | 不作为首选回测引擎 |
| NautilusTrader / LEAN / Hummingbot / Freqtrade | 只借鉴职责分离、风险引擎、Executor 有限任务和保护器语义 | 不引入第二套执行内核，详见 [成熟交易工具取舍](AI_TRADING_MATURE_TOOL_REVIEW_2026-09-04.md) |

编写 TqSdk 代码前必须阅读信易科技官方 `tqsdk-trading-and-data` 技能说明和对应参考文件。当前品种、合约和行情实现遵守以下规则：

1. 用 `query_quotes(..., expired=False)` 发现可交易交割合约；
2. 用 `query_cont_quotes()` 获取当前主力对应的实际交割合约；
3. 主连代码用于发现、展示和历史研究，委托必须绑定未到期的实际交割合约；
4. `get_*` 返回的是由 `wait_update()` 更新的活动对象，Runtime 只接收脱离 Entity 的普通快照；
5. 长历史下载使用官方 `DataDownloader` 前必须先核对当前账户权限和许可。

## 3. 改动与验证

先确定用户可观察的结果，追踪受影响入口、消费者和正式写入路径，再做最小可回滚改动。复用现有接口、状态和事务，不为审阅意见增加第二事实源；只有实际跨越交易、认证或发布授权边界时才停下补齐范围。

按改动选择既有检查，PR 的 CI 墙钟目标为 5 分钟以内。文档核对内容、格式及引用；前端运行前端 lint 与受影响单测；后端运行后端检查及受影响测试；CI、依赖锁、共享契约或打包发布文件运行对应构建或全量。全量测试只在合并进 main 后跑一次，正式发布仍要求 main 全绿。具体 CI 实现以当前工作流为准，不重复维护作业清单。

测试保护真实故障与关键不变量，默认并行；慢用例使用假时钟或可配置短超时，避免真实 sleep。源码、diff 和依赖锁未变时复用绿灯；提交、文档与生成证据不触发应用重跑。触及重复覆盖或只核对内部实现的测试时合并或删除，不顺带清理无关测试。

界面、交易、恢复或发布边界变化时，选择对应的现有浏览器、Runtime/Sidecar 集成或烟测。用正式用户入口验收；线上写入只用快期测试账号，主人账号只读。只改文档不打包、不部署。安全边界和发布授权见 [AGENTS.md](../AGENTS.md)。

改动以提交或 PR 推送到 GitHub，说明问题与结果；用户可见行为、发布或部署变化在对应 CHANGELOG 版本署名执行 agent。审查集中核对全部 diff 与证据，不逐条追加可选打磨。

## 5. 停止条件

出现以下任意情况时，不能继续补丁式开发：

- 修复需要新建通用 OMS 或 Event Sourcing；
- 为审阅意见增加新状态、表、Owner、Shadow、Projection 或自动重试；
- 同一 PR 同时修改行情、下单、平仓、回测和更新器；
- Fake/Fixture 数据可能在正式界面伪装成 TqKq 事实；
- TqSdk 权限、许可证或实际字段没有得到官方资料或只读实测确认；
- `liveTrading`、真实账户或自动执行边界发生变化。

PR #12–#15 是这些停止条件的历史案例：Codex 反复 review 把模拟买卖闭环审成 Saga、Journal、Shadow 双内核，最终被 PR #16 的薄实现取代。处置见 [未合并执行 PR 资产清单](HISTORICAL_EXECUTION_PR_INVENTORY.md)。

## 6. 发布失败处理

- 任一代码、CI、桌面、TqKq 或签名门槛失败：停止发布，不修改线上清单。
- TqKq 委托结果未知：只查询原订单，不重新提交。
- 烟测出现意外成交：停止继续创建订单，只通过已经验收的手工平仓流程处理该模拟持仓。
- 更新安装失败：保留当前已安装版本和应用数据；不得在 `/Applications` 安装第二个带后缀的 AI Trader。

正式发布入口与回读要求见 [三端与网页部署](THREE_PLATFORM_AND_WEB_DEPLOYMENT.md) 和仓库 [AGENTS.md](../AGENTS.md)。
