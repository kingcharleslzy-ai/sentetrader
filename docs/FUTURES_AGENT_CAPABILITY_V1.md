# 期货 Agent 能力 v1

本文件给开发者看两样东西：下文内置 AI 的内部架构与设计取舍，以及后面的界面表面 × 命令 × 观察覆盖表。功能做什么见帮助目录（`GET /api/app/help`），接口参数与错误码以能力目录（`GET /api/agent/capabilities`）为准，外部 Agent 的操作规则见 [skills/ai-trader/SKILL.md](../skills/ai-trader/SKILL.md)。

## 目标与边界

Sente 的 Agent 默认是面向国内期货的决策助手，不只是把通用模型接到工具上：它解释界面、读取当前行情与账户事实、分析 K 线、搜索最新外部信息，并调用受控的模拟交易工具。

实盘始终关闭。模型没有 TqApi、账号密码或 Sidecar 令牌；行情、账户、候选和模拟执行都经过 Runtime 的窄工具与确定性校验。外部信息由 Runtime 的 `web_search` 工具在服务端检索（唯一后端 DeepSeek Search，官方公告与统计查询追加官方域名检索），研究数据与消息面走 `get_research_brief`，模型不持有搜索密钥。

## 内置引擎、操作说明与开放接口

Runtime 自己的模型循环（`native_agent.py`）用 openai SDK 以 OpenAI Responses 协议直连各供应商，工具是进程内函数；模型密钥在服务端端点表里，没有子进程或外部引擎。

操作说明随 Runtime 内置于帮助目录 `trader_runtime/help/catalog.json`（`app_help.py` 加载、校验），能力目录由本版本实际业务路由和工具定义生成。模型先调 `app_capabilities`，按 operation 查参数定义，再经 `app_call` 操作并回读；无需额外插件。模型没有通用 Shell 写入权限，也不继承外部应用或 MCP 工具。`POST /api/agent/call` 的 HTTP 操作沿用实际业务接口，`tool:` 操作复用内置工具及其原有检查；账户头怎么随调用转发见 SKILL.md“账户与多用户”。

认证、交易执行、风险权限和更新机制是受保护核心，模型不能修改。策略规则和参数只经完整 StrategyPlan 接口保存、验证和启动。图表配置（`/api/app/config`）按 revision 修改、可回滚上一版本；独立扩展只支持 SMA、EMA、价格通道的声明式配置，不执行任意代码。

历史回放使用独立的模型会话、资金和策略库：回放内 `web_search` 等联网与研究工具不注册，模型不能切回当前账户操作；回放窗口里的语音通话绑定该次回放，关掉的回放按 `replay_not_found` 失败关闭、不回落实盘。回放的到价提醒、画线与收盘前/风险度提醒记在回放子 Runtime 的库里。回放命名空间里与回放无关的用户级接口（语音状态/音色/播报、模型列表与偏好、账号偏好、owner 状态、账户目录只读）由主 Runtime 以当前登录用户应答；账户写入不转发。

登录接口（认证接口不进能力目录，agent 不得替用户登录）：启用接入池时 `POST /api/auth/tqkq`（body `{"username","password","inviteCode?"}`）是唯一登录入口，客户端不再调 `POST /api/auth/owner`。池验证口令后建 / 复用 `cloud_users` 里 role=user 的用户（再次登录按用户名、invitedBy=tqkq-login 识别，不需要此前的绑定记录）并发会话 cookie，返回 `{status:"logged_in", userId, username, role:"user", accountId, assembly}`：配置了本站模拟盘的部署只开或复用本站模拟并设为默认（accountId 为 paper 账户 id，assembly "connected"），不建、不绑定、不重新启用 `tqkq-sim`、不装配 sidecar；没有本站模拟盘的部署密封口令绑定池账户（accountId 为 `tqkq-sim:<hash>`）。首次登录要有效邀请码（403 `invite_code_invalid`，口令验证通过后才消费；消费与建号在同一事务，失败整体回滚、码不消耗，一次性码并发只成功一个）；主账号的快期用户名 403 `use_owner_login`；用户名是 Runtime owner 或分享码账户时不走池、按本地密码校验，成功返回与 `POST /api/auth/owner` 相同的 `{status:"authenticated", …, bindings}`，失败 401 `invalid_owner_credentials`。口令错误 401 `tqkq_login_failed`（reason: auth_failed / timeout / capacity_full；从未登录过的新账号名带 `canRegister`），按 IP 与用户名双键限频（429），池不可用 503 `account_pool_unavailable`；未启用接入池时未知账号名 404 `{code:"account_not_found", canRegister}`。`canRegister` 为真（开放注册且填了邀请码）且 reason 是 auth_failed（或 404）时，登录框问“用这个账号和密码创建新账号？”，确认后调 `POST /api/auth/owner/register` 并登录。`GET /api/auth/owner/status` 匿名返回 `tqkqLogin: {enabled, inviteRequired, registerUrl}`（`registerUrl` 只为旧客户端保留）与 `paperConfigured`。没有任何账户授予的 role=user 用户：业务请求 403 `tqkq_account_required`，不回落到管理员默认账户（配置了本站模拟盘时先幂等补开 `paper:<id>` 再重解析）；装配中 / 排队中的账户 `GET /api/runtime/status` 保持可读（降级载荷，`account.poolStatus` 报进度）。

## 一次回答的决策链

1. 识别意图：概念解释、最新信息、行情/账户分析、策略评估或模拟交易动作。
2. 读取事实：方向判断和风险评估先调 `get_futures_decision_context`，由 Runtime 一次汇总并校验状态、实际交割合约、行情、K 线分析、账户、持仓和活动委托，并标明分析、候选与模拟网关是否就绪。交易候选不先调它：`propose_order` 出卡时跑同一套就绪门禁（同一内部计算），结果写进卡的 `readiness` 与详情风控行；未就绪不出卡，返回 `proposal_gate_not_ready` 与 `userFacing` 中文缺失项；行情不可用时返回决策上下文同名错误码，回合按“实时行情未就绪”收口。用户指向屏幕（“这个/这里/屏幕上/我看到”）时，Runtime 组装回合时附本对话窗口快照摘要（≤1.5K 字），不要求模型自己读屏；未命中或 `chat.autoReadScreen=false` 时不附。
3. 补充外部证据：当前合约判断与“今天、最新、新闻、政策、天气、宏观”类问题默认调 `web_search` 核对当天或过去 24 小时的信息；用户明确只看技术面或不要联网才跳过。新鲜度门是事后标注：标为行情相关的回答只要调过 `web_search` 或实时行情/账户工具即视为已核验；都没有却断言了行情/新闻/账户数字时，同一 turn 先发 `warning`（标题“本轮未读取实时数据”，客户端渲染见帮助主题 chat）；闲聊与元问题（什么模型、什么版本、你是谁）豁免。提示词四类路由：软件用法先读 `GET /api/app/help`；实时事实调工具；研究数据（排名/仓单/基差/库存/期限结构/手续费）与消息面用 `get_research_brief`；当前日期与时效核验用 `web_search`；交易常识直接回答。
4. 对立验证：同时检查多头理由、空头理由、量价/持仓量、账户暴露和判断失效条件。
5. 通俗输出：默认“结论、为什么、风险、现在怎么做”四个短段；一句话先给结论，理由不超过三条，再给行动条件和失效条件。工具名、字段名、状态码、错误码与未解释的英文缩写不进普通回答。
6. 交易门禁：用户消息引起的回合（打字、语音委派、chat:send）不提供 `execute_simulation_trade`、不替用户确认卡片；会自动下单的策略只在用户这句话要启动它时启动。AI 自主执行只用于策略自动下单等 AI 自己发起的操作，Runtime 为此自动建内部执行租约，并在每次动作前重查行情、账户、持仓与用户写进策略的预算（模拟账户没有平台或账户级风险规则，AI 也没有提议风险规则的工具）；明确停止或急停后不自动恢复。停止三档、保护性退出与租约到期的行为见帮助主题 protection；停止接口与工具 `stop_simulation_execution` 共用 `scope` 参数。`trade.aiAutonomy`（行为见帮助主题 preferences）关闭时 Runtime 拒绝 `execute_simulation_trade` 与 AI 建租约，策略监控只监控不下单（`ai_autonomy_disabled`）。`trade.aiAutonomy` 与 `trade.voiceOrderConfirm` 只经偏好接口（`update_preferences` / `PUT /api/preferences`）修改；界面命令载荷带这两个键或已退役的 `strategyInstance` 在入队前即拒，纯界面请求不能顺带改交易开关。工具失败可追查：`task.progress` 的失败步骤带 `errorCode`，Runtime 日志 `agent_tool … outcome=<ok|错误码>`。出卡工具的业务拒绝按 `userFacing.candidateIssues` 原话回复（真正的就绪门禁才是 `proposal_gate_not_ready`）；没走固定路线的回合里同一拒绝第二次出现即以拒绝原话收尾，不连调重试。语音只读快查（fast 回合）只拿只读工具，其中 `app_call` 只放行只读操作（`operation_is_read_only`），写操作在执行处拒绝（`fast_path_read_only`）；到价提醒说法（`voice_intents.ALERT_WORDS`）不进快查与语音前台，走带 `create_price_alert` 的完整回合。多账户角色与执行负责人见帮助主题 accounts。

## 工具分层

- 行情与账户事实：`get_runtime_data_status`、`search_instruments`、`get_market_snapshot`、`get_account_summary`、`get_positions`、`get_account_activity`。
- 报数口径随工具返回：`get_account_summary` 另带 `pnlFields`（各盈亏字段原值与口径，口径见帮助主题 positions）与 `pnlRule`，问今日平仓/手续费/今日盈亏直接报字段，不从成交或交易日志加总（`get_trade_journal` 按原开平价逐笔配对，与账户平仓盈亏口径不同，描述里写明）；`card.account` 卡仍是原摘要。`get_account_activity` 另带本账户保护单 `protections`（标签与执行卡同一映射 `conversation_cards.protection_state`）与 `protectionRule`；对话推荐问题也只用有效保护。
- 账户现状只按本轮读回：`trader_tools.account_state` 是唯一读取入口——整账户 `positions`、仍挂着的 `workingOrders` 与全部仍生效的 `protections` 取自同一次组合读取（`provider_read_snapshot(account=True)`），带 `asOf` / `asOfLocal`；数据源 stale/connecting/unavailable/backup 或委托缓存陈旧都按读不到（`available: false`，要求不陈述现状）。撤单、挂/撤保护与停止工具成功后回报带写后重读的 `accountAfter`，计入本轮新鲜度证据；说到持仓/挂单/委托/保护的非出卡回合，上下文附回合开始时的同一份读取，出卡路由以出卡工具自己的读取为准。回合内以末次账户读取为准：开头读取与每次 `accountAfter` 共用一个更新入口（`_Turn.account_reads`）；`get_positions` / `get_account_activity` 各读一半、不在同一切面，不参与。写操作后请求里开头那段现状被替换（读回成功＝以最近一次 `accountAfter` 为准，失败＝开头那份已过时、不要陈述也不要说没有）；末次读取失败时此前的账户证据不计入核验、正文不流式放出，答案前加确定的“账户现状未能确认”脚注（不靠模型自述；语音回合第一段同样以此开头）；写操作本身的成功与行情/新闻证据不受影响；回合日志 `agent_turn … account_reads=` 留每次读取。
- 思考不进正文：供应商思考走独立通道，Runtime 从不收进正文；模型把自言自语写进正文（`<think>` 块，或句首的 Wait/Hmm/Let me、“等等，”“重新组织：”“用户此前…”等）时，正文出口 `native_agent.visible_answer` 截断：流式停止外发，屏幕显示“正在整理回复…”（不通知语音念稿监听），收尾禁工具重写一轮，仍不干净只留重写里标记前的话，重写失败或为空显示固定一句；会话历史、`message.completed` 与语音念稿只用最终文本。
- 下单规划器（设计见 `docs/ORDER_INTENT_V2.md`）：所有出卡入口——交易 AI 唯一的出卡工具 `propose_order`（严格结构、一次一单，`legs` 不出卡；先按 `ProposeOrderArguments` 校验、`resolve_words` 读合约）、打字快速路径（解析器有把握的下单句不经模型）、HTTP/CLI/外部 MCP 的三个出卡路由（下单票也走它）、目标持仓接力的下一步、语音前台——都构造 `OrderIntent`（`order_intent.py`）交给唯一的 `order_planner.plan`：在一次整账户读取（`provider_read_snapshot(account=True)`，开仓不读）上定合约月份、开平、今昨（`close_allocation`）、手数和价格（`leg_price_intent`）；各项怎么定见帮助主题 order。反手“确认一次”的第二段只承接计划存储里 `confirmOnce: true` 的授权，缺标记的旧计划第二段仍出卡等待确认。开仓门禁分两层：下单安全检查对所有入口生效（合约在目录且未到期，报价、时段、最小变动价位、涨跌停、账户最新与可平量由 `build_candidate` 写卡时核对）；AI 决策就绪（决策上下文的 proposalReady 加日内开仓限额）只对 AI 发起的出卡生效——内置工具、语音前台、外部 `tool:propose_order`、打字快速路径、目标持仓路由与接力。HTTP 单笔出卡路由只有安全检查：网页/桌面下单票与外部调用方用同一种 Bearer 会话令牌（CLI/MCP 还带同一个 `tauri://localhost` 来源），Runtime 分不出是人点的还是 AI 调的；回放下单票也在这一层（回放导出没有到期日，不当作到期）。出卡后的确认链 `ProposalService.confirm` 不变。策略出卡、停止并平仓与策略自动执行的今昨拆分用同一份 `close_allocation`。
- 确定性技术摘要：`get_market_analysis` 从最近 20–120 根 K 线计算区间涨跌、5/20 均价、量比、持仓量变化、平均振幅、趋势标签，以及 BOLL(20,2)/ATR(14)/RSI(14)/CCI(14) 最新值与一句读法（口径与 tqsdk.ta 一致，由对拍测试钉住）；模型不能自行伪造指标。
- 统一决策上下文：`get_futures_decision_context` 组合上述事实，分别返回分析和模拟通道的确定性门禁及稳定的中文用户文案；内部代码和值只供程序判断。`propose_order` 开仓复用同一计算（平仓沿用持仓/行情/可平手数校验），因此下单请求是一轮。用户说出的价格由 `limitPrice` 原样传入，Runtime 不按盘口重定价；没说价才用 `priceIntent`，两者都没传时由 Runtime 确定性默认（平仓对手价、开仓按 `trade.defaultPriceIntent`）。平仓先核对持仓，没有持仓时诚实收尾，先于平今/平昨判定。价格超出涨跌停或不是最小变动价位整数倍时不出卡并返回中文原因，绝不静默改价。模拟动作不弹授权确认，但每次都重新通过最新事实与风险规则。
- 下单“钱”估算：只读工具 `estimate_order`（同 `GET /api/simulation/order-estimate`，口径见帮助主题 order），归属 order-proposal 技能；“开一手要多少保证金 / 最多还能开几手 / 平掉能腾出多少钱”路由到通用回合由它回答，不出卡。开仓一手手续费与 `fee`、下单票同一入口 `ProposalService.open_fee_basis`（自定义 → 交易所标准按现价 × 乘数 → 行情源每手参考值，`commissionSource` = custom / exchange_standard / market_source）；AI 的 `get_market_snapshot` 把 `contract.commissionPerLot` 换成同一入口的值（行情源每手值对按成交额收费的品种只有约 1/乘数）。`propose_order` 的开仓卡把同一估算写进 `payload.estimate`，只供展示、不新增拒绝条件。
- 合约信息与交割月提醒（只读）：行情快照与合约目录带 `contract`（sidecar 报盘字段经 Runtime 校验后透传）与 `deliveryNotice`，规则与提醒行为见帮助主题 contract-info、delivery。主动提醒由 Runtime 的 30 秒账户循环发出（不依赖客户端读持仓），经统一提醒入口投递，SQLite `delivery_notices` 主键幂等；只提醒，不平仓、不新增拒绝下单条件。
- 统一提醒：所有主动提醒经 `reminders.deliver_reminder` 一个入口投递（开关、认领与对话消息同一事务、`reminders` 表去重、落点与类别见帮助主题 reminder-center）。
- 实时网络信息：`web_search` 函数工具由 Runtime 调 DeepSeek Search 检索；公告、保证金、涨跌停、交易规则、统计、宏观数据等查询额外查官方域名，按 URL 去重后一起交给模型，返回标题、链接、摘要与发布时间；DeepSeek 与 GLM 模型统一走这条路。回放内不注册；未配置密钥返回 `web_search_unconfigured`。网页结果只作背景证据，不替代交易所行情或账户事实。
- 研究信息统一入口：`get_research_brief` 按 topic 路由——position_rank / warehouse_receipt / spot_basis / inventory / term_structure / fees_margin 读 AKShare（与 `GET /api/research/*` 同一服务与缓存）；news 用 DeepSeek Search 按品种中文名搜近 7 天资讯、DeepSeek Fetch 读前两篇原文（每篇最多 6000 字，失败保留标题摘要），15 分钟缓存；desk 返回调研汇总（与 `GET /api/research/desk` 同一服务），工具侧只读事实与已生成的判断、不触发生成，而 HTTP `GET /api/research/desk` 在能力目录标为非只读（当天判断未生成时触发一次模型生成）。各源独立失败，每条带 source 与 status；回放内不注册。消息面只作背景证据，缺失时明确说明，不用记忆补数。
- 实时研究情报四个只读工具（`ResearchLiveService`，`research_live.py`；来源分层、保留期、AI 筛选分层、今日新闻要点与本机缓存的行为见帮助主题 research）：`get_news_flash(product?, hours=24, limit=20, macroOnly=false, officialOnly=false)`、`get_foreign_markets(product?)`、`get_economic_calendar(days=7, region?, product?)`、`get_interest_rates()`；HTTP 同款 `GET /api/research/flash` 与 `GET /api/research/calendar`（注册在 `{dataset}` 回退之前）。实现要点：

## 技能注册表

内置 AI 的每项能力都是一个技能：`services/trader-runtime/src/trader_runtime/agent_skills/<name>/SKILL.md`（Agent Skills 开放规范）是唯一事实源，Runtime 启动扫描为注册表，派生 AI 工具隐藏集、能力目录的技能归属、HTTP 写接口的技能门禁（app 级 dependency `write_skill_gate`：按匹配路由查 `METHOD path → skill` 归属表，有归属且写方法即拦；四条写路由刻意留给各自的 handler 并有书面理由——回放 control 的 close 是安全退出动作、邀请码生成与停用以认证层 owner 会话为门、简讯刷新保留档位未开时温和的 `status: "disabled"` 契约）、语音/打字路由的技能可用性检查与帮助的技能章节。每个内置 AI 工具与每个写接口恰好归属一个技能（测试钉住）；技能管理接口 `GET/PUT /api/admin/skills` 刻意不归属——它是恢复入口，停用 admin-console 不得让主账号无法再启用技能。添加/移除行情专用快期账号的两条路由（涉及口令）列在 `HUMAN_ONLY_ROUTES`，不进能力目录，但仍归 admin-console 的写入门禁。

开放控制两层：主账号全局启停（`skill_settings` 表，缺行=启用，403 `skill_disabled`）与档位勾选（`plan_tiers.config.skills`，成员档位未勾选 403 `feature_not_in_plan`，兼容码；机器可读原因 `not_in_plan` 在 `GET /api/agent/skills`）。停用只管 AI：本身就是 AI 功能的技能（`AI_FEATURE_SKILLS`，`GET /api/agent/skills` 标 `aiFeature: true`）停用后对所有人（含主账号）停；其他技能停用只从 AI 那里拿走（内置工具隐藏、能力目录不列、`/api/agent/call` 拒绝、语音/打字路由拒绝），用户自己的界面按钮与它们直接调用的接口照常可用。owner-only 技能仅主账号；owner 不受档位约束、受全局停用约束。旧档位配置的 `features` 键一次性幂等迁移为技能组。

渐进披露三层（内置 AI 与外部 Agent 一致）：目录层给可用技能的 name + description，内置 AI 的目录行再接“负责：<它负责的帮助主题标题>”（帮助目录每个主题的 `skill` 字段，`app_help.skill_catalog_line`；外部 Agent 在 `GET /api/agent/skills` 的 `helpTopics` 里拿到同一份）（不可用技能不出现，`activate_skill` 的 enum 也不含）；指令层 `activate_skill` 返回 `<skill_content name="…">…<skill_resources>…</skill_resources></skill_content>`（外部 Agent 原样拿到；内置 AI 改为“挂上”：手册进系统说明、该技能的专用工具从下一轮起声明，工具回报只说挂上了什么，压缩不丢，同会话重复激活去重）；资源层 `read_skill_resource` 只允许该技能目录内的相对路径。

内置 AI 打字回合的 token 策略：
1. 按技能延迟挂载：`TraderReadOnlyTools.DEFERRED_TOOL_NAMES`（定义里的 `deferLoading`）列出的不常用工具（回测与策略实验室、画线、流程、复盘日志、记忆、回放控制、外盘/日历/利率、结算价/排名/总表、自主下单/查单/恢复执行、分步引导）一般回合不带；提醒、下单估算和策略管理与信号的工具每轮都带（所有者 2026-11-02，多约 4–5 千输入 token），挂载词对它们只带上手册；技能 SKILL.md 的 `ai-trader-mount-words` 加上它负责的帮助主题的 `words`（句中词，`app_help.skill_mount_words`）、`activate_skill`、调用该技能的工具、定义“我的流程”的句子、对象级 AI（策略/实例/委托的 AI 菜单）会挂上该技能（专用工具 + 手册），连续 2 回合（`SKILL_MOUNT_IDLE_TURNS`）没用到就卸下；技能目录里有专用工具且未挂上的技能前标 `*`。确定性路由（出卡、平仓、目标持仓、行情快问、界面兜底、策略信号）与“我的流程”各步仍用各自固定的工具集；句子用到带专用工具技能的挂载词时不走界面兜底轮。
2. 紧凑目录：内置 AI 的 `app_capabilities` 不带 operation 时返回按技能分组的操作、界面命令每字段一行的索引（`uiControl.index`，由 UiChanges 机械生成，对象字段的文字键带说明首句）与 workflow，不重复工具说明与外部 Agent 指南；`query=<关键词>` 只列匹配的操作、工具与界面字段；`operation=<原文>` 返回完整参数，`operation=ui:<字段>`（内外一致）返回该字段完整定义与说明里提到它的句子。外部 Agent 的 `GET /api/agent/capabilities` 与 MCP 目录不变。
3. 界面兜底回合的系统说明只带这份字段索引，不内嵌整份 UiCommand JSON Schema。
4. 工具参数发给模型时去掉 pydantic 自动生成的 `title`；策略生命周期、自主执行细则、联网新鲜度细则放在 strategy-management / order-ops / web-research 手册里，挂上时随行。
5. 内置 AI 用 `app_call GET /api/app/help` 不带 topic 时拿到目录（分组与各主题标题、一句摘要），全文按 `query.topic` 读一个主题；带 `query.search=<关键词>` 返回各主题里提到它的句子（每主题一句、写位置的优先；写位置的主题排前，其次按标题 / 摘要 / 步骤里提到多的、全节提到次数多的，最后按说明书顺序，最多 16 条）；说“没有这个设置 / 在哪”之前要先这样核对。接口本身不变。
6. 刚结束那一回合的工具结果再带一回合时每条最多 4000 字符（`CARRIED_TOOL_OUTPUT_CHARS`，注明已截断），本回合内仍完整。
7. 语音委派的回合只带最近 3 个回合（`VOICE_HISTORY_TURNS`，含语音前台 `append_voice_turn` 记的问答）与当前持仓一行；打字回合仍带整段对话。
8. 计量：每次请求日志 `agent_request … input= output= cached= reasoning= tools=`，每回合日志 `agent_turn_usage` 与表 `agent_turn_usage`（路由、来源、请求数、输入/输出/缓存命中/推理 token、首字与总毫秒，保留 30 天）。

确定性路由命中（语音或打字）先查技能可用性，不可用回统一提示「「技能名」已停用 / 当前档位未开通「技能名」」；等待确认的下单卡优先级不变。

技能清单以 `GET /api/agent/skills` 与帮助主题 skills（由注册表生成）为准；外部接口（`GET /api/agent/skills[/{id}[/resource]]`、MCP 与 CLI 的技能命令）与后台管理接口见 SKILL.md。

## TqSdk 语义

行情对象是由 `wait_update()` 驱动更新的实时引用；主连代码只用于发现和研究，订单必须绑定当前未到期的实际交割合约。账户余额、可用资金、保证金、盈亏和风险度保持各自语义；SHFE/INE 平仓继续区分今仓与昨仓。历史回测使用隔离的 `TqBacktest + TqSim`，不触碰 TqKq 模拟委托账户。官方查询接口（`query_symbol_settlement`、`query_his_cont_quotes`、`query_symbol_ranking`、`get_trading_status`、`open_limit`）由 sidecar 在独立会话线程同步调用后以只读 HTTP 形状暴露，模型永远不直接持有 TqApi。

## 配置

模型池提供 DeepSeek、GLM 与会员可选的 Kimi K3.1 Pro，访问权限由档位模型集合统一决定。各供应商都走 Responses 端点：DeepSeek `api.deepseek.com`、智谱 `open.bigmodel.cn/api/v1`、Kimi Code `https://api.kimi.com/coding/v1`。Kimi 模型标识统一为 `k3.1-pro`（显示名 Kimi K3.1 Pro），默认值集中在 `model_provider.KIMI_MODEL`；复用服务端 `MOONSHOT_API_KEY` secret 直连，不经过 GPT 代理。`gpt-6-astra` 与 `kimi-k3` 偏好及旧档位模型集合在读取时映射为 Kimi，不批量改库；没有 Kimi 密钥时报不可用，不静默切到其他模型。`AI_TRADER_KIMI_BASE_URL` 只收 HTTPS 或本机 HTTP，`AI_TRADER_KIMI_MODEL` 可覆盖上游模型名。Kimi 同时用于默认研讨裁判与空方备用。

模型错误码：HTTP 401/403 `model_auth_failed`；HTTP 429 或流里的限流/额度错误 `model_rate_limited`；其他失败 `model_request_failed`。联网搜索与原文读取共用服务端 `DEEPSEEK_API_KEY` secret。

搜索不可用时不得编造最新信息；行情或账户陈旧/不可用时同样失败关闭。

协议测试固定覆盖两条链：完整建议必须先取得统一决策上下文；交易请求一轮出卡且卡带门禁结果，门禁未就绪时无卡并以中文标签解释；AI 自主执行的模拟动作仍先通过上下文门禁，再由 Runtime 直接执行并回读结果，不出现授权确认。

## 中文建议验收契约

单靠“说通俗一点”不作为验收。每次版本升级至少覆盖这些真实问法：当前合约怎么看、账户断开时还能分析什么、行情过期时能否给方案、最新消息对当前品种有什么影响、模拟下单、平今和平昨、急停后要求下单、结果未知时再次操作。

普通回答必须同时满足：全文自然中文；不泄露内部英文标识；结论在第一句；关键理由不超过三条；行动和失效条件明确；缺数据时说明缺什么以及因此不能做什么；涉及当前消息时给出来源和时间；交易类问法的工具顺序与最终门禁可回放。开放式文字质量使用人工或模型评分，工具调用、安全状态和禁用词使用确定性断言。

普通建议不设机械字数线，但每句话都必须影响结论、关键理由、实质风险或下一动作；通常每段一至两行，删除重复背景、实现细节和不改变判断的数字。用户说“简单、直接、通俗、只说重点”时，只保留一句结论、最多两个理由、一项风险和一个具体动作。普通建议不显示底层组件名。

当前合约判断默认检查实时新闻，必须使用真实当前日期和品种搜索，同时核对网页发布时间与事件/报告所属日期；页面最近更新不代表旧事件变成新信息。普通情况下只采用当前交易日或前 24 小时，周末和节假日采用最近交易日，周报/月报只采用已发布的最新一期。优先交易所、政府和一手行业数据，比较候选来源后最多保留一个新闻要点与一至两个最新可靠来源；找不到足够新且可靠的材料时直接省略新闻，不显示搜索状态、不说“没搜到”，也不拿旧闻补位。

客户端识别上述四段稳定结构，把结论、原因、风险和动作渲染成带字号与底色层级的建议卡：模型提供内容，界面负责确定性排版，避免 Markdown 符号和长段文字堆在气泡中。

## 参考取舍

- TqSdk：采用官方对象更新、合约、今昨仓、模拟账户、回测与下单语义。
- TradingAgents：借鉴“分析—多空辩论—风险—最终决策”的职责顺序，但不引入不可控的多 Agent 自动交易链；借鉴其结构化输出与统一输出语言“先形成有类型的结果，再统一渲染”的方向，以中文文案对象、协议测试与界面确定性渲染的建议卡落地。
- Qlib：借鉴数据基础设施、预测/决策、执行环境和界面分析的松耦合分层；只实现可审计工具层，不把模型预测直接连接执行。
- OpenAI Evals：把真实用户问法保存为可重复的数据集；精确门禁用程序断言，开放式可读性用单独评分标准，避免只凭一次对话判断提示词是否有效。
- DeepSeek Search / Fetch API：经 Runtime 函数工具为当前事件问题提供可追溯来源；实测各模型供应商的内置搜索工具对第三方调用方不生效，因此不依赖模型自带搜索。
- [NinjaTrader News Window](https://ninjatrader.com/support/helpguides/nt8/news_window.htm)：简讯交互对照其按品种筛选和独立提醒开关；它的实时新闻依赖新闻服务提供商，本版简讯是有限来源的定期检索，不宣称等同专用实时新闻流。

## 外部 Agent 与界面操作

外部 Agent 的连接（stdio MCP 入口基于 [官方 Python MCP SDK](https://github.com/modelcontextprotocol/python-sdk)、MCP 配置、打包 CLI）、界面命令生命周期与页面快照读取见 [skills/ai-trader/SKILL.md](../skills/ai-trader/SKILL.md)，命令字段与取值见帮助主题 ui-commands。实现上的取舍：

- 浏览器心跳/回执接口不在 Agent 能力白名单中；MCP 不提供任意 JS、Shell、鼠标或 DOM 执行工具，业务行为仍经原鉴权、风险检查和回放串行调度。连接切换、凭据输入与软件更新的下载/安装不进通用界面命令。
- 前端每次只处理一个命令，并检查身份、环境与界面版本；身份失效的排队命令不派发；命令记录只在内存里保留五分钟。窗口只回报“已执行”或“执行不了”，applied 由 Runtime 判定：按这次及之后心跳里 React 已提交的状态核对所改字段（`ui_control.changes_match`，全系统唯一一处回执规则），7 秒内没对上记 unknown；窗口因版本已变回“执行不了”时，与派发时版本不符一样记 rejected 且不带 state，调用方读最新 revision 后换新 commandId 重发；applied 不保证行情请求已完成。界面表面的 id、旧名、游客可用与否统一在 `services/trader-runtime/src/trader_runtime/ui_surfaces.json` 一张表里，Runtime 与客户端都读它。图表周期切换复用原图表周期接口，保留跟随图表策略的行为。
- 观察数据不参与界面 revision，避免报价跳动让纯外观命令不停冲突。心跳里的 `state` 是窗口现状的报告：Runtime 只做形状与数量上限校验（`highlights` ≤20、`chartAnnotations` ≤50 条宽松记录），不用命令输入的严格规则拒绝它——否则旧契约下画的内容会让整个窗口失联；命令输入（`UiChanges`）仍严格。客户端心跳连续 3 次 422 时在工作区显示登记失败提示（`data-agent-target="ui-control-health"`）并写桌面 frontend.log。
- 模拟限额、策略定义和手续费仍调用业务 API；客户端同步外部保存结果，保留本地尚未保存的限额草稿。

### 覆盖自动核查

`apps/client/tests/ui-coverage.spec.ts`（execution config，单 worker）用界面命令逐个打开每个表面：电脑窗口里的交易台、各侧边面板与子页、报价总表（含筛选、排序与列设置浮层）、设置各页、对话框（含合约抽屉）、折叠段、AI 球菜单、动态卡和图表右键菜单（`chart-context-menu`，三种菜单与子菜单）；另开一个 390×844 触屏窗口，用 `mobileTab`、`mobilePage`、`mobileNotifyFilter` 等逐个打开手机版页面。Runtime 夹具没有的数据（简报订阅与简报、锁屏推送状态、我的流程、提醒、策略与回测结果等）用 route 注入；再经 fake agent 跑一轮真实对话，出对话卡（含折叠“详情”）与流程卡。收集每个表面的可交互控件（a11y：button、a[href]、tab、menuitem、switch、checkbox、radio、separator、input、select、textarea、summary），与 `GET /api/app/ui/windows/{id}` 快照的 `controls` 对照，按 `tests/support/uiCoverage.ts` 分类：**command**（有界面命令）、**capability**（走能力目录接口，如下单 / 限额 / 回放创建）、**exempt**（自由输入框、受保护核心，每条写原因）、**known-gap**（待补清单，每条写缺口与建议）。无人认领的控件、能操作但快照看不见的控件、已补齐却仍留在 known-gap 表的条目，都使测试失败；表面本身必须能用命令打开（rejected 即失败）。不新增 CI 门禁，随既有 `npm run test:e2e` 跑。

核查脚本为每个控件记下所在设置分类或最近的 `data-agent-target`（`group`），按它分类而不按文字：快捷技能栏 chip（`quick-skills`）归 `chat:send`（标签来自技能注册表），设置里「快捷技能」开关归 `preference: ui.quickSkills`；价格阶梯买卖一至五档归 `selectedPrice`。快照 `controls` 带 `title`（仅当与标签不同），快捷技能置灰的原因、可用时“发送：<文本>”由此可见。

按设计处理的：复盘页的 `dialog: account-detail / fee-hint` 只在 `view: review` 下可开（交易台发命令 rejected）；对话框打开时快照以对话框为根，背景控件不在 `controls` 里（观察器设计）。known-gap 表当前为空；本核查够不到的两块——复盘月/日展开（假账户没有平仓成交）、方案卡与确认框（execution Runtime 的网关拒绝夹具报价做委托准备，主套件的“AI trade remains a candidate”测试覆盖其用户路径）。

### AI 工作区与事件解释

事件解释（`strategy_explanations.py`，`POST /api/app/strategy-explanations` / `GET …/{id}`）只解释当前账户已发生的成交、执行尝试、保护或委托：服务端从本人的动态快照里按事件编号核对归属并取事实，不收客户端写的依据；一次结构化模型调用，不开应用工具、MCP、Shell 和搜索，30 秒超时；用户发对话时取消该用户正在跑的解释（用户对话优先）；结果只在进程内存，不落库，取不到回 404。客户端只自动解释新成交、明确失败和保护变化，委托只能手动；是否支持由能力目录里有没有该接口判断，旧云端只保留记录与图表联动，不假报自动解释可用。

面板各页的内容、规则与刷新见帮助主题 research、research-debate；外部 Agent 的读取与转述规则见 SKILL.md“调研与新闻”。以下是实现。

新闻只读入口 `GET /api/research/news?symbol=`（自动纳入能力目录）与内置研究工具共用 `ResearchBriefService`：品种名取正式合约目录，按交易所+品种共享缓存与在途请求；失败结果也共享缓存 60 秒，过期才重新请求来源，旧值保留原 fetchedAt / searchedAt 并返回真实错误。每次读取把缓存的搜索结果过一遍同品种的新闻筛选（排除词 + 已有的模型判断，未判的排队），只返回留下的；调研台的相关报道同样只用留下的。

全网新闻后台复用调研台近 7 天阅读名单，每品种交易时段约 30 分钟一轮，日夜盘同规则，休市或日历未知跳过；`news_search.NEWS_DOMAINS` 是唯一来源白名单，只搜官方发布者与行业数据站，排除已直接采集的主流财经新闻站；3 站一组轮换以适应 128 字符限制，按开工检修、库存到港、利润成本、政策限产、进出口主题轮换，结果来源标“全网搜索”。官方轮次由 `web_search.official_query` 统一追加对应部门 / 交易所查询，普通结果保留、官方结果按 URL 去重追加。结果经 `research_live.ingest_search` 进入原有合并、`news_screen` 与事件方向流程，再供调研事实 / 新闻面读取。新闻要点生成前 Fetch 最多 3 篇、各 2000 字，失败保留标题摘要。新闻采集、调研与原文读取按 `model_call_days` 的 `news-search` scope 计尝试数，对话 AI 的 `web_search` 另按 `agent-search` scope 计（各自每日默认 600、跨重启 / 槽位共享；聊天搜索不挤占新闻采集额度）。

调研汇总 `GET /api/research/desk?symbol=`（`ResearchDeskService`，`research_desk.py`；公开源在 `research_sources.py`）：

- 采集与缓存：按交易所+品种共享，事实 5 分钟内复用，并发读者共用一次采集，任一类加载中时 30 秒后重读；行情缺失时 30 秒后重读而不是缓存 5 分钟。事实存进共享表 `research_desk_facts`（重启与另一槽位立即可用）。面板读取不等采集：旧事实照样先给、后台重读并带 `factsRefreshing`；从没采集过的品种最多等 0.3 秒，没好就先给各块“加载中”，客户端 4 秒后再读；旧于 30 分钟的事实上不开新判断，等重读落地再判。AI 工具（`get_research_brief` 等）仍等新事实。快讯的品种视图读一份所有读者共用的解析副本（`research_live._parsed_rows`，按计数器与行数判断表是否变过，只重解析变过的行）。
- 分段：快讯条目作为 `section=flash` 的事实进判断输入与资料来源，不单列一段；macro 按品种类别过滤（沿用日历的 `CALENDAR_CATEGORY`，未归类品种不列宏观），`E.calendar` 只列与该品种相关的事件。
- 八类事实与来源：
  - market：主力合约日线（最新价与日涨跌、近 20 个交易日涨跌 / 振幅 / 均线位置、持仓变化与量比、RSI / 布林 / ATR 读法）；有外盘对应的品种加 `M.foreign`，读统一外盘入口 `foreign_market.py`（约 3 秒共享一次读取，失败或部分成功 5 秒后重读；随调研事实 5 分钟复用，不是整个调研台每 3 秒刷新），关联外盘从没取到时写“某某 暂无报价”。
  - related：`RELATED` 表的产业链关联品种（最多 3 个，主力日涨跌与近 20 日涨跌）；`R.linkage` 联动度（`linkage.py`，改写自 Vibe-Trading `regime.py`）：主力与每个关联品种近 20 个共同交易日的日收益相关系数，3 个及以上品种时再判整体是否抱团——两两 |ρ|≥0.5 的占比按 5 日均值滞回判定（0.65 进、0.45 出），写起始日期，起点就已抱团写“至少自”；与行情段共用一次主力日线读取，不足 21 个共同交易日不出这条。
  - fundamental：基差、仓单、持仓排名、期限结构（不含保证金，也不含与仓单重复的东财“库存”）；生猪加 `D.hog_price`（外三元现货价与 7 日变化）。
  - official（产业数据）：上期所周报仓库库存 `O.shfe_stock`（按当周最后交易日、周五放假取周四，逐日回退查找）、国家统计局旬度重要生产资料价格与近 20 天带百分比的发布标题、CFTC 非商业净持仓（CFTC 拒绝国内 IP，云端经 `AI_TRADER_CFTC_PROXY` 指向主机的出口隧道，只有这一个请求走代理）；配置 `FRED_API_KEY` / `EIA_API_KEY` 后加美元指数、美债 10 年收益率、EIA 商业原油库存。
  - macro：宏观指标、经济日历 `E.calendar` 与利率 `E.rates`。
  - research（机构观点）：东方财富资讯搜索按品种找到的期货公司笔记（取正文里讲该品种的一段），加东方财富期货频道“期货机构观点”（column=516）与“国内期货”（column=513，只取期货日报）栏目——全品种共用一次读取（慢源 `orgfeed`，30 分钟一刷，失败或为空沿用上次好值），只取标题、摘要、链接、时间与机构名、不抓正文，按品种名在标题（观点取板块之后那段）或摘要（从提到处取一段）里挑出；两路合起来近 3 天、每家机构一条、最多 6 条，进判断输入与多 AI 研讨资料；另含 `V.inv*`（笔记里引用的库存数字，最多 3 条）。
  - report：与 news 同源的报道。
  - flash：跨源快讯，每品种最近 24 h 相关 5 条 + 宏观 3 条，引用写“快讯”。
- 来源失败：每个来源 8 秒截止，失败只影响本类；官方源各自缓存 3–12 小时，失败 10 分钟后再试；失败、超时或返回空（任何慢源的空结果都算失败，如机构观点检索为空、统计局价格页 200 空正文）时沿用上次好值（事实标 stale，好值存 `research_live_cache`，重启或另一槽位在好值 TTL 内直接复用、不重取），从没取到过才报该类不可用。
- 事实形状：id 固定（`M.price`、`R.i`、`D.spot_basis`、`O.nbs_price`、`O.cftc`、`N.<链接摘要>` 等）；保留来源质量（有 `fetchedAt` 就带上，旧值带 `status=stale` 与 `error`，所在 section 同为 stale）；`M.price` / `M.limit` 的 asOf 是报价自己的时间（quoteDatetime），报价缺失时 `M.price` 改称“最近收盘价”并用日线日期；`D.position_rank` 标签注明合约（郑商所为“全品种”）。这些字段进模型输入与判断 `basis` 快照，展示时 `changedBasis` 列出当前同 id 事实 label/value 已与快照不同的依据。
- 行情读取：日线一律取 sidecar 的 history 会话（`market_history`，独立的只读 TqApi，缓存 5 分钟，不占实盘会话的订阅；TqSdk 无法退订），只有主力合约另读一次实时报价（现价、日涨跌、涨跌停），关联品种的日涨跌由日线算。
- 判断生成：一次不带工具的 `complete_structured`（默认 `AI_TRADER_RESEARCH_DESK_MODEL=deepseek-flash`），输入只有品种、主力合约、时间与事实；任一类事实仍 `loading` 时不生成。`validate_judgment` 丢弃无引用、`quote` 不是所引事实原文（去空白与引号后 4–40 字的子串）、引用未知 id、数字不在所引事实（label/value/detail）里、含下单用语的论点（丢弃原因计数写日志 `research_desk_statements_dropped`），全部被丢弃时判断失败；`headline` 须带 `headlineBasis` 且同样核对，不合格换成“倾向X，信心Y”；每条论点带程序判定的 `grounds`（data/report/mixed）。`conclusion` ≤60 字，数字须出现在事实里、不含下单用语，否则置空。`points` / `risks` 的 `direction` 模型没给或不合法时 points 随立场、risks 反立场，震荡 / 不明为中性；库里的旧判断读取时同样推断，不改存储、不重算。`change` 与历史表里上一研究日最后一份判断比。信心由 `rated_confidence` 在同一入口按留下的论点计算（档位规则见帮助主题 research；数据类别：行情、关联品种、宏观各算一类，基本面与官方数据每个数据集各算一类，报道不计），模型自报的存为 `modelConfidence`、一句依据存为 `confidenceBasis`（≤40 字），随 payload 写进历史表；多 AI 研讨写进今日判断时同样重算，`modelConfidence` 是研讨自己算的信心。没有这两个字段的旧判断，confidence 即模型自报。内置 AI 的系统提示要求转述 desk 事实时逐条标来源。
- 生命周期：判断共享给所有登录用户，每品种每研究日（北京时间 08:30 翻篇）一份，存 SQLite `research_desk_judgments`，重启后读回；reason 为 daily / swan / manual / news / night（触发条件见帮助主题 research），自动重判在 `trigger` 写原因。`POST /api/research/desk/refresh` 强制重读事实（同一品种最多每 60 秒一次），判断距上次满 1 小时才重算（`manual`）。因资料加载中推迟的重判在资料到齐后没能跑（事实不足、当日额度用完、失败退避）时，判断带 `rejudgeSkipped`（同 `rejudge` 形状）直到下一次重判开始；等完了但生成时间没变，界面不说成功。每天 08:45（交易日）按 `research_desk_watch` 里近 7 天被读过的品种（最多 12 个）预生成，用量计给最后读它的用户；只在实例租约持有者上跑，08:45–15:00 之间换槽或重启接手时立即补跑当天，已有当天判断的品种不再调模型。某类事实加载超时时，加载完成后立即重读事实并开始生成（`stage=facts`→`model`，`expectedSeconds` 取最近 10 次耗时中位数）。每天生成上限 `AI_TRADER_RESEARCH_DESK_DAILY_CALLS`（默认 200，计在共享库，重启与换槽不重置），同时最多 2 个。失败后 5 分钟内不重试：无现成判断时 `{status: failed, error, retryAt}`，已有判断时照常返回它并加 `refreshError`、`retryAt`（重算进行中不带，成功后清除；退避到期不自动重算，需再次刷新）。客户端读取失败时保留已读到的内容并写明失败，按 4、8、16、32、64 秒重读，之后回到 10 分钟。只有档位含 web-research 的读者用自己的模型适配器触发生成；游客 `GET /api/guest/research/desk` 只得事实（不带 `news`），`judgment.status` 为 `signin_required`。
- 外盘：外盘代码（`KQD.m@CME.NQ` 或 `CME.ENQZ26`）走外盘分支（`research_data.research_target`，product 为外盘品种键如 `CME.NQ`），sections 只有 market / related（有国内对照时）/ report；`/api/research/summary` 对外盘返回 `foreign: true` 与说明；外盘的 AI 简报（`/api/app/brief-subscriptions` 接受外盘键，合约为外盘主连）取 `research_live.product_events` 的 major 事件；多 AI 研讨对外盘发起价取外盘报价、`settlement.status=void`，快讯事件按外盘快讯键归属。

多 AI 研讨（`research_debate.py`，表 `research_debates`；流程、对账口径、限制与接口见帮助主题 research-debate）：

- 资料：`ResearchDeskService.debate_material` 的事实加触发快讯；只给 eventId 时品种由 `research_live.event_products` 查出；程序算近 20 个已收盘交易日的收盘最高 / 最低 / 均价（盘中正在形成的当日 K 不算）。
- 发言：四次依次进行（多方开场、空方回应、多方反驳、空方反驳），每方看到之前的全部交锋（未核对的句子带“（未核对）”）；措辞借鉴 TauricResearch/TradingAgents 多空研究员提示词的对话风格（Apache-2.0）。每次 400–600 字（`TURN_CHARS`，引用标记不计），超过 750 字（`TURN_LIMIT`）在句末截断加“…”、不算未核对；引用写成行内标记 `[F编号]`（编号即资料来源的 `n`）；最后一行“总体看法”是该方自己的看法（对账用，不显示、不给对方看）。边写边经 `feed.debate` 推给发起者和等待者的窗口（每 0.25 秒最多一帧，带整段已写文字，不落库；本进程的读取带上正在写的那段）。旧的两轮结构记录读取时由 `turns_of` 换成四次发言。
- 核对：说完由 `check_turn` 逐句核对——标记指向已知事实、句子里的数字都在所引事实里、没有下单用语（调研员的 `sentence_problem`）；未通过的留在记录标“未核对”、裁判看不到。
- 裁判：只见 A/B，随机映射记在 `mapping`；`_verdict` 按 mapping 把“A 方”与匿名编号换回空方 / 多方与真实编号后再核对，只改裁判真看到的匿名编号（富时A50、中证A500、B方案、A 方面原样）；裁判写的 A/B 一律换回多方 / 空方。裁决读不出标 review；判了胜方但采纳的句子没有带引用的依据也标 review，并在 `unsupportedVerdict` 留下裁判原判；`reason`（≤130 字）同样核对数字；读取另带 `checks`（rounds / arguments / unverified / cited，界面与对话 AI 同数）；立场按胜方与幅度定档，信心由程序算。
- 槽位：被另一槽回收的旧 worker 迟到完成不再发“研讨完成”；关停时取消的研讨存 failed，由下一个活着的槽位提醒等待者一次。
- 缓存与配额：缓存键（事件或今日议题, 品种, 事实快照哈希），一个事件在同一品种同一研究日只辩一次，`force` 再辩一轮；每天次数 `AI_TRADER_DEBATE_DAILY_RUNS`（默认 30），并发 `AI_TRADER_DEBATE_CONCURRENCY`（1–2）；用量记 `platform:research-debate`。
- 模型：`AI_TRADER_DEBATE_BULL_MODEL` / `BEAR_MODEL` / `JUDGE_MODEL`（经 `deploy/vps/docker-compose.yml` 透传；留空用默认多方 deepseek-flash、空方 glm-5.3-flash、裁判 deepseek-flash）。空方兜底 `AI_TRADER_DEBATE_BEAR_FALLBACK`（默认 deepseek-flash）：空方模型不可用——超时、`model_rate_limited`、`model_auth_failed`、`model_unavailable`、`model_stream_interrupted`、`model_request_failed`（连接失败、5xx、404/408/409；其他 4xx 不算）、没配密钥——就换兜底并在本场后续一直用它，`fallbacks[{role, stage, from, to, reason}]` 记切换，`models.bear` 改成最后实际说话的模型，兜底的每次调用带 `fallbackFrom` / `fallbackReason`；`model_output_invalid` / `model_output_empty` 不切换，兜底没配密钥也不切换（照原样报主模型的错）；两路都失败 failed 并在 error 里列出两个模型；发起前检查只要角色自己的模型或兜底有一个配了密钥。裁判失败重试一次，仍不可用换兜底 `AI_TRADER_DEBATE_JUDGE_FALLBACK`（默认 k3.1-pro）；多方没有兜底，模型不可用就 503 写明角色与模型。双方发言经 `stream_text(light_reasoning=True)`、裁判经 `complete_structured(light_reasoning=True)`，按供应商的 `light_effort` 取最低推理强度：DeepSeek none、Kimi low（它拒收 minimal/none，去掉字段会回到默认 max）、其他 minimal；输出上限两方 6000、裁判 8000，只防失控（思考也计入上限，上限过低会被推理吃满而正文为空），发言长度由字数上限保证；被截断或空内容报 `model_output_empty`、格式不合法报 `model_output_invalid`，裁判两者都进需复核。
- 对账实现：出结论时冻结交易日、到期日（5 个交易日后）、发起价、失效位、裁决、双方各自看法与当时的单模型今日判断。发起价按 `quote_is_fresh`（与下单同一新鲜度判定）取当时行情；休市时当前交易日已有成交（按可信报价——normal/simulated、非缓存、成交时间不超前——的最后成交时间所属交易日判断，交易日口径同 `closed_closes`）取该报价最新价（`entrySource: last`，与底稿 M.price 同源），tradingDay 记当前交易日；当前交易日还没成交取最近已收盘交易日的收盘价（`entrySource: close`）；交易时段行情过期，或当前交易日 K 已在形成却没有可信报价，则没有发起价、这场 void（已落库的研讨不改写）。是否休市先看行情的 `marketSessionStatus=closed`，否则由 `debate_entry` 按目录里主力合约的 `tradingSchedule` 与交易日历经 `debate_sessions` 判断（`normalize_schedule` 规整跨零点夜盘，`trading_calendar.sessions_of_day` 排时段，长假前后不排夜盘）；盘间行情源给不出报价或状态 unknown/trading 都不算交易时段内过期，交易日的时段还没开始时它的占位日 K 也不算成交。void 的 `reason` 由 `void_reason` 区分交易时段内行情过期（`quote_stale` / `quote_not_current`）、交易时段内行情缺价格或时间（其他 `quote_*`）与休市取不到价（`closed_price_missing` / `close_missing`）。失效位被去掉时 `confidenceBasis.invalidationDropped.reason` 为 `not_price` / `wrong_side` / `too_far` / `no_stance`（震荡、看不清）/ `no_entry`（没有发起价）。单模型基准只认本研究日的今日判断，没有就 `deskMissing`。五个收盘从发起价所属交易日之后数，只用已收盘的日 K（当天的要过 15:30），`due` 只是开始检查的日子；收盘后后台按同一规则结算，满 30 次才给命中率。
- 游客不能发起（界面命令 `guest_ui_action_forbidden`、语音 `guest_debate_forbidden`）。

### 游客服务边界

开关与部署：`AI_TRADER_GUEST_ENABLED=1` 显式开放游客；真实行情默认关闭，fake 本机默认开启。生产 `.env.production` 的该变量由正式 Compose 传入两个 Runtime 槽位，缺省为 0。开放生产前须确认行情对外展示许可，金融 MCP 不使用个人 OAuth 公共分发。

身份与会话：`POST /api/auth/guest` 向浏览器发放独立 HttpOnly `ai_trader_guest` cookie；允许的桌面来源另获仅存内存的 `accessToken: guest.<opaque>`，HTTP 通过 Authorization Bearer、WS 通过 `ai-trader-token, bearer.guest.<opaque>` 子协议携带，令牌不进 URL；一小时失效，不落 cloud_users、不装配个人 sidecar、账本或策略循环。游客只可访问 `/api/guest/session`、`instruments`、`market?symbol&duration`、`research/{dataset}?symbol`、`ui`、`voice/intent`、SSE `stream` 和 WS `voice/transcribe`；普通账户接口依旧拒绝游客。`instruments` 只返回行情源当前标为主力的那一个螺纹合约（TqSdk `query_cont_quotes`，随成交量/持仓换月，不写死合约号）；`market`、`stream`、`research` 及界面命令的 `symbol`、`pinnedSymbols.add`、`news.pinnedSymbol` 用其他合约时整条命令不生效（`403 guest_symbol_forbidden`）。客户端表现见帮助主题 guest。

来源地址与档位：游客限流与认证共用 `auth.visitor_ip`，仅按规范 `request.client` 计来源地址，不直接读取 `X-Real-IP` 或 `X-Forwarded-For`。正式代理由 nginx 覆盖 XFF 为可信还原后的 `$remote_addr`、再由 uvicorn 解析；必须先按[部署合同](THREE_PLATFORM_AND_WEB_DEPLOYMENT.md)完成规范 nginx 安装与校验，再切换新版 Runtime。非代理环境保持默认不信任转发头，按实际连接对端计地址。后台 `guest` 档位保留、不可设为默认或删除，不能分配给正式成员或邀请码；模型/技能开关不扩大游客权限，语音零额度表示关闭。

普通用户的公共行情：页面行情与纯行情能力 `search_instruments`、`get_market_snapshot`、`get_market_analysis`、`get_chart_bars` 复用同一公共源，继续由普通身份认证，不借源账户的交易权限。账户决策/交易和策略执行/深历史保持原接口与本人 provider。普通 `feed.market` 按公共更新独立推送，慢端取最新完整图表。

能力目录：游客身份查询 `/api/agent/capabilities` 得到专用目录，通过 `/api/agent/call` 只能转调该目录。CLI/MCP 的受保护连接文件支持 `authMode: guest`，只发送独立游客 Bearer（token 字段取 bootstrap 的 accessToken）；不自动从浏览器导出 HttpOnly 会话，宿主须通过同一引导接口取得自身会话，不能控制另一游客窗口。登录凭据优先走原目录。

公共行情多账号接力：有序源清单存库（`market_sources` 表），首次启动用 `AI_TRADER_SHARED_MARKET_ACCOUNT_IDS`（逗号分隔有序；兼容旧单账号名 `AI_TRADER_SHARED_MARKET_ACCOUNT_ID` / `AI_TRADER_GUEST_MARKET_ACCOUNT_ID`）播种，之后管理员经 `PUT /api/admin/market-sources` 在线维护、不用重启；每个源是一个已绑定的快期成员账户（或主 sidecar 账户），复用其认证创建独立只读数据会话。清单为空且无兼容配置、或全部源停用/解绑/不可达时返回 `503 guest_market_source_unavailable`，不回退默认主账号。公共读取不装配私人策略/下单/账本服务；无人登录时可恢复该共享连接，浏览保活也不冒充账户本人在线；浏览和账户本人均闲置后沿用池回收规则。每个行情源账号最多 48 个活跃组合，K 线通道创建时固定到一个健康源并留在那里（按清单顺序每源先放到 16 组，之后放到负载最低的源）；源报订阅上限（`market_subscription_limit`）时该通道转下一个源重试一次，源不可达时按指数退避重查、其通道转走且恢复后不抢回；全部源满才报 `guest_market_capacity`。单源部署行为相同。

冷序列与换源（单源部署同样适用）：源还在载入的序列答 `market_series_not_ready`、或通道刚转到另一个源时，这一轮读取由该图表唯一的取数任务重试，同一图表的读者共享这一次载入、继续等首帧（最多 20 秒，`series_wait_seconds`），不因一个失败全体 503；已在服务的图表从换源那一刻起继续给上一份、`dataStatus` 标 `stale`（先接后断，不等新源的冷读取答复），从换源起算超过 20 秒仍未就绪才按失败处理（`unavailable`/503）。

推送：实时市场数据按规范合约和秒周期共用一个更新任务，内部版本长轮询收到变化即唤醒 SSE，无每游客一秒取数循环。独立公共 SDK 会话同时冷加载最多 8 组；无读者后停止任务，Sidecar 的 30 秒兴趣租约到期后关闭或预热替换会话以真正释放订阅。合约目录短期共享缓存。游客身份上限 1000 个仅是内存边界，并非已验证的在线容量。SSE 首帧 `snapshot`，后续共享编码的 `update` 包含完整 quote（变化时）、workbench 变化状态/quote 及 barsPatch；barsPatch.bars 按 datetime 覆盖/追加，trimBefore 删除更早 K 线，不重复发送不变的历史 K 线。丢代或历史替换时恢复 snapshot。catalogStatus 与 marketSessionStatus 保留；周期仅 60/180/300/900/3600/86400 秒。慢客户端不积压历史事件，断线释放订阅，重连重新快照。服务端空闲时最长 15 秒发一次心跳，客户端 45 秒无任何数据即视为静默断开并重连。每会话最多两条流。

客户端实时推送重连：每次 SSE 建立均幂等重放当前会话 focus（合约、周期及当前可用 since）和 view（可见性、报价范围）；短于连接状态去抖的断线同样恢复。登记暂时失败按既有 2 秒间隔重试，401/403 不重试；旧会话、旧 Runtime 或已卸载图表不再发送。市场/报价补丁缺基底沿用各自重同步，不放宽 channel 新鲜度判定。

界面命令与语音：SSE 初始及 revision 变化时发送 ui 事件，命令独立唤醒、不等待行情变化，前端不持续轮询；`GET ui` 保留给 CLI 观察，返回 windowId/changes/snapshot/revision；`POST ui` 仅接受同窗口，changes 增加 revision，snapshot 仅回报当前可见状态，可带 appliedRevision；精确确认当前 revision 后消费已执行 changes，未确认命令继续合并，旧回执不能清除新命令。语音仅匹配固定界面意图，未知拒绝，不触发通用 Agent。PTT 沿用 16k PCM16、end、partial/final，单次总长 15 秒，按完整 15 秒预留额度；会话与 IP 各自限额，刷新 cookie 不会清除 IP 成本，重启会结束游客会话与进程内限额。

工作区与历史限额：游客和所有账户等级复用同一工作区与权限反馈。免密身份适配层只管理游客会话和公共传输，所有私人 hooks 按身份关闭；UI 入口点击会解释限制，服务端身份、技能与配额检查不可绕过。游客档 `marketHistoryTradingDays` 只接受 1/3/5（新游客配置为 3，原游客档缺字段同样解析为 3），普通档位只接受 null；session、owner/status、管理员 plans 响应公开同名字段；游客行情（HTTP 与 SSE 每一帧）在 `workbench.historyTradingDays` 带上当时生效的限额，客户端图表与快照只读这一处。普通历史限额需要同时覆盖回放、回测、AI 深历史后才开放。

历史裁剪：SharedMarketService 按源版本与天数共用投影，HTTP 和 SSE（增量、丢代恢复、重连）都只返回最新 N 个交易日且最多现有 500 根；日线与夜盘按正式交易日工具解析，无法分类的 bar 不跨过边界。范围收紧会发送新快照。游客限额查询共享 1 秒缓存，活跃流在下一行情/UI 事件或心跳时读取生效（最长约 16 秒）；语音授权仍逐请求读取全局技能。正常成员原始包不受游客裁剪影响，不为游客启动历史下载、私人账户/交易循环。
