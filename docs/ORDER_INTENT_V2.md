# 下单意图与规划重构（2026-10-16 所有者确认，按建议执行）

作者：Claude Code 主代理 / Opus 5.5。依据：现状地图、成熟方案调研、测试集来源盘点（三份调研，证据见文末）。

## 1. 为什么要改

一句用户话变成一张交易卡，今天要经过两层，问题集中在上面那层：

| 层 | 现状 | 本月相关修复（10-01 起，123 个） |
|---|---|---|
| **意图识别**：这句话是不是要下单、平仓、做到几手、是不是问句/条件/转述/撤回 | 打字、语音前台、界面兜底三处各判一遍，约 60 个下单相关正则，否定词表 4 份、口径各不相同 | 29 个，其中 28 个是“加词/加特判” |
| **参数与规划**：合约、方向、手数、开平、今昨、价格方式 | 工具、HTTP 路由、策略、目标持仓接力、客户端下单票 5 条路径各自凑参数；打字路径里方向、手数（含“平一半”）、平仓方向多由模型自己算 | 读取/归属 25、执行回写 22、规划计算 9、模型越权 9 |

数据说明两件事：
- 已经“收成单一入口”的 20 处（工具边界、今昨分配、目标持仓规划、整账户读取），收口后同类问题**没有再复发**。
- 意图识别层**从来没有单一入口**，问题在三处轮流复发；打字路由对问句、条件、时间、转述、同句撤回五类句子基本不防，全靠“出卡后要确认”兜底，而语音关掉口头确认时这层兜底并不存在。

结论：不是再补哪个词，而是给“意图”和“规划”各建一个唯一入口。

## 2. 目标结构

```
一句话（打字 / 语音 / 外部 AI）
  └─► ① 意图解析（唯一入口）──► OrderIntent（结构化）
          快速规则：只在很有把握时给结果，拿不准就说“不确定”
          不确定 → 交易 AI 按严格结构填意图（不再直接填下单参数）
  └─► ② 下单规划器（唯一入口）── 意图 + 一次整账户读取 ──►
          出卡（一张或多张）｜ 追问缺的信息 ｜ 拒绝并说明原因
  └─► ③ 现有确认链（不变）：出卡 → 你确认 → 执行
```

HTTP/CLI、策略出卡、目标持仓下一步、客户端下单票也都进 ② 规划器，不再各自凑参数。

### 2.1 OrderIntent（下单意图）

| 字段 | 取值 | 说明 |
|---|---|---|
| `act` | open / close / close_all / target / reverse / cancel_order / retract / amend / confirm / none | 动作 |
| `stance` | order / question / conditional / reported / retracted / advice | 这句话的语气：只有 `order` 才可能出卡 |
| `product` / `symbol` | 品种名或合约 | 指代（“这个合约”）由解析器按当前界面解析 |
| `dir` | long / short | 方向（多/空），不是买卖 |
| `vol` / `target` / `frac` | 手数 / 目标净持仓 / 比例（如一半） | 三选一 |
| `price` | counter（对价）/ queue（挂买一卖一）/ passive / limit:数值 | “市价”= counter |
| `bucket` | today / yesterday / auto | 平今、平昨，默认 auto |
| `cond` | 价格或时间条件 | 有条件时 `stance=conditional`，不出即时卡 |
| `legs` | 多个意图 | 一句话两单 |

字段沿用语音前台原来的 `FrontAction` 雏形，扩成全路径共用（第 2 步起 `FrontAction` 已删除，语音前台直接用 `OrderIntent`）。撤单在 Runtime 源码里叫 `cancel`（测试集写 `cancel_order`，发布预检禁止该字样）；解析器另带 `scope`（撤单/撤回/改单/确认的对象）、`fixed`（句中改过口）、`bare`（只说了买/卖，没说开/多/空）。

### 2.2 意图解析器（`order_intent_parse.py` 的 `parse`，纯函数、无 I/O）

- **一处维护**：数字解析（现有 4 处重复）、品种词、否定/询问/条件/转述/撤回标记，全部收在这里。
- **快速规则只做“有把握”的句子**：常见简单句（“买两手螺纹”“螺纹平一手”“全部平仓”“螺纹做到多 2 手挂买一价”）直接给结果；只要有拿不准的成分，就返回“不确定”，绝不猜。这一条用测试集强制：快速规则在测试集上**不允许给错误结果**，只允许“不确定”。
- **拿不准时交给交易 AI**：AI 只能调用一个工具 `propose_order(intent)`，参数就是上面的结构（严格 schema，枚举约束）；Runtime 先校验，再交规划器。AI 不再直接填买卖方向、开平、今昨、手数计算。
- 调研结论：DeepSeek 只有 `/beta` 接口文档化了严格模式，豆包、GLM 都不保证遵守 schema，所以 schema 只是第一道防线，**保证靠 Runtime 校验**；豆包实时语音只转交原话，槽位以 Runtime 解析为准。
- 不引入 Rasa、Instructor 等运行依赖；借鉴 Rasa CALM 的“命令集”（设槽、改槽、取消、澄清）思路，复用仓库已有的结构化调用 + 校验失败重问、“需要确认”追问卡。

### 2.3 下单规划器（`order_planner.py`）

输入：意图 + 一次 `provider_read_snapshot(account=True)` 整账户读取 + 用户偏好。输出三选一：

- **出卡**：算出每一腿——合约（目录解析）、开平与方向（看持仓）、手数（含差额、一半）、今昨（统一 `close_allocation`）、价格（统一默认值规则 + `leg_price_intent`）、开仓就绪门禁、未成交挂单检查——调现有 `proposals.create_*` 出卡。
- **追问**：缺方向/手数/合约时出追问卡（复用“需要确认”卡 `card.order_question`；第 3 步起快捷选项由 `ask_choices` 生成补全后的整句，点了直接出卡，`ask_order_details` 工具已删除）。
- **拒绝**：非 `order` 语气、条件句、读不到账户、有挂单冲突等，给中文原因。

复用现有确定性件，不重写：`build_candidate`、`close_allocation`、`plan_target_position`/`working_order_lots`/`leg_price_intent`、`_decision_context` 就绪门禁、`ProposalService.confirm`、#936 执行前工具边界。

### 2.4 不变的东西

- 出卡后要你确认才执行；语音免确认开关语义不变。
- 不新增、不提议任何风险规则。
- 语音前台的确认/取消/挂断/查询固定词表保留（速度关键、与下单无关）。
- 回答卡核对是另一条链，本次不动；2026-10-17 已单独改为“模型按字段引用读数”（读数表 `answer_readings`，#962 起）。

## 3. 真实语句测试集

- **位置与格式**：`services/trader-runtime/tests/intent_corpus/cases.jsonl`，一句一行；账户上下文用命名快照引用（`contexts.json`：空仓、已持多 1、有买开挂单、当前图表合约……）；期望只写结构不写措辞。
- **两级断言**：
  1. 快速规则：每句要么给出期望结构，要么“不确定”；给错 = CI 失败。
  2. 规划器：在给定上下文下，期望结果（出哪几张卡 / 追问什么 / 拒绝）。CI 跑，纯确定性。
  3. 模型抽取（拿不准的那部分）：离线评测，每句重复 3 次只比结构，看意图准确率、误出卡率、漏出卡率；不进 PR CI（费用与不确定性），发布前与模型更换时跑。
- **第一版规模**：以现有 `eval/fuzzy/testset.py`（116 句）与 `test_voice_front_action.py`（约 62 句）为种子，加 issue 出错原句与测试会话证据，约 250–320 句。今天出过错的句子全部在内。
- **维护规则**：每个新的“说法”问题只加一行测试；关键词层已冻结（#932）。

一句多单（2026-10-17，分支 `claude/intent-multi-order-20261017`，兑现第 5 节第 3 项“按顺序出两张卡、各自确认”）：解析器在 `_order` 一处按“然后 / 之后 / 接着 / 另外 / 再（动词之后）”或停顿拆分句，每个分句当成一句简单话用 `parse` 单独读（`_legs`），每单的合约、方向、手数、价格只来自它自己的分句；只有每个分句都是有把握的 stance=order 开仓（说了方向和手数）、平几手 / 平一半或全平，且各自点名合约（`Mentions` 的品种、月份或“这个”，全平可说“全部”）、一单只在一段里说，才产出 `legs`；否则整句 `Uncertain("legs")`（撤单 / 目标持仓 / 反手夹在其中、价格或合约单独一段说、同一单说两遍、共用的“各买”、持仓反方向的裸买卖、条件管几单说不清，都不读）。`legs` 交规划器：互不影响一次按序出全部卡，同一合约先平再动走接力，不限范围的全平夹别的单 `legs_entangled`；新增：某一单只说买 / 卖而持仓反方向、或某一单要追问（两个月份、多空都有）时整句拒绝 `legs_unsettled`（请一单一单说，不在句中追问）；这些卡记 `intentSource=parser_legs`，语音免口头确认不代确认；打字与语音前台每张卡按它自己的源腿念，出不了卡的那一单在回复里说原因。模型路径（`propose_order`）的 `legs` 仍一律拒绝。测试集加 8 行（c366–c373），`LEGS_READ` / `LEGS_UNSURE` 逐行钉住多单行的期望，并把解析器自己的 legs 经目录与规划器跑一遍比对出卡。

#932 P2 集中修（2026-10-17，分支 `claude/p2-planner-20261017`）：出处校验（`ground`）按值收紧与补回——品种名后的月份（`Mentions.months`，“螺纹2705”）绑定模型的合约；止损/止盈各读自己那一段的价、撤与成本（`Mentions.stop/take` 的 `Guard`），“挪到成本”按点名月份的持仓算；原话唯一的平今/平昨、价格方式在模型漏填时补回，限价与价格方式同说追问；改单只改说了的槽位（动作、方向、手数、价格沿用唯一待确认卡，说了的只认原话）。规划器：一句多单按已解析合约判是否牵连（同品种不同月份互不影响）；目录读不到时开仓不出卡；今仓/昨仓全平读不到账户报“读不到”；批量平仓卡的读取异常收成拒绝。解析器：“追多/追空”“两张”入词表；手数后裸说的数字交下单回合；命令与问句同句（`mixed`）交完整回合两件都办；“不用问我/不用再确认”不算否定这句的动作。目录匹配认口语别名（白银→沪银）。目标持仓卡被放弃或超时作废时计划随卡结束（不再等 30 分钟停滞清扫）；HTTP 账户头指名的账户即使与会话相同也记 `accountExplicit`。

#932 下单意图批（2026-10-19，分支 `claude/932-intent-planner-20261019`，PR #997）：出处校验（`ground`）的合约与手数收成一条规则——原话只读一次，读出它留下的候选（`_said_contracts`：代码、品种名后的月份按精确合约，单说的品种名按品种（与代码并列时是另一个更宽的范围，只能由按品种的全平覆盖；盈亏筛选也认赔钱、亏了、赚了等说法）；“这个”是窗口合约，窗口不在就追问；原话没点名时才看明确改单的那张待确认卡的合约本身、再看账户唯一持仓），恰好剩一个候选且模型的值就是它才算有出处，否则追问（“rb2701挂一手au2612多单”“豆二挂一手沪金多单”“改成这个合约三手”在没有窗口合约时）；全平时模型的范围要与原话点名的一致——点的每个合约都在候选里、候选也都在它点的里面（“把螺纹和沪金都平了”只给螺纹也追问），原话点了合约而模型给了不限范围的全平也追问。手数（`_said_lots`）：模型给的是原话说过的数就算有出处（说了几个时挑哪个是模型的事）；不是时，原话恰好说了一个就用它（“改成三手”不留旧卡 5 手、也不被默认手数补成 5），说了几个或读不准（`Mentions.lots_said`，“两百五手”）追问，一个都没说才交规划器追问或落默认手数。动作：原话里有两种动作（`Mentions.acts` 同时有开与平/调/反手，“卖一手螺纹平掉”）追问。校验的边界（PR #997，主代理 2026-10-19 定）：只管两件事——卡上不出现原话没说的合约、手数和修饰（模型不编），平仓范围不比原话点名的窄；原话里说了的几样里归哪一个、语法怎么读是模型的事，用户确认卡片是最后一道；不做分句或短语归属，“该出卡却追问”的过严按低优先级攒批。所以止损/止盈的撤、成本沿用原来的读法（说了就算说了，“止损取消止盈3200”归哪个由模型定），#932 A17 不再按就近归属。原话在平仓那一分句里按盈亏挑持仓（`Mentions.filtered`：盈利的/亏的/浮亏…，意图没有这个槽位；前一分句说“亏钱了”只是原因，不算）而参数是全平或没点名的平仓时追问平哪些（所有者 2026-10-19 定）。规划器：`PlanContext.resolved_account_id` 冻结入口选定的账户（这套工具读的就是它，`TraderReadOnlyTools.account_id`），卡与目标持仓计划都落在它上面，规划途中会话改绑不再让卡漂到别的账户（卡上注明与对话账户不同）；计划落在冻结账户而会话已在别的账户时记 `accountExplicit`，后续各步仍在原账户出卡（每张仍要用户确认），反手不会只平不开。语音：一句多单按规划器的精确合约判断是否接力（rb2701 与 rb2705 互不影响、不等），同一合约先平再动且该合约有进行中的计划时，先等这句话说完再规划（与目标持仓/反手同一个 settle；只说品种的平仓要看持有月份，这时读不到持仓也先等）；speak/inject 的 `on_commit`（下一张卡变成可确认）在 commit 实际发出后才执行，发送失败或被丢弃时卡保持“已准备未念”，inject 的那句记入未念行由上游看门狗在新会话重念，下一句确认/取消重新问它。测试集新增 `model` 行字段：交易 AI 对这句话实际给过的读法与出处校验+规划器应有的结果（`tests/intent_corpus/README.md`）。
