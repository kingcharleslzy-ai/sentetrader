# AI 原生期货工作区 v1

## 1. 目标

本版本把原有“中央对话 + 状态工作台”重组为同源工作区，共享合约、周期、历史 K 线、账户和 AI 上下文，只在需要时展示交易控件，避免全局下单横栏挤压图表或遮挡对话。

## 2. 工作区分工

当前（1.2.8 起）顶部为“交易台 / 复盘”两个工作区加“回放”入口；1.1 版本的独立“看盘”工作区已并入交易台（大图表默认占满主画布，右侧 AI、快速下单、持仓按需单独展开，再次点击收起；原价格阶梯 2026-10-07 起并入下单面板顶部的五档）。

- 交易台：保留大图表；AI 与快速下单在同一辅助工作台中并存（五档在下单面板顶部），工具轨切换内容，也可临时聚焦完整下单面板。1.4.5 起 AI 入口专注盯盘摘要与操作列表，策略配置和手续费按需打开，文字与语音共用独立对话入口。
- 复盘：使用历史 K 线、回测、订单和成交事实，不显示实时下单控件；历史盘口不可得时明确说明，不用当前快照代替。
- 回放：选择实际合约与已结束交易日建立独立 TqBacktest + TqSim 账户，见 README“交互式历史回放模拟盘”。

桌面端使用单一左侧导航、中央图表、底部持仓坞站和窄工具轨。辅助工作台默认同时展示 AI 与快速下单。普通宽度上下排列，辅助区拉宽到 620px 后自动切为双栏，主图表始终由网格重新分配空间而不被覆盖。顶部“布局”入口允许把辅助区放在图表左侧或右侧；分隔线分别在受限范围内调整辅助区宽度、快速下单高度和持仓区高度并本机保存。紧凑窗口把辅助工作台排到图表下方，仍避免横向裁切。语音下单使用独立工具按钮，识别结果只进入草稿链路。字体大小与界面密度独立保存，字体档位只改变文字，密度档位只改变留白和模块尺寸，禁止再使用 WebView 整页缩放放大固定几何。

主工作区不依赖页面级或市场区滚动条：图表使用剩余空间，辅助工作台只允许在安全范围内缩放，五档和快速下单在可用高度内完整排布，AI 上下文使用弹性列与省略规则。AI 回复的结论、原因、风险与动作使用标题在上、内容在下的纵向层级；新闻来源集中到默认收起的“参考依据”。常规状态下只有 AI 对话流持续滚动；设置、合约、持仓等抽屉只在内容确实超过小窗口时使用自身的受限滚动。

AI 模拟操作不显示授权确认卡。用户可以通过文字或语音提出模拟交易请求，Runtime 按需建立内部执行租约；平台默认不设手数或次数上限，设置中可启用自定义限制。AI 标题栏只保留紧凑急停，未决保护单也保留同一取消入口；`liveTrading=disabled` 和 UNKNOWN 不重提边界不变。

用户选择的实际交割合约保存在本机；重载后仅在官方目录仍存在时恢复，失效合约自动回退到当前主力或第一项。

## 3. 下单区、快捷行与右键菜单

顶栏 nav 里每个钉住的合约就是一个交易台标签（`pinnedSymbols`，≤8）：点标签切到该合约的交易台，"+" 经合约抽屉钉住，"×" 移除（最后一个不可移除），复盘 / 回放仍是独立入口；顶栏按实测空间逐级收起（`data-fit`，非视口断点），先把 AI 指令栏缩成 ✦ ⌘K 按钮（等级 1）、收起权益里的美元两段（等级 2，悬停与账户明细仍可见），等级 5 起标签收成当前合约下拉，连接/排队警告与恢复入口永不隐藏。

固定下单区的方向选择为：

1. 买多：填入一张 `BUY + OPEN + LIMIT` 模拟委托预览。
2. 卖空：填入一张 `SELL + OPEN + LIMIT` 模拟委托预览。
3. 智能平仓：必须先选中真实持仓；Runtime 根据多空方向、交易所和今昨仓生成 `CLOSE` 或 `CLOSETODAY`，不会猜测不存在的持仓。上期所 / 能源中心的平仓页默认“自动”（按平今平昨偏好由 Runtime 分配），点了平今或平昨就只平那一侧。

买多和卖空只改变订单预览，不构成提交；用户必须在同一固定下单区点击“确认下单”，才代表本人对这一张模拟委托的授权。客户端内部仍复用既有 Proposal、approvalId、版本、幂等和单次提交链路，以便在真正调用 Sidecar 前重新检查行情、Tick、数量、时段、持仓与风险。

下单区底部、"确认下单"之下的快捷行（一键买多 / 一键卖空 / 一键平仓，双向持仓时为一键平多 / 一键平空）是快捷下单（2026-10-09 起图表右键菜单只服务图表——画线、周期、指标、副图、设提醒、让 AI 讲解——不再下单或填草稿价）：快捷行按当前手数以对手价开仓，智能平仓按当前合约的实际持仓平——只有一个方向时一键全平，多空都有时分成"平多 / 平空"，没有持仓时禁用并提示到持仓栏平其他合约。快捷下单默认先弹一次确认框列出将要提交的委托（一键平仓是一笔请求；上期所 / 能源中心的平仓标“今昨按设置分配”，由 Runtime 按平今平昨偏好分，跨今昨时出一张批量平仓卡、一次确认分两笔发出，2026-10-16 起客户端不再自己拆），设置 → 模拟交易的"快捷下单免确认"（仅存本机、按登录用户分开，换账号不继承，游客固定要确认）打开后直接提交。持仓栏每行的"平仓"按钮只是切到该合约的下单区平仓页并选中该持仓、手数填可平量，仍需"确认下单"。所有快捷下单与固定下单区走同一条 Proposal 链路，不会自动重发；`Alt+B`、`Alt+S` 只填入方向草稿；`Alt+A` 切换 AI，`Alt+P` 折叠 / 展开持仓栏。Runtime 对显式价格再次验证有限正数、Tick 和涨跌停，校验失败直接拒绝。画线下单已移除。

## 4. AI 模拟执行语义

AI 可以持续读取当前图表、行情、账户、持仓和会话上下文。需要模拟下单、撤单、平仓或设置止损时直接调用受控工具，Runtime 自动建立内部执行租约并重新校验最新事实和用户设置。完整语义见 [AI 自主模拟交易与语音会话 v1](AI_AUTONOMY_AND_VOICE_V1.md)。

每次工作区提问会附带一份经过 schema 校验的有界上下文：当前页面和辅助模块、实际合约、K 线周期、候选价（下单面板五档点价）、订单草稿、选中持仓、行情时间与年龄、今昨仓/冻结量、活动委托、最近成交，以及本次软件会话内最近 12 个与决策相关的操作。Agent 根据整体语义解析“这一手”“这个持仓”“现在怎么做”等自然指代，不维护固定问法清单。页面操作只表示用户关注和意图，不是成交事实或交易授权；回答、创建候选或执行模拟动作前仍必须调用 Runtime 工具重新读取状态、行情、账户、持仓和活动委托。普通对话默认使用低推理强度，用户仍可通过进程环境显式调整。

手工三键仍由唯一用户点击“确认下单”后提交；AI 模拟动作不再要求额外授权确认。明确停止或急停后，AI 无权自行恢复。

## 5. 行情能力声明

当前 Provider 只可靠提供买一、卖一、最新价、成交量与持仓量。本版价格梯可以围绕最新价展示 Tick 价位，但只有真实存在的一档显示挂单量；其余位置用破折号表示未知，不能填零，也不能称为完整 DOM。

未来取得交易所 Level 2 后，可以新增独立数据适配器开放更深档位、逐笔成交、逐笔委托和完整订单簿。排队位置只有在数据许可、交易所/柜台协议和订单标识足以可靠关联本人委托时才可展示；没有可靠来源时必须显示不可用，不能推测。

## 6. 永久边界

- `liveTrading=disabled`。
- 不接 `TqAccount`、`TqCtp` 或真实期货账户，不增加实盘网关。
- 不接实盘执行；AI 下单、撤单、平仓和确定性止损只允许作用于绑定的 TqKq 模拟账户。
- `UNKNOWN` 只查询原订单，永不自动重新提交。
- TqKq 凭据、更新签名私钥、Token 和账户信息不得进入仓库、日志或公开目录。

## 7. 验收

- 客户端单元测试覆盖看盘无交易台、交易方向预填、语音草稿不自动提交、持仓缺失时智能平仓禁用和固定下单区最终确认。
- Runtime 测试覆盖显式图表价格保存、提交前复核和非 Tick 价格拒绝。
- Runtime 测试覆盖默认无平台上限、可配置限制、单次开/撤/平/止损、急停与 UNKNOWN 只查询原委托。
- 休市验收覆盖历史 K 线仍可见、交易三键全部禁用和复盘委托链可回读。
- 1920 x 1080 至 320 x 720 的多种视口完成真实浏览器交互、急停入口和无横向溢出核对；另覆盖标准字/宽松、大字/标准、特大字/紧凑组合，并断言常规工作区除 AI 对话外没有滚动策略。
- 本变更只完成代码和本地 Fake Runtime 验收；Windows/macOS 安装包与真实 TqKq 模拟账户仍需在新版本发布前单独执行原生烟测。
