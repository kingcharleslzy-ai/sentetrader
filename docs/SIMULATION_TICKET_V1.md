# 模拟开仓工作台 v1

## 用户可观察行为

1. 用户先从官方 TqSdk 合约目录选择一个未到期的实际交割合约并打开实时行情。
2. 行情工作台提供买入开仓、卖出开仓、1–100 手和挂单价/对手价/最新价三种价格意图。
3. 点击“生成待确认方案”只创建交易候选；页面明确显示“不会直接下单”。
4. Runtime 使用当前官方报价决定限价，并重新校验行情时间、价格最小变动、涨跌停和已确认风险规则。
5. 候选进入原有确认卡片；只有用户再次明确确认后，才进入既有 `SimulationOrderService` 单次提交路径。
6. 陈旧行情、账户不可用、模拟网关不可用或云端模式下，候选按钮不可用。
7. 下单票的出卡（`POST /api/simulation/proposals`）与对话、语音、外部 AI 走同一个下单规划器（2026-10-16，`docs/ORDER_INTENT_V2.md` 第 1 步）：开仓先过下单安全检查（合约在目录且未到期；报价新鲜、交易时段、最小变动价位、涨跌停由出卡时核对），不过就不出候选并返回 409 与中文原因；K 线等 AI 决策就绪检查只对 AI 出的卡生效；上期所/能源中心平仓没给今/昨时按“平今平昨”偏好分配（跨今昨返回一张批量平仓卡）——下单票平仓页默认“自动”就不带今/昨，用户点了平今/平昨才原样带上，快捷一键平仓也是一笔请求，客户端不再自己拆今昨或选默认桶（第 4 步）；返回批量平仓卡时下单票的那次点击同样只确认一次，委托栏逐笔列出；没给价格方式时平仓对价、开仓按账号默认价格方式。历史回放的下单票同样只做下单安全检查（回放导出没有到期日，不当作到期）。

## 官方接口与事实边界

- TqSdk 固定为 3.10.2，合约身份来自 `query_quotes(..., expired=False)` 目录。
- Sidecar 的单一 `TqApi` 线程按需调用 `get_quote(symbol)`；活动 Quote 不离开 Sidecar，只返回普通 JSON 快照。
- 动态报价与首页常驻合约快照隔离，最多缓存 64 个合约；某个按需合约未就绪不会拖垮账户首页。
- 报价时间按 Asia/Shanghai 解释；超过 15 秒、缺失、无效或来自未来的报价均标记陈旧。
- Sidecar 在提交前再次用目录规范化 symbol，并校验 `OPEN + LIMIT`、数量、tick 和涨跌停。
- TqKq 仍是订单、成交和持仓唯一事实源；不增加数据库表或第二套订单状态。

## 不变量

- `liveTrading=disabled`。
- 只允许 `buy_open`、`sell_open`、`LIMIT`。
- 创建候选时 `insert_order` 调用次数必须为 0。
- 用户确认后继续复用一张 `tqkq_sim_order_links`、单次 submit、查询、单次 cancel 和重启恢复。
- `UNKNOWN` 只查询原 `clientOrderId`，不得自动重发。
- 不增加平仓、自动止损、自动追价、多腿、后台 Owner 或云端执行。

## 黑盒验收

- 任意实际交割合约可读取动态报价；目录外合约返回 404。
- 动态合约不会进入常驻首页必需快照集合。
- 生成候选后没有本地订单链接，也没有网关 submit。
- 同一候选明确确认后仅 submit 一次，并保持原有幂等语义。
- 用户已确认风险规则之外的合约或超限亏损保留为 `risk_blocked` 候选，不绕过规则（1.4.5 起平台不再内置默认合约白名单或金额上限，未配置规则时模拟盘不限合约、手数和金额）。
- 陈旧行情下“生成待确认方案”和最终确认均失败关闭。
- Fixture、Runtime、Sidecar、React 和桌面包测试不得使用真实 TqKq 委托。
