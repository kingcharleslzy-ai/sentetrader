# AI 策略工作流 v1

## 结论

AI 负责把自然语言想法整理成结构化策略草案；Runtime 负责合约、参数、风险、回测、模拟执行和结果回读。大模型不直接运行任意策略代码，实盘始终关闭。

## 当前已实现

1. `create_strategy_draft`（2026-10-20 起，#932 F5）把完整 StrategyPlan 经策略编辑卡同一个保存接口 `POST /api/strategy-plans` 存成“我的策略”的一条草稿（`plan`、可选 `instrumentScope`、修改时 `baseStrategyId`——策略库版本或运行实例的 id，存为它的新版本），网页、AI 与 CLI 存的是同一种，能看、能改、能删。此前它存的是旧格式模板草案（均线/突破/KD/MACD/组合，schemaVersion 1，不在“我的策略”里）；这类旧草案仍可读、可验证，没在监控时可用 `DELETE /api/strategy-plans/{id}` 删除（归档）。
2. 旧格式草案绑定当前未到期的实际交割合约，信号输入固定为已完成 K 线。
3. 旧格式草案包含周期、方向、最大持仓、每日委托上限、止损、止盈和冷却期，并生成稳定指纹。
4. 草案按账户隔离保存，可由 Agent 重新读取，不能依赖聊天记录还原。
5. 新草案状态固定为“草案待回测”；创建草案不会建立交易候选、自动授权或委托。
6. `evaluate_strategy_draft` 只读取上一根已完成 K 线，确定性检查草案条件并返回买入、卖出或等待；它不创建候选，也不自动下单。
7. `prepare_strategy_validation` 为当前策略指纹建立验证报告，先完成定义完整性和已完成 K 线检查，其余历史回放、未来数据偏差、样本外、交易成本、风险保护和最小信号数均保持待验证。
8. `run_strategy_validation` 读取官方 TqSdk 历史 K 线，按“上一根已完成K线决策、下一根开盘成交”逐根回放，分离样本内外并计入滑点、费用、止盈止损、冷却和每日开仓上限。最后另附一行“运气检验”（`strategy_validation.luck_check`，改写自 Vibe-Trading `validation.py`，固定种子 42）：样本内外全部成交满 10 笔时，对每笔净盈亏做 1000 次自助抽样，95% 区间在 0 以上记 ✓、跨过 0 记“!”；同样这些成交打乱顺序 1000 次，写 95% 的情形最大回撤不超过多少；不足 10 笔写“判断不了”。这一行只提示，不参与验证是否通过，也不进上线前必须通过的检查项（`evidence.luck` 保存全部数字）。
9. 策略生命周期为“草案 → 验证中 → 验证通过但未启动 → 监控中 → 已暂停/已归档”；监控中或已暂停的实例可以“停止”回到验证通过但未启动（`POST /api/strategies/{id}/monitor/stop`，保留执行记录，不平已有持仓）。不完整或失败报告不能把策略改成验证通过；通过报告也不能直接进入监控。
10. `preview_strategy_intent` 只允许读取当前指纹仍有通过报告的“验证通过但未启动”策略，依次形成信号快照、仓位意图和风险裁剪结果，并保存幂等审计快照。
11. `start_strategy_monitoring`（HTTP：`POST /api/strategies/{id}/monitor/start`，可选 body `{signalAction, sessionId, resetDrawdown}`）可直接启动已验证策略的后台模拟监控，不弹授权确认；监控中再调用即修改执行方式。两个入口（HTTP 与内置工具）共用 monitor 的同一条启动/显式重置链路：`resetDrawdown: true` 走与网页“恢复运行”同一套前提核对（409 带中文原因），普通 start 绝不重置、停机中的一轮保持停止并如实说明；策略挂在别的交易账户时工具拒绝（`strategy_account_not_bound`）。`pause_strategy_monitoring` 停止产生新意图，`get_strategy_monitor_status` 回读保护状态、最近执行尝试与 funds/drawdown 读数（与 monitor 载荷同一份）。
12. 监控器只读取已完成 K 线；同一策略、同一已完成 K 线只有一个持久化执行身份，重启或重复轮询不会再提交第二张委托，`UNKNOWN` 仍只回读原订单。
13a. 执行方式（2026-09-25，`strategy_drafts.signal_action`，旧行默认 `auto`）：所有检查（亏损上限、同合约活动委托、方向对齐、每日次数、冷却、只停新开仓）之后才分叉。`alert` 只提醒：往实例的对话（`signal_session_id`，为空时取该用户在该账户上最近活跃的对话，一个都没有只记日志）发一条消息，不出卡、不下单、不占执行尝试；`confirm` 出卡确认：按计划腿（平今/平昨分开）调用普通 `create_trade` 出待确认卡，卡带 `strategySource {strategyId, name, attemptId}`，价格方式为对手价（结构止损类入场用最新价），有效期同普通卡；执行尝试记为 `SKIPPED` 并保存 `card_proposal_ids`，同一根已完成 K 线只出一次；用户确认后走普通确认 → 下单，开仓卡在下单前在订单链接上写入与自动下单同一套策略保护（`protection_json`：止损/止盈跳数、结构止损、单笔预算、priceTick/合约乘数，由 autonomy 的同一段逻辑构建并校验，结构止损类在信号 K 线过期时拒绝确认），成交后按它布防策略止损止盈；下单结果回填这次尝试（状态、clientOrderId、冷却 K 线），成交来源显示为该策略；`auto` 自动下单即原路径。同一信号只提醒/出卡一次，信号变化后再提醒；判断以数据库为准（提醒也落一条 `SKIPPED`、`signal_action=alert` 的尝试，不计开仓次数、不占方向对齐段；出卡尝试 `signal_action=confirm`；信号离开上次提醒的动作时记 `strategy_monitor_states.signal_reset_at`），Runtime 重启或蓝绿切换后不会重复提醒或出卡。设置里的 AI 自主执行关闭时，`auto` 按 `confirm` 处理（不再“只监控不下单”）；此时 start 带 `signalAction=auto` 返回 409 `ai_autonomy_disabled`。
13b. 每日开仓次数口径：只数已发出的开仓（`SUBMITTED` / `PARTIAL` / `UNKNOWN`）；未确认、被拒或过期的确认卡不计入，确认并发出后才计入。监控回读的“今日”（`today`、`opensToday`）只在监控状态的交易日等于账户当前交易日时给出，否则为 null。
13c. 实例自动暂停或当天停开新仓（亏损上限、连亏、连续监控失败、执行被停止）时，往实例的对话发一条消息，语音通话在线时播报一句；同一原因同一交易日只发一次。
13e. 等待行情（2026-10-12）：一轮监控抛出的异常按来源错误码在 `strategy_monitor.MARKET_WAIT_REASONS` 一处分类——`strategy_connection_initializing`、`market_series_not_ready`、`market_quote_not_ready`、`market_subscription_limit`、`strategy_bars_insufficient`、`strategy_market_not_fresh`（休市时细化为 `market_session_closed`）是“等待行情”：结果 `status=waiting`，带 `waitReason`、`waitingSince`、`stalled`，不计失败、不清已有失败计数、不自动暂停；同一次等待（休市不算）超过 600 秒 `stalled=true`，detail 写明已等分钟数，日志记一次。`evaluate_plan` / 价差两腿读工作台失败时以 `StrategyRuleError` 保留 provider 的码（未知符号 `market_symbol_unknown`，其他 `market_workbench_unavailable`），句子不变。其余异常仍按失败计数，连续三次自动暂停。
13f. 主动提醒去重（2026-10-12）：上次判到与上次提醒过的 `[动作, K 线]` 存在 `strategy_monitor_states.signal_seen` / `signal_alerted`，先写库再推送；重启或蓝绿切换后同一根 K 线不再提醒，持续中的同一信号也不被当成新变化。下单去重仍是执行尝试的数据库预约，不变。
13d. 执行回报卡（2026-10-04）：`auto` 发出的每条腿在实例的对话（与 `confirm` 出卡同一会话选择）留一条说明与 `card.execution` 卡（来源“策略 · 名称”、方向、合约、手数、价格、理由、按 `simulationOrder.displayStatus` 回读的状态，结果未知照实显示）；order watch 每 2 秒只回读该委托，状态变化时用同一 cardId 原地更新，终态或 30 分钟后停止；这张卡不口播。
13. 每次扩大风险前重新读取账户、持仓和活动委托。已有同合约活动委托、陈旧事实、策略冷却期、策略自行配置的每日次数上限或当前风险规则均会阻止新开仓；SHFE/INE 平仓按今仓与昨仓拆分。
13e. 策略持仓口径（2026-10-08，所有者决定）：`confirm` 与 `auto` 的开平仓判断只数策略自己的成交——`held_position` 口径（该策略仍有效保护 `ai_stop_orders.strategy_metadata_json.$.strategyId` 覆盖的手数，按账户实际持仓封顶），经 `preview_strategy_intent(own_position=…)` 传入 `build_strategy_intent`（旧版意图与 schemaVersion 2 的 `PositionState` 同口径）。同一合约上用户或 AI 手动开的仓不数、不被策略平掉、也不挡策略按 maxPosition 开仓，包括同合约已挂手动止损或其他策略保护的情况；策略的平仓成交先扣它自己的保护行（自动下单走执行腿，确认卡的平仓单按 `strategy_execution_attempts.client_order_id` 归因，`_close` 先按策略匹配再 FIFO）。`alert` 仍按账户该合约持仓判断（用户按提醒手动操作，手动开仓后还能收到平仓提醒）；价差策略不改，按两腿账户持仓判断，同一价差不要再手动交易。回测不受影响（自有模拟）。
14. 账户从日内权益高点的回撤达到已配置的风险预算，或策略当日连续三笔已完成平仓委托毛亏损时，停止新开仓，退出和止损继续运行。平仓按最后一笔成交的时间排序，同一时点按原委托编号稳定排序；交易日取该成交已记录的交易日。迟到终态确认会重算当前连续亏损计数，但已经触发的当日保护独立保留，后到盈利、重启或点击继续不会将其解除；换交易日重置该保护，已暂停策略仍需用户恢复。平台本身不设置默认手数或次数上限。
15. AI 对话里的策略卡片可直接启动、暂停和继续模拟监控，并按需展开最近三次执行及保护状态；操作原位更新，不新增独立“自动交易”面板，也不弹授权卡。`create_strategy_draft` 带 `baseStrategyId` 时（“建议调整参数”）另存为该策略的新版本，原策略与运行中的实例不变。
16. 验证工具结果与单张策略回读包含本人最新的完整验证报告，AI 可以解释具体失败检查、样本内外收益和成本，不再只能看到“失败”；回读报告不会改变策略状态或启动执行。

单次意图预览仍然只读；只有显式启动后的后台监控才可创建模拟执行任务。反向信号遇到已有仓位时先减仓或平仓，不在同一次处理中反手（auto/confirm 的“已有仓位”只数策略自己的仓，见 13e；alert 按账户持仓）；行情、账户或活动委托事实陈旧时禁止扩大风险，但风险收缩意图仍可保留。

正式验证只接受 `tqsdk:` 历史来源。合成或演示数据可以测试回放引擎，但验证报告必须失败，不能冒充正式证据。验证报告保存数据、引擎、策略三类指纹以及样本内外指标；历史制品只作为不可变数据来源，不等于旧的量价示例策略验证了当前草案。

## 后续闭环

```text
自然语言想法
  -> 策略草案
  -> 验证报告（官方历史回放、偏差、样本外、成本、保护器）
  -> 单次只读意图预览
  -> 启动模拟监控
  -> 可暂停的确定性信号监控
  -> Runtime 自动建立模拟执行租约
  -> 单次模拟委托
  -> 委托与成交回读
  -> 暂停或急停
```

验证通过、启动和自动执行是三个独立状态。验证通过不等于已经运行；启动后才可产生模拟执行任务。模拟盘不询问启动或逐单授权，默认不设平台手数、次数或有效期上限；用户配置的策略仓位、风险规则、明确停止/急停、行情陈旧、账户不可用或结果未知仍然失败关闭。验证报告必须绑定当前策略指纹，修改任何参数后旧报告自动失效。

成熟工具对照后的详细取舍见 `AI_TRADING_MATURE_TOOL_REVIEW_2026-09-04.md`。后续实现采用“信号快照 → 仓位意图 → 风险裁剪 → 有限执行任务 → 回读”的分层，不让策略 Controller 直接访问交易网关。

## TqSdk 语义

- 行情、账户、持仓和委托对象是随 `wait_update()` 更新的引用，不是一次性快照。
- 策略只在新 K 线产生后读取上一根已完成 K 线，避免未完成 K 线导致信号闪烁。
- 主连代码只用于发现和研究；策略与委托必须绑定实际交割合约。
- 历史回测使用 `TqBacktest + TqSim`；快期模拟执行使用现有 TqKq 窄网关，两者不能混成同一账户事实。
- 现阶段继续使用明确价格的单次委托；不把 `TargetPosTask` 与手工委托混用到同一合约执行链。

## 安全边界

`liveTrading=disabled` 始终成立。策略草案不含账户密码、API Key 或任意 Python 代码；自动执行只作用于绑定账户的模拟盘，默认不询问逐单授权。用户仍可配置策略仓位和风险参数，并可随时暂停或急停。


## 个人策略页（组合规则）

个人策略库可以选择全部品种或指定适用范围；实际模拟监控仍绑定一个具体合约，并使用独立的运行实例。策略设计任务按用户保存，失败显示具体类型和阶段，重连恢复原任务，明确失败后重试才创建新任务。

待确认的交易参数不会直接执行。旧版只有文字问题的草稿也可以继续回答并完善；每轮最多三个问题，已回答的内容随原规则保留，不因两轮结束而失去继续入口。普通规则说明不作为待确认问题，程序参数名称不进入用户说明。策略面板的结果页（2026-10-08 起取代详情页）根据状态显示“完善策略”或“上线运行”：上线运行打开对话框选合约（默认当前图表合约，绑定了合约的策略锁定）和执行方式（默认出卡确认，AI 自主执行关闭时自动下单置灰并写明原因），“验证并上线”先验证再启动模拟监控，验证失败的原因原样显示在对话框里。运行中的实例在“正在运行”页切换执行方式、暂停 / 继续（对这个执行实例本身按它自己的合约重新验证后启动，保留原执行方式，不换成策略库里的另一份实例；不要求图表在该合约）、停止并平仓（二次确认：只停止不平仓，或停止后为策略自己的持仓出平仓卡等确认，从不直接下单），并明确行情不足和连接失败原因。

组合规则的启动前验证仅检查规则完整性和所需周期的已收盘行情可计算性，不代表完成历史回测或证明盈利。每次修改后按新定义重新验证。

个人策略设计默认让未明确指定时间级别的指标跟随当前图表：`timeframe=0` 表示动态周期，MA5/MA10 表示 5/10 根 K 线，MACD 和 KD 参数不随切换改变。明确指定分钟或日线的条件保持固定。启动和历史回放先将动态条件解析为当前图表周期；切换周期会等待当前判断与提交结束，重新检查行情后更新同一运行实例，保留风控、冷却和执行历史。校验失败时保留原周期。旧策略通过另存版本改为动态周期。

### 策略积木与策略引擎（2026-09-25）

- 规则指标（`Operand.indicator`，均为已收盘 K 线）：`ema`、`atr`（Wilder）、`rsi`（Wilder）、`donchian_high/low`（前 N 根，不含当前根）、`boll_mid/up/down`（总体标准差，默认 20/2）、`keltner_mid/up/down`（EMA 或 MA 中轨 ± k×ATR，默认 20/1.5）、`supertrend`（默认 10/3）；日线锚点 `prev_high/prev_low/prev_close/today_open`、`range_nday`（Dual Thrust 振幅，默认 5 日）、`gap_percent`；开盘区间 `opening_range_high/low`（当日前 N 根）。`average=N` 取该指标的 N 根均线；`offset={factor, indicator: atr|range_nday, period}` 表示“本指标 + factor×波动尺度”。旧定义原样有效，`schemaVersion` 仍为 2。
- 交易日（`trading_calendar.py`）：18:00 后归下一日、周末顺延到周一（与 TqSdk 相同），已知交易日（K 线 `tradingDay` 注记或日线序列）用于跨节假日；锚点一律按交易日从 86400 序列取，日线条件在夜盘使用刚结束的交易日。包含锚点的策略自动多读日线，历史回放同样提供日线。
- 计划级字段：`atrStop`（与 `stopLookbackBars`、`pullback` 三选一）、`trailingStop`、`closeBeforeEndMinutes`+`closeBeforeEndScope`、`maxHoldBars`、`sizing`（`atr_risk`）、`entryWindows`、`allowNightEntries`、`maxEntriesPerDirection`。开仓门槛只挡开仓；时间出场（收盘前平仓、最长持仓）走原有执行方式分流与平今平昨，以意图快照里的 `exitKey` 记为已处理，同一持仓只触发一次、重启不重复。设了收盘前平仓但合约行情里没有 `tradingSchedule` 时，验证上线与启动监控都拒绝（“拿不到这个合约的交易时段，无法保证收盘前平仓”）；运行中交易时段丢失且有持仓，每个交易日往实例对话发一次提醒（通话中播报），请用户手动处理。
