# 手工平仓 v1

## 目标

在快期模拟账户中，从当前持仓直接创建一张限价平仓候选。用户确认前不发送；确认后只调用一次 TqSdk `insert_order`，结果未知时只查询原 `clientOrderId`。

## 复用依据

- 官方 TqSdk 3.10.2 `insert_order`：上期所和能源中心平今使用 `CLOSETODAY`，平昨使用 `CLOSE`；其他交易所统一使用 `CLOSE`。
- 官方 `Position`：使用 `pos_*_today`、`pos_*_his` 和 `volume_*_frozen_today/his` 计算可平数量。
- vn.py `OffsetConverter`：仅作为今仓、昨仓、冻结量和活动委托语义的测试对照，不引入其网关或 UI。
- 冻结 PR #14：只参考其纯今仓、纯昨仓、混合、冻结量、身份不一致和响应丢失场景；不复用 Execution Journal、ClosePlan、多腿或 Protection Owner 生产代码。

## 有意保持的薄边界

- 上期所/能源中心的平仓页默认“自动”（2026-10-16 意图重构第 4 步）：下单票不带平今平昨，由 Runtime 下单规划器按“平今平昨”偏好（设置 → 交易 → 高级交易设置）在可平量（扣冻结）上分配；用户点了“平今”或“平昨”就原样只平那一侧。下单票自己不拆今昨、不选默认桶。
- 一次候选、一次确认：只落在一侧时一个 `clientOrderId`、一张委托；跨今昨时是一张批量平仓卡，今、昨各一张委托，各自回报。
- 其他交易所只显示“平仓”，并发送一张 `CLOSE` 委托。
- 多头平仓发送 `SELL`；空头平仓发送 `BUY`。
- 候选创建、最终确认和实际发送前均重新读取当前持仓、冻结量和行情。
- 沿用 `tqkq_sim_order_links`、现有提交阶段、撤单阶段和重启恢复规则。
- 不新增数据库表、订单状态、Owner、后台轮询或第二事实源。

## 明确不做

- 不使用 `TargetPosTask`。
- 客户端不自己选择或拆分平今/平昨（统一在 Runtime 规划器的 `close_allocation`）。
- 不自动重定价、重试提交或建立多 Attempt。
- 不做自动止损、策略自动平仓、云端执行或实盘交易。

## 验收矩阵

- SHFE/INE 多头平今：`SELL + CLOSETODAY`。
- SHFE/INE 空头平昨：`BUY + CLOSE`。
- 其他交易所：一张 `CLOSE`。
- 今昨混合选“自动”且手数跨两侧：一张批量平仓卡（今、昨各一张委托）；选了平今/平昨只平那一侧，那一侧不够时不出卡。
- 冻结量导致可平数量不足时，提交计数保持 0。
- Sidecar 响应丢失后进入 `UNKNOWN`，查询恢复时提交计数仍为 1。
- symbol、direction、offset、volume、price 任一不一致时显示身份异常并停止推进。
- 界面明确显示自动、平今、平昨、可用数量、方向、价格意图和“每次需确认”。
