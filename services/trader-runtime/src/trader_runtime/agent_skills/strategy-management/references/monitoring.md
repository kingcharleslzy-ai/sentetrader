# 策略监控细节

## 监控状态（get_strategy_monitor_status）

- `monitorState.lastDecision`：最近一次判定（checkedAt / action / reason）；action ∈ open / close / wait / hold。
- 未启动、已暂停、策略不存在分别有明确状态，不猜测。
- 决策原因 reason 是给用户看的中文句子，直接复述即可。

## 启动与暂停

- `start_strategy_monitoring`：策略进入自动盯市，`signalAction` 决定信号怎么处理——alert 只提醒（对话里一条消息）、confirm 出卡确认（每根已完成K线最多一张确认卡，确认后才下单）、auto 自动下单（AI 自主执行关闭时按 confirm 处理）；监控中再调用即修改执行方式，提醒与卡发到调用它的对话。
- 开平仓的持仓口径（2026-10-08）：出卡确认与自动下单只数策略自己的成交（它挂的策略保护覆盖的手数，按账户封顶），同一合约上用户或 AI 手动开的仓不数、不平、也不挡策略开仓；只提醒仍按账户该合约持仓判断；价差按两腿账户持仓判断。
- 停止：`POST /api/strategies/{strategy_id}/monitor/stop` 回到未上线，保留执行记录，不平已有持仓。
- 每日开仓次数只数已发出的开仓；未确认的确认卡不算。监控回读的 `today` / `opensToday` 只在状态属于当前交易日时给出。
- 实例自动暂停或当天停开新仓时，Runtime 会往它的对话发一条消息（通话中播报），不需要轮询。
- `pause_strategy_monitoring`：立即暂停；用户说"暂停监控"时优先执行，不等行情。
- 启动前用 `preview_strategy_intent` 预览下一次会在什么条件下触发，帮助用户确认语义。
- 策略积木（个人策略 StrategyPlan）：收盘前平仓、最长持仓与分段止盈（K 线收盘时按已持仓根数取档、浮盈达标）由监控产生平仓动作，按实例的执行方式处理，同一持仓只触发一次；设了复位条件的方向在上次已发出的开仓之后要等复位条件成立过一次才再开（reason 写明在等复位），重启不丢；开仓时段、夜盘开关、每方向每日次数和按 ATR 定手数只挡开仓（原因写在 reason 里），出场与保护照常。追踪止损与保本在已挂保护上只收紧不放松（两者都有时取更紧的一个），ATR 止损按成交价换算成固定价（确认卡晚点确认仍有效）。设了收盘前平仓但拿不到合约交易时段时不能上线；运行中丢失且有持仓，每个交易日往对话提醒一次，请用户手动平仓。

## 验证（prepare/run_strategy_validation）

- prepare 生成验证任务（合约、区间、初始资金）；run 在模拟环境执行并回报成交、净值曲线要点。
- 验证结果与回测（strategy-backtests）不同：验证是"模拟盘实时跑"，回测是"历史数据重放"。

## 策略与档位

- 本技能按档位开放；未开通时工具不出现在目录，接口 403。
