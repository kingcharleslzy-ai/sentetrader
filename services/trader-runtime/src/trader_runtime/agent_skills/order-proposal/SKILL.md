# 下单出卡（order-proposal）

把用户的开平仓意图变成一张待确认的下单卡：合约、方向、手数、价格方式都写在卡上，用户点"确认"才真正发单；开仓时用户说的止损止盈价随卡一起带（`protection`），成交后按实际成交量自动挂上。

## 何时用

- 用户要开仓："买多一手螺纹""开空两手沪金""挂对手价买"。
- 开仓顺带保护："开多一手螺纹，止损 3100 止盈 3200"（也可只给一个）——`protection` 随开仓卡走。
- 合并卡（平仓并改剩下仓位的止损止盈）："平一半，剩下的止损挪到成本""平掉一手，剩下那手止盈改 3200""平一手，剩下的止损撤了"——同一张平仓卡填 `remainingProtection: {stopLoss?, takeProfit?}`（给价=改到这个价，null=撤掉，不填=按今/昨各桶可证明的原价保留）；"成本"= 该持仓开仓均价（`get_positions` 的 openPrice）按最小变动价位取整，多单向上、空单向下。用户确认一次两步都做：先平仓，成交后按实际剩余手数替换原来的止损止盈（不叠两套），不需要开自主执行；平完全部持仓时不能带。同桶异价、部分仓位无保护或现有来源不能证明分配时返回 `remaining_protection_ambiguous`（422），不出卡；按中文原因请用户明确给价（set）/撤掉（remove），或先在持仓面板整理保护单，不擅自统一价位或撤保护。出卡后变歧义则第二步失败、本次修改未执行，已有保护仍按实际成交收拢。
- 用户要平掉某一持仓的一部分（带手数）："平掉螺纹的一手多单""沪金平两手""卖掉这个"。
- 用户接受"先出卡、看清楚再确认"的模拟下单流程。
- 用户问"钱"但不下单："开一手螺纹要多少保证金""我最多还能开几手""平掉这手能腾出多少钱"——用只读工具 `estimate_order` 回答，不出卡。

## 何时不用

- 全部平仓/清仓，或不带手数平掉整个品种（"平掉螺纹""把沪金平了"）→ 批量平仓（batch-close）。
- 把某品种调到目标手数（"调到三手多单"）→ 目标持仓（target-position）。
- 撤单、追单、改价、给已有持仓挂/撤保护（"给我的螺纹多单设个止损 3100"）→ 撤单/追单/改价（order-ops）。
- 只是问行情、问该不该下单 → 先行情/决策上下文，明确要下单才出卡。

## 步骤

1. 简单的说法（"买两手螺纹""螺纹平一手""全部平仓"）Runtime 的解析器直接交下单规划器出卡，不经过你；解析器拿不准的（改口、带止损止盈、少见说法）才到你这里。
2. 用 `propose_order` 把这句填成下单意图：act（open 开仓 / close 平一部分 / close_all 平掉整个持仓 / target 调到目标持仓 / reverse 反手）、symbol（说了月份写合约，只说品种写品种名，没说不填=当前窗口合约）、dir（多/空，不是买/卖）、vol / target / frac（平一半=0.5）、price（counter 对价/市价、queue 挂单价、last 现价）或 limitPrice（用户说的价）、bucket（平今/平昨）；act 必须是用户说的动作（平/开/调到/反手）。一句里有几单时填 legs，Runtime 不出卡、请用户一单一单说，照返回的话回。只填用户说了的：没说的方向、手数、合约留空，Runtime 会出“需要确认”卡追问，不要猜，也不要用文字追问。用户随单说的止损价放 `protection.stopLossPrice`、止盈价放 `protection.takeProfitPrice`（至少一个才填）。
3. Runtime 的规划器读整账户、定合约月份、开平与方向、手数（差额、平一半向下取整至少 1 手）、平今平昨（上期所/能源中心按账户平今平昨偏好分配，与 estimate_order 同一份，跨今昨出一张批量平仓卡）、价格，并做就绪检查（数据新鲜度、涨跌停、持仓、时段）与保护校验（多单止损要低于委托价、止盈要高于它，空仓相反）；不就绪或条件单（到价/到时间才下）不出卡并给中文原因。
4. 只问"钱"时用 `estimate_order`（symbol/side/offset/volume，可选 price，平仓还可选 positionBucket=today/historical/all，默认 all 按账户平今平昨偏好拆）：开仓回答每手保证金、手续费约、可开手数与资金够不够（可开手数 = 可用资金 ÷（每手保证金＋每手手续费），与问的手数无关，手续费估不出时 maxOpenVolume 为 null）；平仓回答预估释放的保证金，按今仓/昨仓拆分给出 `feeBreakdown`——今昨各先扣冻结，上期所、能源中心按指令/账户平今平昨偏好拆，其他交易所的平仓指令不分今昨、费用按撮合的真实顺序先昨后今分别收平昨、平今费率；请求数超过这次实际可平的手数时不拒绝，按可平量估算并在 `missing` 写明（如 `close_volume_exceeds_closable:昨仓只有 N 手可平，按 N 手估算`），手续费与释放保证金用同一份手数分配；估算按 `basis` 口径说明，缺数据的字段为 null 时按 `missing` 原因如实说明，不编数字。只读，不出卡、不拦截下单。
5. 卡片内容如实复述给用户（含保护价位），等待用户点确认或说"确认"；一次出几张卡（如今仓全平涉及几个合约）就各自确认（语音逐张念、逐张问）。
6. 用户确认后才发单；结果按实际回报播报（已受理≠已成交）。保护在成交后按实际成交量挂上（部分成交挂部分、撤单不挂），挂上时 Runtime 会回报一条通知，如实转述。

## 安全边界

- **一律出卡→确认**：AI 永远不直接发单；语音"免口头确认"只是设置项，卡仍然先出。
- 打字与语音前台（`AI_TRADER_VOICE_FRONT_ACTION`）里一句话说全了的下单由 Runtime 的解析器直接交规划器出卡（不经本回合），对话里会出现这张卡和那句回复；拿不准的才到你这里，按上面第 2 步填意图。
- 模拟账户专属；实盘请求一句话拒绝。
- 模拟账户没有风险规则（每日亏损上限、合约白名单等），设置里也没有这一项：用户要设就说明没有，改推"给持仓挂止损单"。
- 疑问句、否定句、转述、条件单、整句收回、UI 上下文都不是授权；用户没说要下单就不出卡（这类回合 Runtime 不给出卡和任何下单写工具）。交给你的下单回合必须调 `propose_order`（出卡、拒绝或追问），只回文字不算。

细节（卡片字段、确认时效、失败码人话）见 [references/card-flow.md](references/card-flow.md)。

## 典型说法

- 买多一手螺纹
- 开多一手螺纹，止损 3100 止盈 3200
- 开空两手沪金，挂对手价
- 帮我把这个多单平了
- 开一手螺纹要多少保证金
- 我最多还能开几手
- 平掉这手能腾出多少钱

## 反例（不该触发）

- 全平（批量平仓，走 batch-close）
- 别下单啊，我就是问问（明确禁止，只回答不下单）
- 帮我设个每日亏损上限（模拟账户没有风险规则，口头说明并改推止损单）
