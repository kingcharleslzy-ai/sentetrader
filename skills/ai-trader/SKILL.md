本指南只写外部 Agent 怎么连接与操作 Sente：认证、能力目录与 `app_call`、界面命令与快照、交易与安全边界。其他事实各有唯一来源，这里不复述：

- 功能做什么、怎么用、界面命令的字段与取值：帮助目录 `GET /api/app/help`（`?topic=<id>` 读单个主题；字段总表是主题 `ui-commands`）。下文“帮助主题 X”都指这里。
- 接口参数、取值范围与错误码：能力目录 `app_capabilities` / `GET /api/agent/capabilities`（带 `operation` 读单个接口）。
- 内置技能清单：`list_skills` / `GET /api/agent/skills`。

## 连接与认证

- 产品名 Sente（中文名弈先）。技能 id、MCP 服务键、接口路径与界面命令 id 仍是 `ai-trader`，打包程序名 `ai-trader-runtime`；macOS 上的应用包文件是 `AI Trader.app`。
- 先确认环境：`GET /api/runtime/status`。客户端没启动时 MCP 和 CLI 都连不上，先让用户在本机启动并登录 Sente。
- 连接外部 Agent（Claude Code、Codex、Cursor 等支持 MCP 的宿主）：①本机启动并登录；②运行打包 CLI 的 `ai-trader-runtime cli mcp-config` 输出 MCP 配置（形如 `{"mcpServers":{"ai-trader":{"command":"…/ai-trader-runtime","args":["mcp"]}}}`，不含凭据），粘到宿主配置；③宿主可见 app_capabilities、app_call 与技能三件套 list_skills / activate_skill / read_skill_resource。
- 没有 MCP 的宿主用同一可执行文件的 CLI：`cli capabilities` 查目录、`cli capabilities --operation '…'` 查单个接口定义、`cli call` 调用（AppCall JSON 经标准输入或 `--file` 传入；多账户时加全局 `--account <账户id>`，id 取自 `GET /api/accounts`，不填按会话或默认账户）、`cli skills list|show`（`--resource` 读附加资源）、`cli doctor` 检查初始化与账号连接、`cli migrate-strategies` 迁移旧策略（`--apply` 保存到当前登录账号；只迁移定义、按内容去重、不启动监控）。
- 云端 Runtime 两个入口：桌面客户端与打包 CLI/MCP 直连 `https://ai-runtime.qilinshuzhi.com:8443`；网页版走官网同源中转 `https://qilinshuzhi.com/trader-runtime`（只放行 80/443 的网络也能用）。两者是同一个 Runtime、同一套接口，登录各自独立。
- 打包 CLI/MCP 的标准输入输出使用 UTF-8；读取子进程管道时显式按 UTF-8 解码。
- 连接信息来自本机 0600 的运行时连接文件，凭据由程序读取：不能查看连接文件、读取 Keychain 或把令牌放进模型参数；不向模型提供密码或 Key。
- 配置外部 OIDC 的部署遇到格式无效令牌回 401：重新认证，不要绕过认证重试业务写入。
- 外部 Agent 不因此获得额外交易授权：急停、风险检查和实盘关闭同样生效；接口与 CLI 用同一能力目录、均需认证；切换模型不改变能力与权限。实盘始终关闭，不存在的能力要明确报告，不能用任意脚本、DOM 注入或鼠标模拟绕过业务边界。
- 客户端连不上应用服务时（超时、自动重试与提示见帮助主题 connection）：读快照判断，不据此重发写操作。下单、回测、登录、注册等写入客户端不设时限，结果以原请求为准，写入超时不算可重试；登录 / 注册 / 建号请求会消耗邀请码、计入登录失败次数，不能替用户重发。说明卡与合约列表的重试命令（`help: {retry: true}`、`contractCatalogRetry: true`）见帮助主题 ui-commands。

本站模拟持仓读取：`GET /api/positions`（含 `paperusd:…`）行情中断仍返回 200 和最近撮合账本仓位，必须连同 `dataStatus`、`isCached`、`ageSeconds` 解读，价格与盈亏可能沿用最近快照。首次装配最多等 2.5 秒，超时回 `snapshotAvailable: false`、`items: []`、`dataStatus: unavailable`，不能报告为确认空仓。引擎账户条目报错时同样只给最近成功快照；快期读取及交易执行校验不变。
- 非默认安装路径或其他系统：用实际的 Runtime 可执行文件路径，并以 `--connection-file` 指定宿主维护的连接文件。MCP 入口不会自动启动客户端，也不更改客户端的连接。

## 能力目录与统一调用

- 使用 `app_capabilities` / `app_call`（CLI 与内置模型同一套）。先读本次连接的能力目录，再以 `operation` 查所需接口的完整参数定义，不照抄旧版本字段；界面命令单个字段的完整定义用 `operation: "ui:<字段>"`（如 `ui:disclosure`）读取。外部 Agent 拿到的是完整目录，读 `GET /api/app/help` 也返回完整说明（内置 AI 的紧凑目录与技能挂载见 `docs/FUTURES_AGENT_CAPABILITY_V1.md`）。
- `operation` 保留目录中的 `{路径参数}` 占位符，实际值放 `path` 的同名键，如 `{"operation":"GET /api/app/ui/windows/{window_id}","path":{"window_id":"实际UUID"}}`。已读定义在同一构建和登录会话内复用；不能把 MCP/CLI 的结构化参数与内置模型的 requestJson 字符串封装混用。
- 技能按渐进披露使用：`list_skills` 看当前账号可用的技能（停用或档位未开通的不出现），`activate_skill` 读完整手册，`read_skill_resource` 读技能目录内 `references/` 相对路径。HTTP 等价 `GET /api/agent/skills`（含每个技能的可用状态与不可用原因 `disabled`/`not_in_plan`/`owner_only`、`aiFeature`）、`GET /api/agent/skills/{id}`、`…/{id}/resource?path=…`。技能清单不在本文件列出：用 `list_skills` / `GET /api/agent/skills` 查当前账号可用技能。
- 技能可有一层上级（`parent`），上级不可用时子技能一并不可用。`disabled` 的技能对外部 AI 不可用，即使用户自己在界面上还能点：不要引导用户绕开，也不要绕过 `app_call` 直接调它的接口。只有 `aiFeature: true` 的技能停用后用户本人也用不了。
- 解释功能读 `GET /api/app/help`：先用人读层（summary/steps/faq），细节在 `detail`；解释策略术语优先引用 `strategy-glossary` 的 `terms`，与模板参数 `help` 口径一致。`?topic=<id 或旧 id>` 只返回该主题，未知 404。

## 界面命令与快照

- `GET /api/app/ui/windows` 读在线窗口、状态与 revision。MCP 默认筛选本机设备，内置 AI 默认筛选发起对话的窗口；明确需要其他设备才用 `query: {"deviceId":"*"}` 并固定 `windowId`。多窗口时按已知环境选择，无法确定才询问用户。检查 `device.platform/version/build` 与 `connection.build/compat`：正式桌面的 `device.build` 与快照 `context.connection.build` 回报实际源码提交，先筛选在线目标窗口再核对发布 SHA；旧客户端的缺省、空值或 `dev` 不构成来源证明，`compat: ok` 只证明版本兼容。外部 Agent 请求可带 `X-AI-Trader-Client: agent/<版本>`，Runtime 在每个 `/api/` 响应回 `X-AI-Trader-Client-Compat`（只判客户端是否过旧；网页是否过旧由网页客户端对照 version.json 判断）。网页窗口快照 `context.webUpdate: {available, banner}`；网页刷新与“检查更新”是用户操作，没有界面命令——用户问“网页怎么还是旧版”时让其点提示条的刷新，或 设置 → 关于 / 手机我的页底部的“检查更新”（自动刷新规则见帮助主题 settings）。
- `GET /api/app/ui/windows/{window_id}` 读结构化页面快照：当前弹窗（`state.dialog`，打开时快照以该对话框为根）、可见文字（含滚出视口的内容）、控件状态（`inViewport`、select 的 `value`/`options`、与标签不同的 `title`——如置灰原因行）、尺寸与计算颜色，以及合约、周期、指标、设置值。这不是像素截图；输入框内容和凭据窗口不提供；离线或过旧的快照不能当当前现场，检查 online 与 capturedAt。图表 K 线需另读行情接口。当前图表合约以快照 `state.symbol` 为准（新闻 `pinnedSymbol` 是阅读品种，可与图表不同）。图表视口 `observation.context.chartViewport` 含 `panes`、`displayedIndicators` 与 `shortPanes`：K 线不足、标“数据不足 · 需 N 根K线”的副图（口径见帮助主题 chart）对应 `displayedIndicators` 为 null，不要读成指标值。
- 命令生命周期：`POST /api/app/ui/commands` 传新 UUID `commandId`、`windowId`、`expectedRevision` 和仅含一个字段的 `changes`，按原 commandId 查询。只有 `applied` 表示客户端已回报目标状态；`queued`、`dispatched` 未完成；`unknown` 可能已生效，先读最新状态，不能盲目重发；`rejected`、`expired` 也先读现状。命令保留五分钟，Runtime 重启不重放。`query: {"waitMs": 3000}` 等待真实回执；applied 返回的 `state`、`observedRevision` 供下一条命令用，超时不重发。行情加载成功与界面切换成功是两件事。
- 字段与取值的完整总表读帮助主题 `ui-commands`（`GET /api/app/help?topic=ui-commands`：每个 `UiChanges` 字段、dialog 与 disclosure 名称、只能关闭的确认框与别名都在其中），单个字段用 `operation: "ui:<字段>"`；本文件不重复。交易笔记、策略面板与策略卡的命令和接口见帮助主题 playbooks、strategy-editor 与 ui-commands。
- 分步引导：用户说“带我看看 / 教我用 / 怎么下单”时用 `tour` 生成课程（字段见 ui-commands；默认七步课程在帮助主题 tour 的 `tour` 字段，目录里的 `tool:start_tour` 一步启动）。用户打字说“下一步 / 结束”由 agent 发 `next` / `stop`；语音通话中 Runtime 自己路由并念每步的 `say`。
- 问题反馈（页面内容见帮助主题 settings）：AI 只能用 `settingsPage: feedback` 打开与观察页面，不代填、复制或发送；输入与正文预览不进入窗口快照。用户点“打开邮件草稿”后仍需在邮件程序里确认发送。
- AI 指令栏见帮助主题 ai-command-bar。外部 Agent 要撤销 AI 建的到价提醒、画线、策略 / 条件提醒草稿，同样直接调 `DELETE /api/market/alerts/{id}`、`DELETE /api/market/drawings/{id}` 或 `DELETE /api/strategy-plans/{id}`（在监控、有委托或持仓时 409 并给原因）。下单仍只出确认卡。
- 快捷键由用户本机录制、只存本机，agent 不改（快照 `settings.shortcuts` 可见）。
- 按需截图 `POST /api/app/ui/windows/{window_id}/captures`（body `{requestId:新UUID, expectedRevision}`，query `waitMs=3000`；未完成按原 requestId 读 `GET /api/app/ui/captures/{request_id}`）：只有 `ready` 有图片，凭据窗口拒绝、输入遮蔽；只有可见内容或页面版本变化才拒绝（行情推送刷新不算）；图片 60 秒过期，过期或拒绝后重新读取页面再试。网页客户端只提供结构化现场。核对视觉效果才截图，不用截图坐标代替业务接口。
- AI 标注层（`highlight`、`chartAnnotations`、`chartFocus`、`chartMarks` 字段见帮助主题 ui-commands，讲解方式见 chart-ai）只是观点，不产生委托。工具封装 `tool:get_chart_bars`（读用户图上可见 K 线、均线与摘要，`bars[].time` 直接用于标注）、`tool:annotate_chart`、`tool:highlight_ui` 都要 `uiWindowId`（内置 AI 默认本次对话窗口，绝不猜别的设备）。讲走势：先 get_chart_bars，再画（point/hline/zone、≤6 条、短标签），按 ①②③ 逐条解释；讲完不清除，用户右键自己清。
- 同一窗口还有 `queued` / `dispatched` / `unknown` 的命令时，新命令回 409“已有未确认的界面命令，请按原编号查询”：按原 commandId 查询；`unknown` 在五分钟保留期内一直挡住该窗口的新命令。

## 交易与安全边界

- 模拟盘专用：实盘始终关闭。一般排障、查看界面不授权下单、启动策略、撤单或重启连接；沿用用户本次已给出的授权，不重复要求确认。
- 账户停止与恢复（停止三档与角色见帮助主题 protection、accounts）：停止 / 急停作用于该账户所有用户；恢复只能由执行负责人明确授权。用户本人的恢复（界面“恢复执行” = `POST /api/ai-execution/resume {sessionId, symbol}`，或 `POST /api/ai-execution/start`）一并解除本站模拟美元子账户的停止，`tool:resume_simulation_execution`（AI 自己的恢复）只恢复当前账户。切账户或账户代次变化后旧的确认作废；已发出的请求只查原编号，不重发。放弃未发委托只能在它所属且有写权限的账户执行，失败不写入。复盘补充保存 / 删除要显式指定人民币或美元账本，删除成功以 `deleted: true` 为准；迟到回执不改切换后的账本。
- 下单出卡只用 `tool:propose_order`（字段见它在能力目录里的定义）。参数只填用户原话说了的，没说的留空、不要猜，也不要先读持仓自己算手数；外部 agent 自己保证每个参数都来自用户原话。返回处理：`errorCode: legs_entangled`（一句几单）→ 请用户一单一单说；`invalid_tool_arguments` → `warning` 用中文写明缺哪个字段或哪个字段不合法；`order_<slot>_missing` → 按 `data.ask` 的 `question` 问用户，用户选了某个 option 就把它的 `prompt`（补全后的整句）原样发回；`proposal_gate_not_ready` → 把 `userFacing.candidateIssues` 按原话转告，不要换参数重试；带 `cond` 的条件单不出即时卡，到价的返回 `suggest: price_alert`，建议先建价格提醒。单张卡返回 `symbol/side/volume/limitPrice/readiness/riskCheck`，多张卡返回 `totalCards` 与 `cards`，每张各自确认。规划器怎么定合约月份、开平、今昨、手数和价格见帮助主题 order；内置 AI 的槽位出处核对与卡上 `intentSource` 见帮助主题 ai-actions。
- 随单保护与合并卡（行为见帮助主题 protection）：`protection` 方向或价位不对时 422 中文原因、不出卡。`remainingProtection` 出卡前遇到同桶不同价、有/无保护混合或手数归属不可证明时返回 422 `remaining_protection_ambiguous`：让用户明确设置或撤掉该项，或先整理保护单，不要自动选最新价；平完全部持仓还带它返回 422 `remaining_protection_nothing_left`。第二步结果随卡回写（`GET /api/proposals/{id}` 读同一份）：`remainingProtection.status` = awaiting_close / done / failed / skipped，带 `reason` 与 `result`；`perBucketOriginal` 是出卡时各桶原价，`result.perBucketProtection` 是实际剩余桶/手数/价位及该次事务的 `previousStopLoss/previousTakeProfit`，混合价的单值字段为 null，不代表没有保护；被替换的旧保护 `last_error=replaced_by_card`。
- 保本提醒（见帮助主题 breakeven）：读问题与结果 `GET /api/ai-execution/breakeven`（卡 `card.reminder` kind=breakeven 带 `step` 与 `breakeven.state`，`breakeven.stopIds/triggers` 是它问的那几行止损）；只有用户明确要移或不移时才调 `POST /api/ai-execution/breakeven/{id}/move` 或 `/decline`，不要替用户决定移止损。
- 挂/撤已有持仓的保护（行为见帮助主题 protection）用 `tool:set_simulation_stop_loss`（HTTP `POST /api/ai-execution/stops`，可带 `trailing` 与 `breakevenAtR`）与 `tool:cancel_simulation_stop_loss`（`POST /api/ai-execution/stops/{stop_id}/cancel`），挂上后复述两个价位与手数。上期所/能源中心今昨仓分开挂（`positionBucket` 只能 today/historical）。前 N 根 K 线追踪：K 线不够 N 根拒绝 `trailing_bars_unavailable`，现价已越过那 N 根的极值拒绝 `trailing_bars_breached`。已挂保护的 `trailing`/`breakeven` 写着它怎么动，`triggerPrice` 是现在的位置。账户数据不新鲜或读不到时会被拒（“账户数据还没跟上，稍后再试”）。AI 工具路径要求执行负责人且自主执行开启，被拒时不绕路，指引用户在持仓面板该持仓行点“保护”自己填；AI 限时执行租约到期（`ai_execution_expired`）只拦 AI 自己发起的操作，用户自己挂止损、确认带保护的下单卡照常生效，不要说成用户也挂不了。用户点了提醒卡的“重新挂”就是要按原价位重新挂，照常走 `set_simulation_stop_loss`。策略挂的保护（`source: "strategy"`）只读，撤销前先向用户说明并确认。本站模拟等交易所结算价时已触发的保护行 `lastError = paper_settlement_pending`，向用户说“已触发，在等交易所结算价，公布后按当时价格平仓”。
- 读保护与账户现状：已挂保护读 `GET /api/ai-execution`（`stops`）；内置 `tool:get_account_activity` 返回 `protections`（每条带 `status`、`statusLabel`、`effective`、失效原因 `statusDetail`，有效的在前、失效的只留最近 10 条）与 `protectionRule`。只有 `status` 为 ARMED 且剩余手数大于 0 的才仍挂着；用户提到的保护价不在有效列表里时直接说它已经不在了，不当作有效止损讨论或建议改价。撤单、挂/撤保护与停止/急停的工具回报（`cancel_simulation_order` / `set_simulation_stop_loss` / `cancel_simulation_stop_loss` / `stop_simulation_execution`，急停撤掉的委托与保护不在其中）带 `accountAfter`：写完之后现场重读的整个账户的 `positions`、`workingOrders`（仍挂着且有剩余手数的委托）、`protections`（全部仍生效的，不截断）与 `asOf`/`asOfLocal`（北京时间）；`available: false` 时不陈述现状。说剩余持仓、挂单或保护只按回合开始时现场读的账户现状与本轮工具结果，不按之前对话里说过的；chat:send 的事件里答案前有 `warning`“账户现状未能确认”时，开头那份也不再当现状，需要时再调只读的持仓/委托工具。
- HTTP/CLI 出卡（`POST /api/simulation/proposals`、`/api/simulation/close-batch-proposals`、`/api/simulation/target-position/proposals`）与 `tool:propose_order` 是同一个规划器，但单笔路由分不出是下单票还是外部 AI，只做下单安全检查（合约到期 409 `instrument_expired`，报价/时段/价位/涨跌停按中文原因拒绝）；外部 AI 出卡请用 `tool:propose_order`，它多一道 AI 决策就绪检查。上期所/能源中心平仓只有用户明确说了平今/平昨才传 `positionBucket` today/historical（那一侧没有可平的仓 409 `close_bucket_empty`，有但不够 409 `close_volume_unavailable`），否则不传（或传 `all`）按偏好自动分配，跨今昨时返回一张批量平仓卡（响应带 `orders`，确认同一路由）。带账户头（CLI `--account`）时卡出在指定账户（须有授权且可写，否则 403/404），与会话账户不同时以指定为准、卡上 `accountOverride` 写明；不带时跟随 `sessionId` 所属账户。
- 目标持仓与反手（“调到三手多单 / 做到多 2 手 / 清零”，行为见帮助主题 order）：用 `tool:propose_order` 的 `act: target`（反手 `act: reverse`）；HTTP 路由收 `{symbol, targetNet, priceIntent?}`（priceIntent passive / aggressive / last 对应工具的 queue / counter / last）。差额由 Runtime 按当前持仓算：agent 不要先读持仓自己算手数，也不要用开/平仓卡拼接（“做到多 2 手”是目标，不是再买 2 手）。该合约还有没成交的挂单返回 `target_position_orders_working`，委托读不到或不是最新返回 `target_position_orders_unreadable`。反手两段只确认一次，agent 不要也不需要再确认第二段（卡的 `targetPosition.authorizedByProposalId` 记着授权它的第一段卡，审计里有 `target-plan-authorized`）。HTTP 出卡的回答带 `approvalId` / `proposalVersion`（客户端快捷反手用它们当场走普通确认路由）。
- 问“钱”但不下单（“开一手螺纹要多少保证金”“我最多还能开几手”“平掉这手能腾出多少钱”）用只读 `tool:estimate_order`（HTTP `GET /api/simulation/order-estimate`），缺数据的字段如实说明、不出卡；口径见帮助主题 order。报手续费以它或 `tool:get_market_snapshot` 的 `contract.commissionPerLot` 为准，HTTP `GET /api/market/{symbol}` 的 `contract.commissionPerLot` 是行情源参考值，不拿来报（见帮助主题 contract-info）。账户可用资金与风险度读 `tool:get_account_summary`；“今天平仓盈亏/手续费/今天赚了多少”直接报它 `pnlFields` 的字段，不从成交或交易日志加总，也不用“今日 − 浮动”推算（口径见帮助主题 positions）；2026-10-12 前的日记录 closeProfit 是混合持仓价口径，只拆分有偏、权益正确。
- 持仓（`get_positions` / `GET /api/positions`）每行的 `lastPrice` 是持仓自己的最新价（浮盈按它算，旧版 sidecar 没有该字段时为空）：问“某合约现在多少”优先看行情快照，持仓行的现价用于说明浮盈。
- 确认后的 `candidate_recorded` 只是用户授权。单笔卡的真实状态看 confirm 返回的 `simulationOrder.displayStatus`（或按 proposalId 查委托列表），批量平仓卡看 `simulationOrders` 逐笔事实与 `execution` 汇总。委托读数的 `accountId` 是所属账户，撤单、查询等请求须带该账户头（CLI `--account`）；会话事件里的下单类卡（`proposal.trade` / `proposal.close_batch` / `proposal.spread`）带 `accountId`，查这张卡的委托要读它所属账户的列表（`GET /api/simulation/orders` 带 `X-AI-Trader-Account: <accountId>`），不是会话当前账户的。同 `idempotencyKey` 重试只回读不重发；未发送的用 `POST /api/simulation/orders/{clientOrderId}/continue|abandon`；结果未知的只能 `query`，任何 agent 都不得重发——query 时网关确认这笔从未发出（`lastReadError` 为 `gateway_command_expired` / `sidecar_reconnecting` / `sidecar_auth_rejected`），委托回到“待发送”，之后才可 continue。本站模拟结算完成前下单返回 409 `paper_settlement_pending`。到期合约暂估平仓的成交（`reason: "expiry"`，带 `expirySettlement`，`statusLabel`“暂估，待核”）要向用户说清暂估价不是最终结果；挂起与暂估待核的合约在账户摘要（`get_account_summary` / `GET /api/account/summary`）的 `expirySettlements` 里逐项列出（symbol / finalDay / status / statusLabel，暂估带 estimate）。委托状态、限价当日有效、成交价、结算、交割月与开仓均价口径见帮助主题 order、positions、paper-account。
- 汇报下单结果按实际发出的子单：跨今昨的平仓是一次确认、两笔委托，汇报写总手数并逐笔说平今/平昨、手数、价格和 `displayStatus`；规划器跳过的一侧（create 返回的 `skipped`，带 volume 与原因码）要说少了几手和原因，不按用户请求的手数报。确认已记录时不得说“未确认”或建议重下：被拒照实说，结果未知只 query，待发送的 continue/abandon。对话卡“确认”按钮与开仓没说合约时的规则见帮助主题 order。
- 作废待确认卡：用户明确说取消/算了/不要了时用 `tool:reject_proposal`（body `{"proposalId","proposalVersion"}`；HTTP `POST /api/proposals/{proposal_id}/reject`，body `{proposalVersion, idempotencyKey}`），与卡片“放弃”按钮、语音“算了”同一接口；id 与 version 取 chat:send 返回的 `pendingProposals`。版本不符 409 `stale_proposal_version`，卡已结束 409 `invalid_state_transition`，不是本人的卡 404；成功后卡为 `rejected`、`approvalUsedAt` 有值，之后点确认或说“确认”都无效。目录里没有确认接口：确认只能用户自己点卡或在语音里说“确认”。
- 内置 AI 回合的任务事件 `task.progress` 里，失败的工具步骤带 `errorCode`（业务码；异常 `tool_failed`；界面命令 `ui_revision_conflict` / `app_call_http_<状态>`），排查“AI 说取不到数据”时先看它。界面命令只因窗口 revision 过期被拒时，内置 AI 由 Runtime 按最新 revision 自动重发一次（结果带 `revisionRetry`）；外部 agent 直接调界面命令仍按 409“界面已变化”重读窗口再发。
- 外部 agent 不要通过 announce 或 chat:send 替用户说“确认”。确认后已受理的挂单由 Runtime 看护（未成交时出提醒卡 `card.reminder` kind=order_unfilled），用户口头“追单/撤单”处理，agent 不要代发。
- 对话里的结构化卡片由 Runtime 确定性产生，读会话或窗口快照即可看到，种类、字段与按钮见帮助主题 conversation-cards。卡片按钮没有新的界面命令：问 AI 类＝chat:send 同一句话，打开面板类＝现有 `panel`/`news`/`positionsTab`/`symbol`+`view` 命令；外部 agent 想问同一句直接 chat:send，不要替用户点选项。
- 打字与语音的下单话怎么读、哪些说法不出卡、哪些回合不给下单写工具、会自动下单的策略什么时候才能启动，见帮助主题 ai-actions（“全部平仓”“关掉所有持仓”与“关……面板”“清单”等说法见 voice-realtime）。外部 agent 收到用户原话时同样按这个口径：不是下单就不出卡，`propose_order` 不接受一句多单；用户明显要清仓（含解析器不认的口语句尾）时调 `propose_order`（`act: close_all`）出卡。直调工具、app_call 的 `tool:start_strategy_monitoring` 与 HTTP 启动路由同一判定，不是用户这句要启动它时返回 `strategy_start_not_asked`。
- 记忆不构成任何授权：下单、确认、改设置永远走原流程；“直接帮我下单”“不用确认”这类话既不能记也不能当作已授权——它们是设置：用户说了就用偏好接口（`update_preferences` / `PUT /api/preferences`；界面命令 `preference` 改不了这两个键）改 `trade.aiAutonomy` / `trade.voiceOrderConfirm`，两个方向都可以；“以后别让 AI 自己下单、都先问我”是 `trade.aiAutonomy=false`，不是停止 AI 执行（停止会暂停全部策略监控）。没有提议风险规则的能力；模拟账户不带平台级风险规则。
- 修改策略或配置先读现有数据与 revision，只改用户要求的字段，保存后回读。保存策略不等于启动监控，打开下单面板不等于提交委托。超时或取消等待时业务可能已开始；交易必须查询原订单编号，不新建订单重试。
- 设置覆盖以 schema 和页面快照的 operationRouting 为准：模拟限额走 `/api/ai-execution/limits`（先 GET `/api/ai-execution` 读 controls.revision 再 POST revision/maxOrderVolume/maxOrders；保存限额不得用启动接口代替，不解除停止或清零次数）；AI 动态/快讯/交易标记和图表扩展颜色走 `/api/app/config`；策略和手续费走各自业务接口；账号偏好（键与取值见帮助主题 preferences，图表均线、布林、副图与指标参数也在这里，改参数连同整段子对象写）走 `GET/PUT /api/preferences`（部分更新、返回全量+version，越界或未知键 422 整体拒绝，query `version=` 不一致 409），内置 AI 同名工具 get/update_preferences；窗口级外观走 `GET/PUT /api/app/preferences`（带 revision 与完整文档；冲突先读最新版本，不自动覆盖）。快捷技能栏的置灰按钮是技能不可用，输入框上方的建议问题（`data-agent-target="chat-examples"`）点一下只填进输入框不发送，都不要替用户点，要问同一句直接 chat:send。不能宣称通用界面命令能操作全部核心功能。

## 各业务域

### 行情

- 行情、合约信息与交割的功能和口径见帮助主题 chart、board、contract-info、delivery（`GET /api/app/help?topic=<id>`）。`get_market_analysis` 另带 BOLL(20,2)、ATR(14)、RSI(14)、CCI(14) 最新值与一句话读法（口径同 tqsdk.ta）；当日涨跌看 `get_market_snapshot` 的 `dayMove`（对昨结算），写“暂无当日涨跌”时（夜盘开盘前或本交易日还没有成交）快照的涨跌幅 0 是占位、不是读数。合约带交易所日内开仓限额时，行情快照与合约搜索给出 `openLimit` 与今日已开手数，超限不出卡、返回 `open_limit_exceeded`。
- 合约信息与交割：`get_market_snapshot` 的 `contract` 与 `deliveryNotice`（合约目录条目同样带）字段见帮助主题 contract-info、delivery。“一手多少钱”“跳一下多少钱”“什么时候要平仓”用它答，不要自己换算月份；`deliveryNotice.estimated: true` 时转述说“大约”。交割提醒由 Runtime 自动发，只提醒，不平仓、不拦下单。
- 报价总表 `get_market_board`：“今天哪些品种涨得最多”“持仓量最大的几个”用它，不要逐合约 get_quote。`sort=changePercent|volume|openInterest|openInterestChange`（默认 changePercent 降序）、`exchange` 可选、`limit` 1–30（默认 10）；服务端约 30 秒一轮刷新，最多 160 行、超出按目录序截断并标 `truncated`；未成交/盘前行在 `status` 标明；最新价落在当日最高/最低之外的行按 `market_quote_unavailable` 返回、不给价格。界面命令与列偏好 `marketBoard` 见帮助主题 board、ui-commands（改列先读当前列序再增删）。
- 自选品种记在偏好 `watchlist.products`：“交易所.品种”（如 SHFE.rb）的整段清单，≤50 个、后加在后，按品种不按月份。“把螺纹加到自选”“自选里删掉沪金”“我的自选有哪些”先 `get_preferences` 读整段、改这一项再整段写回；“报价表只看自选”用 `boardExchange: watchlist`。
- 外盘行情：`GET /api/market/foreign`（工具 `get_foreign_markets` 同源）一次读全部外盘主连，品种清单、数据源、外盘图表与界面命令见帮助主题 board、ui-commands。每行整行取自一个源（`source`，名称见 `sourceLabels`），带 `unit`、`domestic`（关联国内品种）与 `chartSymbol`（图表用的快期外盘主连代码，界面命令 `symbol` 切过去），MT5 来源另带 `contract`（所用月份合约，如 GCEZ26）；该源没有昨结算时 `change`/`changePercent` 为 null，昨结算为负数时只有 `changePercent` 为 null，不要自己推算；`status` ok/stale/unavailable；有品种没取到时 `partial{failed, carried, missing}`（missing＝从没取到过、也没有上次的行）。
- 外盘下单（本站模拟的美元子账户，规则见帮助主题 paper-account）：子账户编号 `paperusd:…`（`currency: USD`），合约写 `CME.<MT5 月份>`（如 `CME.GCEZ26`，目录 `isMain` 是主力月份）。在人民币账户上出外盘单（`propose_order` 的说法或 symbol 是外盘品种，或什么合约都没说而窗口开着外盘图表；下单票送 `KQD.m@…` 也一样）会自动落到美元子账户，卡上 `accountOverride` 写明、金额字段 `currency: USD`。外盘持仓、平仓与成交在美元子账户上读写（HTTP 带 `X-AI-Trader-Account: paperusd:…`；`/api/positions` 的外盘月份行带中文名 `instrumentName`）；人民币账户的运行状态账户块带 `foreignAccountId`，`get_positions` / `get_account_activity` 在人民币账户上附 `foreignAccount`（编号、`currency: USD`、同一读数），报持仓时两边都报、外盘写美元。
- 到价提醒（技能 price-alerts，`create_price_alert` / `list_price_alerts` / `cancel_price_alert` 走 `/api/market/alerts`，外部 Agent 经 `app_call` 调同三条路由）：功能与外盘规则见帮助主题 price-alerts。只提醒不下单，到价自动下单不存在，如实说明。删除只针对生效中的提醒：已触发的 DELETE 回 409 并说明原因，不存在或已删的回 404。画线提醒 `POST /api/market/alerts {drawingId}`（symbol、price 可省）；挪线（`PUT /api/market/drawings/{id}` 带 points）后提醒重设不了时回包带 `alertNotice`，该提醒已取消。
- 收盘前与风险度提醒由 Runtime 自动做、无工具，规则见帮助主题 reminders。用户说“快收盘提醒我”“风险度高了告诉我”→ 指到 提醒面板 → 通用提醒 的这两个开关并用 `update_preferences` 改 `notify.marketCloseReminder` / `notify.riskReminder`；要盯具体价位用到价提醒。
- 条件提醒（只提醒的策略）：功能与界面命令见帮助主题 reminder-center。新建 / 修改走策略编辑卡的提醒模式（`strategyEditor: {new: true, reminder: true, ask?}` / `{edit: id}`），存为草稿或“开始提醒”由用户点；或走接口 `POST /api/strategy-plans`（`plan.reminderOnly=true`）→ `POST /api/strategy-plans/{id}/validate` → `POST /api/strategies/{runId}/monitor/start {signalAction: "alert"}`（只能 alert，confirm / auto 回 409 `strategy_reminder_only`）；暂停 `monitor/pause`，删除先暂停再 `DELETE /api/strategy-plans/{id}`。
- 提醒面板与提醒记录：类别与开关、投递规则、读写接口见帮助主题 reminder-center。`GET /api/reminders` 一页默认 50 条，有 `nextCursor` 就带 `before` 接着读；`accountId` 非空的账户类提醒（成交、撤单、挂单未成交、复盘等），点开委托或复盘前先用 `tradingAccount` 切到它，等 `state` 报出的当前账户是它再开。`get_account_activity` 的成交行带 `sourceLabel`（策略执行回报卡只进策略自己的对话，别处靠它认出是哪个策略）。用户说“别提醒我成交了”“关掉交割提醒”→ `update_preferences` 改对应 `notify.*`；“看看今天有哪些提醒”→ 读 `GET /api/reminders`。
- 锁屏提醒与管理员行情桥告警（`admin_alert`）见帮助主题 push。Agent 可读 `GET /api/app/push`、发 `POST /api/app/push/test {deviceId?}`、移除 `DELETE /api/app/push/subscription?deviceId=`；开启只能由用户在那台设备上点“打开锁屏提醒”并在系统询问里允许（`PUT /api/app/push/subscription` 不在能力目录），agent 不能替用户订阅。
- 用户画线（技能 chart-drawings，`list_chart_drawings` / `create_chart_drawing` / `update_chart_drawing` / `delete_chart_drawing` / `clear_chart_drawings` 走 `/api/market/drawings`）：线型、坐标、样式、界面命令见帮助主题 chart-drawings，样式取值以接口 schema 为准（fib/percent 的坐标可带 levels）。只在用户明确要求时替画 / 替改 / 替删；锁定的线移动返回 409，先解锁；`allPeriods: false` 时合并后的样式须带有效 `period`（0 = 分时），缺周期返回 422。与 AI 讲解标注是两层：不占 AI 标注的 6 条上限，“清空图上标记”不清用户画的线；AI 自己的临时讲解标注仍走 `annotate_chart`。
- TqSdk 官方数据（`get_settlement_prices`、`get_main_contract_history`、`get_symbol_ranking`，用法见能力目录的工具说明）：问结算价、换月、龙虎榜用它们，不要联网搜。外部 agent 要这些数据用 `chat:send` 让内置 AI 走对应工具。
- 回放：功能与步进、行情缺项、保留规则见帮助主题 replay。回放窗口固定历史合约；历史回放调用须明确 `replayId`，不得把模拟账户状态当作回放结果。进入回放的窗口把界面快照报给回放子环境：读 `GET /api/replays/{replayId}/api/app/ui/windows`（`state.replay=true`），主环境的 `/api/app/ui/windows` 里那个窗口回放期间不再更新，那里的 `replay=false` 不代表没有在回放。控制走 `tool:control_replay`（`POST /api/replays/{identifier}/control`，body `{"action","speed?"}`，动作见工具说明；speed 缺值报 `speed_required`）。回放行情不带昨结算、当日开高低与当日成交量，不要把它当成 0 或缺数据去推算；不能按时间跳，如实说明，不要用连续 step 逼近。状态 `incomplete`＝上一步中途超时、这一分钟只推进了一部分：读数不可交易、新委托与撤单被拒、原委托仍可 query，play/step 先走完这一分钟再回到 `ready`，不要重建回放或重发委托；`unconfirmed`＝某一步没拿到结果、Runtime 正用同一步编号自动重发（同一步只执行一次），期间不可交易、play/step/停盘被拒，等它回到 `ready`。回放里的到价提醒、收盘前/风险度提醒与画线只限回放合约，提醒工具走回放命名空间的同一批接口。创建（`POST /api/replays`）后未就绪周期 503 `market_series_not_ready` 是等待不是故障，不要据此重建回放。交易日历 `GET /api/market/calendar` 返回当前交易日、`previousTradingDay`、最近十个已结束交易日与可回放的 `latestClosedTradingDay`；行情源全挂时返回最近一次成功的日历并带 `stale: true`、`savedAt`（存在 state_root，重启后仍在），从没成功过或那份的交易日已早于今天才 503（sidecar 答空日历也按读不到 503）；选到休市日或还没走完的交易日，创建回 422 中文原因点名最近的交易日，换日重试即可。服务更新（蓝绿换槽）不结束回放：新槽以暂停状态接管，`replay_already_active` 也计入可接管回放，不因部署前后状态变化重建；已结束的回放被接管后条目暂停、控制操作 409，不要试图重开。不要按目录修改时间判断或手动删回放库。

### 调研与新闻

- 研究数据 `GET /api/research/summary?symbol=` 一次返回六项（position_rank、warehouse_receipt、spot_basis、inventory、term_structure、fees_margin），单项 `GET /api/research/{dataset}`；各项内容、按合约/按品种、交易日历与来源限制见帮助主题 research。每项独立 `status`：ok / stale（源失败时的上次成功值）/ unavailable（`error` 给原因，如大商所 position_rank 的 `research_source_blocked`、广期所铂钯 term_structure 的 `research_product_not_in_source`）；引用带 `asOf` 与 `source`；position_rank 与 fees_margin 带 `data.contract`，position_rank 的 `data.scope=product` 表示交易所只给全品种汇总；外盘代码回 `foreign: true` 与说明。爬虫源缺失是常态不是故障，不为此重试或排障；不要把参考保证金写回手续费设置；不要替用户绕过交易所校验。
- 消息面 `GET /api/research/news?symbol=`：`source` 为 deepseek_search（DeepSeek Search 搜索、Fetch 读取前两篇原文，失败保留摘要；是背景报道不是核实过的行情数据）。来源失败返回 stale/旧值日期/真实错误，无旧值则 unavailable；不得把失败当作没有新闻。`results` 按品种筛过：留下的带 `ai` 一行解读，筛掉的在 `screen.dropped`（字段同快讯）；没有 `ai` 的条目不自行推断利多利空；缺少媒体名显示链接域名，缺少发布时间不推断补齐。失败结果共享缓存 60 秒。全网新闻后台采集见帮助主题 research。
- 调研汇总 `GET /api/research/desk?symbol=`（外盘代码 `KQD.m@CME.NQ` / `CME.ENQZ26` 也可以）：页面结构、事实来源、信心算法、自动重判与重算条件见帮助主题 research。
  - 不等采集：带 `factsRefreshing: true` 时事实是旧的或还在加载（各块 `status: loading`），几秒后再读一次；要当场的新事实用 `get_research_brief`。
  - 返回 `facts`（每条 id/section/kind data|report/label/value/source/asOf，报道带 url；带 `fetchedAt` 时照引；快讯是 section=flash 的事实，`sections` 里没有快讯段）、`sections`、`tiles`（≤8 格：label、value、color up/down/none、note 含数据日期、ref 事实 id；缺的不给，不补零）、`news`（今日新闻要点的 net 与 take，没有要点时没有这个字段）与共享 `judgment`。
  - `judgment.status=ready` 时带 stance、confidence（程序算）与 confidenceBasis（转述信心时带上）、modelConfidence（模型自报，仅供对照，不要当信心转述）、headline（headlineBasis 为依据）、points/risks/watch（`basis` 所引事实 id、`kind` 推断或推测、`grounds` data/report/mixed、`quote` 服务端核对过的原话；points/risks 带 `direction`）、`conclusion`、`change`（previousDay、previousStance、same、text，没有历史时不给）、`stale`（{count, newsNet}，转述时说“判断可能过时”；自动重判带 `reason: "news"` 与 `trigger`）、`nextAuto`（{nightAt, news}，夜盘品种 `reason: "night"`）、`updates`（今天每次判断）、`basis` 快照与 `changedBasis`（转述时说明“生成后已更新”，以快照为判断当时的依据）；旧判断可能没有 confidenceBasis、modelConfidence、conclusion，direction 按立场推断。pending/refreshing 生成中，disabled 档位不能触发且无现成判断，insufficient 事实不足，failed/budget_exhausted 生成失败或当日次数用完（failed 带 `error` 与 `retryAt`）。ready 时带 `refreshError` 与 `retryAt` 表示最近一次重算失败、展示的是之前那份（`generatedAt` 不变）：转述要说重算失败，`retryAt` 之前再刷新不会重算，之后要显式再刷新一次。
  - 事实 `status=stale`（附 `error`，所在 section 也为 stale）转述必须说是旧值并给日期；`M.price` 标签为“最近收盘价”时是报价缺失、用日线收盘代替。
  - `POST /api/research/desk/refresh`（界面命令 `news: {deskRejudge: true}`）：照返回的 `rejudge.message` 转述，不要循环调用；started 之后若判断带 `rejudgeSkipped` 或 `generatedAt` 没变，就是没有生成新判断。
  - 转述时把事实与 AI 判断分开，报道说明是媒体说法，判断不是交易建议；逐条注明来源：数据带来源与日期，期货公司观点写“某某期货认为”，媒体写“据报道”，快讯写“快讯”，调研判断写“调研判断（推断）”。问“怎么看/综合分析”先读 desk 再考虑联网。
- 快讯 `GET /api/research/flash`（内置 AI 工具 `get_news_flash`）：来源、保留、筛选分层与今日新闻要点见帮助主题 research，参数与返回形状见接口说明。`since`/`include` 是客户端本地缓存用的紧凑增量，agent 读取不传；`official=true`（工具 officialOnly）只列官方条目、不经品种筛选，可往前读 30 天，其余 `hours` 最长 72。`screen.mode=keyword` 表示这次未经 AI 筛选（超限、模型不可用或失败时退回关键词，不丢列表、不报错），`unscreened` 条目没有 `ai`（合成事件里 tier 为 unscreened）；`ai` 与 `brief` 只解读新闻本身，不是交易建议；不带 product 的宏观/全部视图不经 AI 筛选。`lastPoll{at, failedSources}` 是最后一轮抓取；该轮实际尝试的来源全失败且窗口内没有任何存量时 `status=unavailable`（`research_flash_unavailable`），是抓取失败不是没有快讯（尝试范围按当轮动态算，不与固定源数比较）；本机版没有快讯源时为 `research_dependency_missing`；回放中不可用。
- 经济日历 `GET /api/research/calendar?days=&region=&product=`（工具 `get_economic_calendar`）：`days` 1–7，超出 422；`status` ok＝窗口内每天都取到（items 为空即确认没有事件）、stale＝有日期没取到（`staleDays` 显示上次内容、`missingDays` 无数据，不能说成那几天没有事件）、unavailable＝窗口内一天都没有、loading＝首轮还没跑完。
- 外盘参考 `get_foreign_markets`：`status` stale 为上次价格（`fetchedAt` 是采集时间，`error` 为 `foreign_sources_failed:<源>`，或源答了却缺这一行时 `foreign_rows_missing`）；带 product 时关联外盘一行都没有为 `unavailable`（`error=foreign_product_unavailable`），部分没有时 `missing` 列出缺的品种（只算已配置数据源能提供的；不带 product 时列整表缺的）；desk 的 `M.foreign` 写“某某 暂无报价”——不要当成该品种没有关联外盘。desk 的 `E.rates` 只挂一个源或 LPR 刷新失败时 `partial{failed, carried}` 写明哪部分是上次的值（事实标 stale）。利率用 `get_interest_rates`。
- 调研面板（`panel: "news"`，页签、子页、折叠与快照见帮助主题 research、ui-commands）：今日作战表数据走只读 `GET /api/research/sheet`（不调模型），快照 `state.news.sheet`；转述时只讲价位和情景，不替用户下多空结论。回放中面板不请求、不显示新闻与研究数据。
- 配置共享行情源时，普通用户的合约目录、报价、图表与 search_instruments/get_market_snapshot/get_market_analysis/get_chart_bars/get_market_board 共用该来源，不要求先连接本人快期账户；界面与命令入口维持原认证，不以共享源替代本人交易身份、下单前核验或策略执行/回测的原有读取。

- 多 AI 研讨 / 辩论：流程、模型与兜底、对账规则、界面命令与限制见帮助主题 research-debate。

### 策略与回测

- 功能本身见帮助主题 strategy、strategy-editor、strategy-templates、strategy-backtest、strategy-launch、strategy-funds、strategy-glossary（`GET /api/app/help?topic=<id>`；价差执行规则在 strategy）；内置工具用法见技能注册表（`GET /api/agent/skills`）。下面只写外部 Agent 调用时要注意的。

- 执行方式（三种方式、持仓口径、停止并平仓的核对见帮助主题 strategy-launch；`monitor/start` 参数与 409 `ai_autonomy_disabled` 见接口说明）：监控中再调 `monitor/start` 即修改执行方式；confirm 的信号卡带 `strategySource`。`monitor/stop` 默认不平持仓（返回 `positionsKept: true`）；body `{closePositions: true, sessionId?}` 停止后若它自己还有持仓就出平仓卡并返回 `closeCards`（卡按实例自己的交易账户出，卡上 `accountOverride` 注明；出不了卡时 `notice` 是一句中文原因，照实告诉用户到持仓里手动平）。每张卡带自己的 `stop_close` 尝试归属，确认时核对不过返回 409 `stop_close_*`：提示用户重新“停止并平仓”，不要重发旧卡；从不直接下单，自动下单的实例也一样。价差停止平仓确认的底层守卫：同一事务内复核同腿委托与守卫后新增成交，跨 Runtime 进程也只允许一张卡发送；并发确认时迟到的拒绝不覆写已确认的卡；基线成交的交易日字段不可读时不做日过滤；账户成交记录不新鲜或旧 sidecar 无 combined 快照能力都拒绝。内置工具 `start_strategy_monitoring` / `get_strategy_monitor_status` 与这条 HTTP 同一入口同一核对（读数同一份）；策略挂在别的交易账户时工具拒绝（`strategy_account_not_bound`）、status 不给读数。监控回读 `GET /api/strategies/{id}/monitor` 带 `signalAction` / `effectiveSignalAction`、`position`（策略自己的持仓 {direction, volume}）、`signalsToday`（当日执行尝试数）、`researchClash`（`{stance, direction, text}`，震荡 / 不明 / 无判断为 null）与 `funds` / `drawdown`（见下）。auto 发出的每笔委托在同一会话有执行回报卡 `card.execution`（同一 cardId 更新）。价差策略 confirm 时出价差卡 `proposal.spread`，确认结果带 `simulationOrders` 逐笔回读，执行结束再推 `executionConclusion`；等确认时策略已停返回 409 `strategy_not_monitoring`（卡带 `confirmBlocked`，不下单）。

### 策略实验室与“试几组参数比一比”

- 结果页“试几组参数比一比”（行为见帮助主题 strategy-lab）：`POST /api/strategy-plans/{id}/compare {symbol, timeframe?}` 不带 `runOn` 在服务端算（你调用时就这样）；`GET` 同一路径读最近一次（未比过 status none；rows 每组 summary 与 inSample / outSample，current 标当前组，line＝“后 X 个月单独检验：……”，source 与 fallbackReason）。界面命令 `strategyLab` 见帮助主题 ui-commands。
- 多组对比 `POST /api/strategy-labs`（字段见接口 schema）：`skipInvalid` 默认严格，任何一组建不起来整次 422 并指明第几组；true 则跳过并记 `skipped:[{index,reason}]`，能比的不足 2 组仍 422；不带 label 的模板组只列与默认不同的参数，最多 3 个。`GET /api/strategy-labs/{lab_id}` 读 status pending / running / done / error、source browser / server、tried、ranking；云端那次被服务重启或发布打断的读回 status error、`ranking.error`“这次比较被中断了”，可重新比或 `POST …/{lab_id}/run-server`（可带 `fallbackReason`）。`POST …/{lab_id}/choose`（variantId、name?）服务端先按同口径重跑权威回测再保存，与本机结果不同时带 serverSummary 并以服务端为准；上线仍由用户决定。`…/inputs`、`/api/strategy-engine/bundle`、`…/results` 是界面本机计算用的（engineDigest 不符 409＝页面版本旧，让用户刷新重跑，不自动转云端），你不要调用。
- 排名口径：同一合约一次最多 12 组，历史按时间切前 70%（样本内）/ 后 30%（样本外），跨过切点的那笔平仓两段都不计；样本内第一名到样本外掉队（排名掉出前三、样本外亏钱、平均每笔明显缩水）标 overfit；另有 negative_oos、too_few（样本内不足 5 笔不参与排名）；衰减＝样本外平均每笔÷样本内平均每笔。各组样本内都没赚钱时 `ranking.best` 为 null、`noProfit` 为 true——如实告诉用户，不要硬挑一组。样本内 / 样本外按完整逐笔算，结果里的逐笔清单只留最近 2000 笔，不影响排名与 best。按资金比例定手数拿不到保证金时整次比较报错。价差策略不支持实验室；两组以内直接规则回测两次更省事。

- `GET /api/account/habits?currency=CNY|USD`（只读，口径见帮助主题 review 的“习惯对照”）：`actual` / `planned` 各自 {count, pnl}，`gap`＝planned − actual；`split` 是计划外单按开仓标签（remind / adhoc，旧的无标签另列）各自的盈亏，相加等于 actual − planned（即 −gap）；`holding.lateLosers` / `holding.earlyWinners` 是估算、不和差额相加，没有可比的为 null；`picks` 最多 5 笔（id 可直接用于界面命令 `reviewSelect`，带 reason）；计划内少于 5 笔时 `status: insufficient`（带 planned、needed）；盈亏口径 `basis` net / gross。界面与快照见帮助主题 ui-commands。
- 引导复盘 `GET /api/account/review-picks?scope=day|week`（挑选规则见接口说明）：带用户复盘一次问一笔，回答用下面的接口原话记下。等价入口是复盘页“语音复盘”（`disclosure: {name: "voice-review", open: true}`，接通后 Runtime 逐笔提问）。
- `PUT /api/account/trade-notes/{round_id}`（body 见接口 schema，`via` typed / voice / chat）写 / 覆盖这笔的补充，`DELETE` 删除。只记用户自己说的想法，不写你的评价；round_id 不属于当前账户的已平仓交易时 404。`approximate: true` 的一边是按委托补录的成交（见帮助主题 review）：真实成交到达后 round_id 随之变成真实成交号，旧 id 再写 404 时重读日志取新 id；迁不过去的补充列在 `GET /api/trade-review` 与 `GET /api/account/pnl` 的 `unlinkedNotes[]`（`{roundId, text, via, updatedAt}`），只读——不改写、不猜着挂到别的交易上，需要用户自己删掉重写（删除用列表里的原键 `DELETE /api/account/trade-notes/{roundId}`）。复盘页“未关联的补充”块的界面命令见帮助主题 ui-commands。

### 私人记忆

- 三层记忆与规则见帮助主题 memory。接口都要登录、按账号隔离，别人的 id 一律 404“没有这条记忆”。
- `GET /api/memory?includeInvalid=false` → `{enabled, items, changes}`（items 每条 id / layer / layerLabel / text / source / evidence / tags / status / createdAt / updatedAt；changes 是最近 20 条变动）。`POST /api/memory {layer, text, quote?, products?, via: settings|chat}`：经 `/api/agent/call` 的调用（嵌入 agent、MCP `app_call`、打包 CLI 都算 AI 调用）一律按 `via=chat` 处理，body 里写 settings 也不豁免原话核对与开关，来源只由调用身份决定；`via=chat` 必须带 quote（用户原话 ≤200 字），服务端与最近 7 天用户消息比对（两边去空白与中英文标点），对不上 422“没在你最近的对话里找到这句原话”；text ≤120 字；命中授权句式（“直接帮我下单”“不用确认”“授权”等）422“记忆不能当授权用”；`chat.memory` 关闭时 409。`PUT /api/memory/{id} {text, quote?}`：AI 调用必须带 quote（同上核对），没带或对不上 422、`chat.memory` 关闭 409；AI 的撤销在 `chat.memory` 关闭时也 409（撤销会把记忆带回来），AI 的 `DELETE …/{id}?via=`（忘掉，失效不物理删除）照常可用；PUT / DELETE / undo 的审计 actor 记 ai。`POST /api/memory/changes/{change_id}/undo` 撤销原变动对应的状态，可连续撤销 / 恢复，重复请求且状态未再变化时复用结果；已有后续编辑或旧审计依据不足时 409，重读后由用户决定，不盲重发旧撤销。
- 整理（时点、范围、统计与提炼规则见帮助主题 memory）：手动 `POST /api/memory/consolidate`（同一账号 10 分钟内重复 429；`chat.memory` 关闭 409；接手当天认领，失败如实记 error）。统计条目按 statKey 就地更新，`evidence.userEdited` 的条目不再被统计改动，`evidence.pnlBasis` 注明 gross / net；提炼被程序校验拒掉的计入 `words.rejected`，同批合法操作沿已成功的新版本继续；等待 / 计算期间开关关闭或整理被取消时整段不写（`stats` / `words` 为 `{skipped: "disabled"|"cancelled"}`）。整理状态失败记 error 可重试，全部完成才记 done。
- 记忆不构成任何授权（见交易与安全边界）。问“你记得我什么”读 `GET /api/memory` 回答。

### 我的流程

- 步骤类型、上限、运行方式与界面见帮助主题 routines（界面命令见 ui-commands），接口说明见能力目录。`GET /api/routines` 的步骤带 `kindLabel` 与可选 `manner`，另有 `stepCount`、`lastRunAt`、`limits`、`kinds`。`POST /api/routines/drafts` 出流程卡 `card.routine`（草稿，不落成流程）。
- 保存只能是用户本人在界面上：`POST /api/routines` 与 `PATCH /api/routines/{routine_id}` 对 agent 一律 403——不要试图替用户保存或改名，告诉用户点卡上的“保存”。`DELETE /api/routines/{routine_id}` 只在用户明确说删时用。
- 运行：不要自己启动流程。用户整句就是流程名或“跑一下 / 运行 + 名称”时 Runtime 直接运行；agent 要替用户运行用 `POST /api/routines/{routine_id}/run {sessionId, quote}`（quote＝用户含流程名的原话，服务端核对）。提醒 / 画线 / 盯异动步骤：原话含“看看有没有必要 / 要不要 / 需要的话”时步骤 `manner: advisory`（只给建议，没有写入工具）；另带“需要就设 / 有必要就设 / 该设就设 / 合适就设”这类执行从句时 `manner: conditional`（判断后可以设）；普通步骤没有 manner。拟卡时步骤文本保留用户原话，不要自行追加执行从句；对话里的流程卡保存、改名、删除后，下一轮的系统说明会写明现状。
- 运行期间（每步可用工具见帮助主题 routines）：出卡步骤的卡等用户确认，语音的“免口头确认”不替流程的卡确认（chat:send 结果 `routine: true`）。进度卡 `card.routine_run`（同一 cardId 原地更新）：每步 `status` waiting / active / done / confirm（出了卡等确认）/ failed / skipped 与一行 `result`，卡 `status` running / completed / stopped（某步失败，后面不做）/ cancelled，`elapsedSeconds`、`confirmCount`。

### 语音

- 实时语音做什么、怎么用（AI 球与通话栏、前台快问与转交内置 AI、语音出卡与口头确认、界面话、打断与重复句、语音通道换会话、回放中的通话、诊断时间线字段）见帮助主题 voice-realtime；通话开关、静音、球菜单的界面命令见帮助主题 ui-commands。外部 agent 要知道的：鉴权用登录会话；`GET /api/voice/realtime/status` 的 `enabled` 只看服务器有没有语音密钥，`reason` 为 `voice_key_missing`、`cloud_call_limit`（本账号已有一路，新通话以 4429 关闭）或 `voice_daily_limit`（当日语音分钟用完，通话以 4430 关闭，次日恢复）；`POST /api/voice/realtime/announce {kind,text}` 给通话中的用户播报一句（同类 60 秒节流）。
- 语音出的卡同样只能由用户口头“确认”或点卡确认。挂单看护（15/60 秒提醒；结果未知时只读查到确定，最多 30 分钟，期间不提醒不重发）和连续语音里重复前句的剥离都由 Runtime 处理，agent 不代发、不自己去重。
- 界面命令入队前被拒（目标窗口不存在或离线、界面已变化、已有未确认命令、命令编号冲突、命令过多）时响应头 `X-UI-Command-Attempted: false`，可重读状态修正后重试；其它 422 或超时不能当作未发送的证明。
- 按住说话（帮助主题 voice-ptt）是用户的物理输入，没有界面命令；agent 要说话直接 `chat:send`。转写 WebSocket `/api/voice/transcribe`、念回答的 `/api/voice/speak` 与 `/api/voice/realtime` 一样不在能力目录，鉴权、voice-call 技能与每日语音分钟和通话相同，通话中以 4432 `call_active` 拒绝；快照 `context.voice.ptt` 可见。
- 快照出现 `context.voice.micSilent: true`（`micLabel` 是浏览器实际在用的麦克风，`micSuggestion` 是同一副耳机带免提的那一项）时，请用户按帮助主题 voice-realtime 换麦克风或检查系统静音，不要当成 AI 没回应；客户端停在“语音通道没有响应，请稍后重拨。”（时间线 `upstreamGaveUp`/`hangupByStall`）时请用户稍后重拨，不是麦克风或 AI 的问题。

### 账户与多用户

- 角色与执行负责人见帮助主题 accounts。非执行负责人的 AI 调自主动作（`execute_simulation_trade`、`set_simulation_stop_loss`、恢复执行、建租约、启动策略监控与策略自动下单）回 403 `not_execution_owner`（工具里是中文 userFacing 提示），改用 `propose_order` 出卡由人确认；viewer 一切写操作 403 `account_read_only`；未授权账户 403 `account_not_granted`。停止与急停（`POST /api/ai-execution/stop`、`stop_simulation_execution`）的范围见帮助主题 protection：在人民币本站模拟账户（`paper:`）上停时连同同号美元子账户（`paperusd:`）一并停，返回 `companion: {accountId, cancelledOrders | error}`，`pausedStrategyIds` 含两边的策略；只有用户在人民币账户上 `POST /api/ai-execution/start` 明确恢复才一并解除子账户，AI 发起的恢复不解除。
- 设置 → 账户（模拟盘 / 实盘两行、交易账户下拉、档位额度）见帮助主题 accounts、ai-model 与 ui-commands。
- 指明账户带 `X-AI-Trader-Account: <账户id>` 头（MCP 的 `app_call` 传 `account`、打包 CLI 加 `--account`，都会带上；经 `/api/agent/call` 时头随调用转发到业务接口、`tool:*` 工具与 chat:send 新建的会话，工具会话按账户各一个，工具内部再转发的业务读取——如交易日志、复盘——也落在该账户；内置 AI 回合里的嵌套读取跟对话会话的账户，会话重绑后跟随）；不带时按会话绑定账户或默认账户解析（无任何授权账户的成员不回落默认账户，账户类操作 403 `tqkq_account_required`；配置了本站模拟盘时该请求先幂等补开该用户的 paper 账户再重解析）。方案卡/策略等存储行以所属账户为准，不随请求头转移。`GET /api/accounts` 列出有权限的账户（`current` 是本次实际账户）；外部 agent 切会话账户用 `PUT /api/sessions/{session_id}/account`（body `{"accountId", "expectedGeneration"?}`，后者取 runtime.status 的 `accountGeneration`）：回 409 `account_switch_superseded`（detail 带会话当前的 `accountId` 与 `accountGeneration`）时什么都没改，按它或最新 runtime.status 再决定，不要原样重试。观察当前账户用 `runtime.status.account`（快照 `state.tradingAccount` 同值）；给用户窗口发 `tradingAccount: <账户id>` 等价在“设置 → 账户”里选账户。
- 快期模拟已停用交易（帮助主题 paper-account）：`POST /api/auth/tqkq` 是 UI 唯一登录入口（新账号名失败时带 `canRegister`，用户在登录框确认后走注册接口）；外部 agent 不替用户登录或注册，复用本机已保存会话。所有者的快期主账号（`tqkq-sidecar`）没有下单网关：对它下单或撤单回 `simulation_gateway_disabled`，不要重试，改用本站模拟账户（`PUT /api/sessions/{id}/account` 或账户头）。`POST /api/accounts/bind-tqkq` 与 `unbind-tqkq` 只为旧桌面客户端回 410 `tqkq_trading_retired`，不在能力目录。
- 本站模拟账户（`providerKind: "paper"`，行为见帮助主题 paper-account；未配置引擎时 agent 不需要区分）：下单回执常是“已受理/部分成交”而不是立刻成交，按委托状态与成交读结果，不要因此撤单重发；每笔成交带 `fill`，对账与复盘直接读它。下单结果带 `contractSource`（`fees: contractTable`；`feeStale: true` 表示表里的保证金超过 3 个交易日未更新；随委托保存，查委托与重放回执同样带）；合约资料缺失被拒的委托是错单（`isError`）并写明原因，等行情补齐再下，不要换参数重试。不存在的合约读报价答 404 `symbol_not_found`、下单因没有行情被拒且不进账本，都不要原样重试，改用目录里的写法。用户问仓位为什么没了，先查有没有 `clientOrderId` 以 `paper-force-` 开头的强平成交。目录与 `runtime.status` 的 `poolStatus`（connecting/connected/offline）复用同一字段。开通本站模拟（`POST /api/accounts/open-paper`）是用户自己的账户决定，不在能力目录（`app_call` 得 404），agent 只提示入口，开通后切换用 `PUT /api/sessions/{id}/account`。下单/撤单的命令编号由 Runtime 生成（agent 不传）；回 409 `command_kind_mismatch` 时不要换编号重发，先查原委托现状。
- 档位（帮助主题 ai-model；主账号不受档位约束）：可用技能看 `GET /api/agent/skills`，档位视图看 `GET /api/auth/owner/status` 的 plan/features/skills，模型与用量看 `GET /api/models` 的 quota；AI 简报品种上限读 `GET /api/app/brief-subscriptions` 的 limit（档位字段 `briefProducts`），档位调低后已存清单超限（`overLimit`）时，只删减已存品种的整表 `PUT` 即使仍超限也照存，新增或换入品种仍 422 `brief_limit_exceeded`。越界是业务事实不是故障，向用户解释后停止：换不在档位内的模型 403 `model_not_in_plan`（`/api/models` 只列档位内，inPlan 说明原因）；token 用完当日新提问 429 `daily_token_quota_exceeded`；全局停用技能 403 `skill_disabled`（含主账号）；档位未开通技能 403 `feature_not_in_plan`（读取类接口与收尾动作——`/api/ai-execution/stop`、回放关闭、监控暂停——永远可用；语音 socket 4431 拒绝；行情简讯读取返回空列表加 `status:"disabled"`；被关技能的工具与接口不出现在 `/api/agent/capabilities` 与模型回合工具集）；语音分钟用完 status reason `voice_daily_limit`、通话 4430 拒绝，次日自动恢复。
- 服务端 accounts 文件可给账户声明 `grants`（operator/viewer 用户名列表）与 `renameFrom`（一次性全量改名），由服务端管理，agent 按目录里看到的账户 id 操作。
- 没有本站模拟盘的部署里快期登录仍绑定 `tqkq-pool` 账户：请求落到未装配的账户会自动触发装配，池满 503 `runtime_capacity_full`、装配失败 502 `account_start_failed`；装配中或排队中 `GET /api/runtime/status` 仍可读（降级载荷，`account.poolStatus` 报进度）。

### 后台（仅主账号）

管理员接口只主账号会话可用，其他人一律 404（是否存在都不暴露）；agent 帮管理员操作用这些接口并回读结果。后台没有界面命令，需要主人看界面时请他用浏览器打开后台（帮助主题 admin）；给普通用户查自己的用量不需要它们。邀请码生成、列表、停用（`POST/GET /api/auth/owner/invite-codes`、`POST /api/auth/owner/invite-codes/{id}/disable`）不在能力目录：那是管理员在网页后台的人工动作，agent 不替主人发码停码（备查：生成 body `{"daysValid":1–90,"plan"?,"code"?,"uses":"once"|"unlimited","neverExpires"}`，格式错 422 `invite_code_format`、重复 409 `invite_code_exists`，响应带 `inviteCode/expiresAt(null＝长期)/plan/uses`，旧数据行 `code` 为 null；停用幂等，未知 id 404 `invite_code_unknown`；列表对已登录管理员同源读取可不带 Origin，写接口严格校验请求来源）。

- `GET /api/admin/plans` 列档位与技能、功能、模型目录；`POST /api/admin/plans`（`{"label","copyFrom?"}` 缺省复制默认档）新建；`PUT /api/admin/plans/{name}` 部分更新（models/额度 null＝全部/不限；skills 部分映射只传要改的技能 id，未知 400 `skill_unknown`、非档位技能 400 `skill_not_tier_gated`），立即生效；`DELETE`（有人使用 409 `plan_in_use`、默认档 409 `plan_is_default`）。技能全局启停 `GET/PUT /api/admin/skills`、`PUT /api/admin/skills/{id}` 对所有人生效（含主账号）。
- `PUT /api/admin/users/{username}` 改档位（下一次请求生效）或停用（立即结束全部会话、其后登录 401 `account_disabled`，重新启用可再登录）；`GET /api/admin/users` 的今日成本是参考值不是账单。
- 用户体验 `GET /api/admin/rum?range=1h|24h|7d`：`metrics.<lcp|inp|cls|fcp|ttfb|price_latency|kline_first_paint|sse_down|memory>` 各有 n、p50/p75/p95（毫秒；cls 是 ×1000，memory 是 MB）、`byClient`（web/desktop/mobile）与 `series`（epoch 秒，1h 每分钟、24h 每 10 分钟、7d 每小时一点）；`counters.errors.byCategory` 报错类别计数、`counters.sseReconnect` 断线重连次数；`totals` 是会话/用户数、可见分钟、按客户端与网络类型的会话数。数据不含对话、合约或账户内容，只能说明“慢在哪、哪端出错多”。
- 重置本站模拟账户只能主人本人在后台操作，不在能力目录，agent 调用不了（帮助主题 paper-account）。
- 内存诊断（默认关闭）：`POST /api/admin/memory/trace?frames=10` 打开追踪并以此刻为起点（追踪中再调把起点移到此刻）；`GET /api/admin/memory?limit=25&types=true` 读 `{tracing, startedAt, rssKb, maxRssKb, tracedKb, growthKb, top:[{sizeKb, count, stack}], types?}`（`types` 全堆遍历，大堆要几秒）；`DELETE /api/admin/memory/trace` 关闭。追踪期间多占内存和少量 CPU，只在查泄漏时开一小时左右，查完关掉；不存任何数据。非管理员读 404、开关 403。
- 本站模拟的美元子账户（`paperusd:`，界面合成一个账户，见帮助主题 paper-account）：看美元复盘用 `reviewCurrency: "USD"`，以 applied 回执和 `state.review.currency/currencies` 核对。AI 工具读数（`get_account_summary`、`get_positions`、`get_account_activity`）在人民币本站模拟账户上带 `foreignAccount`（`status` ok / unavailable）；没点名合约的“全平”两本账都有仓时出两张关联平仓卡（`linkedProposalIds`），确认或放弃一张，另一张同一请求里跟着（返回 `linkedResults`）。保护：`POST /api/ai-execution/stops` 按合约落账，`GET /api/ai-execution` 与 `/api/ai-execution/stops` 在人民币账户上一起列美元那几条（带 `accountId`），撤销按保护记录自己的账户。读美元账照旧用账户头 `paperusd:…`（`GET /api/account/pnl` 返回 `currency`）。`POST /api/agent/suggestions` 的模型输入里美元那几行带 `currency: "USD"`；`GET /api/risk/summary` 不分两本账，返回 `unconfigured`。
- 快期每日例行维护时的状态码见帮助主题 agent、connection：不是故障，不要让用户重登或重输密码。
- 登录密码（帮助主题 ai-model）：本人改密码 `POST /api/auth/owner/password` 不在能力目录，管理员重置 `POST /api/admin/users/{username}/password` 排除在能力目录外（`app_call` 得 404）。两者都是人工操作：agent 可用界面命令打开或关上修改密码框，但不索取、不代填、不代提交密码；改好后其他设备登录失效属正常。
- 公共行情源清单（帮助主题 admin“行情源”）：`GET /api/admin/market-sources` 每源给 `channels`/`channelLimit`、`quoteSymbols`、`health`（healthy/full/unavailable）、`lastError` 与时间、`marketOnly`；`paperEngine` 给撮合引擎当前用的账号（`current`、`position`/`total`、`connected`）、`switchReason`（auth_failed/permission_denied/connect_failed/disconnected/removed）与 `switchedAt`、各账号 `accounts[].state`（active/connecting/standby/cooling，含 `lastError`、`retryAt`），没配引擎为 null，引擎不可达为 `{"error": …}`。`PUT /api/admin/market-sources`（body `{"accountIds":[…]}`）整份替换有序清单（不合格 422 `market_source_invalid`、重复 422 `market_source_duplicate`；漏掉行情专用账号 409 `market_source_remove_required`）。首次启动用 `AI_TRADER_SHARED_MARKET_ACCOUNT_IDS`（逗号分隔有序；兼容旧单账号名 `AI_TRADER_SHARED_MARKET_ACCOUNT_ID` / `AI_TRADER_GUEST_MARKET_ACCOUNT_ID`）播种，之后以库为准。添加 `POST /api/admin/market-sources/tqkq` 与移除 `DELETE /api/admin/market-sources/{accountId}` 涉及托管口令，不在能力目录，agent 不替主人加或删，请主人到后台“行情源”操作（备查：已在清单 409 `market_source_duplicate`、已是某用户的交易账户 409 `market_source_account_in_use`、号池上限不够 409 `market_source_pool_full` 带 `max`/`running`/`poolSources`；移除成员账户 409 `market_source_not_market_only`，改用 PUT）。

## 与内置 AI 对话（外部 agent 专用）

- `chat:send`（目录名 chat_send）：body `{"text":"…"}` 发一句话并等到本轮结束（默认 120 秒，timeoutSeconds 5–600，非数字 422），返回 `data.reply`、`toolSteps`（每项带 name 中文标签与 `tool` 原始工具名）、`model`（本轮实际模型 slug）、warnings、runStatus、sessionId、`accountId`（这个对话绑定的账户，本轮出的卡在它上面成交；省略 sessionId 时新会话绑到请求头指明的账户，没带头才落默认账户）；reply/toolSteps/warnings 只算本轮自己的内容——等待期间落进同一会话的提醒消息或别轮回答不会混进返回；确认“真的联网了/真用了某个模型”看 `toolSteps[].tool` 与 `model`，不看 Runtime 日志。省略 sessionId 新建会话，带上即续聊；`timedOut=true` 时用同一 sessionId 再问“上一轮结论”，不重发原话。
- 底层接口：`POST /api/sessions`（query `{"chat":true}`）、`POST /api/sessions/{session_id}/messages`（返回 runId）、`PUT /api/sessions/{session_id}/account`、`GET /api/models`、`PUT /api/models/preference`（切换本人模型偏好，下一轮生效）。事件流与删除会话不开放。
- 这些对话接口只给外部 agent 使用；内置 AI 在自己的一轮里调用会被拒绝（`chat_recursion_forbidden`），不要尝试让它给自己发消息。

## 游客模式

- 游客是什么、能看什么见帮助主题 guest。接口：`POST /api/auth/guest` 引导，`/api/guest/*` 是唯一游客业务入口；旧服务端或关闭游客时只有原登录入口。游客身份读 `/api/agent/capabilities` 得到游客清单，`uiControls` 列出游客可用的界面命令与取值。
- 行情、新闻、研究和界面命令用螺纹主力（`GET /api/guest/instruments` 返回的唯一合约）以外的合约返回 403 `guest_symbol_forbidden`。公共行情全部源满或不可用报 `guest_market_capacity`/`guest_market_source_unavailable`；换源后超时仍未就绪 503 `market_series_not_ready`；行情源缺失、停用或连接失败返回 503，不回退管理员账号，也不切换身份、不授予权限。容量不足、数据未就绪或来源失败时说明真实状态，不用私人行情接口兜底；不能承诺完整 3 天数据、任意历史区间或未经实测的并发容量。每一帧的 `workbench.historyTradingDays` 是当时生效的历史限额，游客快照 `marketHistoryTradingDays` 同值。
- 读 `/api/events` 事件流的客户端用 `PUT /api/sessions/{id}/feed/view {visible, board: {all | exchanges | products | symbols, key}}` 声明页面是否可见与要哪些总表行，之后收 `feed.board`（整份，带 `feedRevision`、`key`）与 `feed.board-patch`（相对 `base` 的变化，对不上就重发视图拿整份）；`visible:false` 时不推图表行情与总表，账户、委托、提醒等照推。只读一次总表用 `get_market_board` 或 `GET /api/market/board`。事件流每秒复核一次身份：登出或撤销后最迟约 1 秒断流。
- 游客按住说话只把转写交给 `/api/guest/voice/intent` 的窄界面意图（切周期、新闻、主题；切其他品种会被拒绝），不提交普通聊天或交易请求。观察与操作都用游客身份的 `/api/guest/ui`，`windowId` 必须来自该游客会话；不要用普通账户令牌或私人工作区接口操作游客。游客网页用独立 HttpOnly cookie；允许的桌面来源用 bootstrap 返回的内存 `accessToken`，仅发给游客 HTTP/SSE 与转写 WebSocket，不写入普通账户令牌、连接文件或浏览器存储。游客状态由快照同名字段和脱敏 observation 回读，不走私人 `/api/ui/pulse`；受限设置或交易命令被拒，打开登录用 `loginOpen:true`。
- 管理员档位：`marketHistoryTradingDays` 仅游客档可设 1/3/5（缺省 3，null 不能取消限制），普通档位只接受 null；guest 档不能成为默认、分配给正式成员或邀请码；游客语音同时受档位额度及全局 `voice-call` 开关约束。

### 网页下单面板与人工快捷动作

- 盘口、快捷区与快捷键、点价填入见帮助主题 order，对应界面命令（`quickVolume`、`selectedPrice`、`order-depth` 等）见帮助主题 ui-commands。交易快捷按钮仅人工，AI 只出候选卡，不得借快捷键或界面控件直接下单。

复盘历史读取与选择：当前窗口 `state.review` 的 currency、filter、month/day、selectedTradeId 描述复盘状态（month/day 是展开分组，不自动限制历史），`selectedTradeId/selectedNote` 回报选中记录与补充；读美元账历史用 `GET /api/account/pnl` / `GET /api/account/journal` 的 `currency=USD`（参数见接口说明，内置 `get_trade_journal` 同样接受 currency）。按用户指定日期与实际合约核对后，把读回的真实 id 交给 reviewSelect；等 applied 后确认币种及 selectedTradeId。日期或币种有歧义先询问，无匹配只报告本次范围无匹配，不改选另一账本或主连。
