## 连接与认证

- 实时推送每次建立或重连都会重放当前会话的合约/周期关注（focus）与页面可见范围（view），登记失败自动重试；短断线不需要刷新或切合约。切换会话后不会重放旧会话关注。此恢复只登记订阅，不重发交易或对话。

网页委托动作回报按委托所属账户立即同步当前列表和对话卡片；外盘合并列表同时重读。动作返回 409 时自动查询原委托，已结束时显示实际状态并提示不用重复操作；查询失败会提示继续核对，不会自动重发。

- 行情栏的合约按钮用固定高亮目标 `market:contract` 识别（中文名与代码随合约变化）；打开合约列表仍用 `dialog: {name: "contract-drawer", open: true}`。

- 网页版下载入口在右侧栏底部、设置上方（图标与“下载”标签，`download-client` / `rail:download`）；游客同样可见，新标签打开官网下载页，桌面客户端不显示。

打包 CLI/MCP 的标准输入输出使用 UTF-8；读取子进程管道时显式按 UTF-8 解码。

- 产品现名 Sente（中文名弈先，原 AI Trader）。技能 id、MCP 服务键、打包程序名（`ai-trader-runtime`）、接口路径与界面命令 id 都没有改名，仍是 `ai-trader`；macOS 上的应用包文件仍是 `AI Trader.app`。
- 先确认环境：`GET /api/runtime/status`。软件客户端没启动时 MCP 和 CLI 都连不上；先让用户在本机启动并登录 Sente。
- 客户端连不上应用服务时的表现（2026-10-11，读快照判断，不要据此重发写操作）：客户端的读取请求（GET/HEAD，含游客读取与生成的工作台客户端，时限覆盖读完响应体）30 秒无响应即报“应用服务 N 秒内没有响应”，调研、成交复盘、按我的习惯预填、策略引擎包 90 秒；写入（下单、回测、登录、注册等）客户端不设时限，结果以原请求为准。连接应用服务时，读取超时、断网和 5xx 都按暂时不可用处理，客户端退避自动重试（1 s 起、最长 15 s），服务恢复后自动接上；401 进入登录不重试；写入超时不算可重试。已连上的事件推送 20 秒无任何数据（含心跳）即自动重开，不再停在“连接中 / 数据恢复中”。启动“正在连接行情…”超过 10 秒出现“仍在连接…”和“刷新重试”（整页重新载入，不并发第二次身份检查）；身份读取超时时留在启动页显示原因和“刷新重试”，不进入登录框；登录框“正在登录 / 注册 / 创建…”超过 10 秒只显示“还在等服务器响应，请稍候”，没有重试——这些请求会消耗邀请码、建号、计入登录失败次数（按真实来源地址计数，同一地址共享来源预算，快期账号的现行账号级限制也保持），不能替用户重发。使用说明读不到时卡内写原因与“重试”（快照 `state.help.loadStatus/loadError/canRetry`，界面命令 `help: {retry: true}`）；合约列表没读到写“合约列表暂时读不到（应用服务未连接）”（游客为“公共行情暂不可用”），不是“没有匹配”，失败或空目录的“重试”是界面命令 `contractCatalogRetry: true`（游客会话失效时不可用，要用“重新连接”；目录重试从不新建会话）（抽屉打开时快照 `state.contractCatalog.status/canRetry`）；说明正在读取时 `help: {retry: true}` 被拒；设置 → 图表中存在账号上的选项未连接时禁用并写明原因；连接进度“已等待 N 秒”从出问题时算起，同一账户重试不清零，连上或切换交易账户才重新计时。

- 没有 MCP 的宿主用同一可执行文件的 CLI：`cli capabilities` 查目录、`cli capabilities --operation '…'` 查单个接口定义、`cli call` 调用（AppCall JSON 经标准输入或 `--file` 传入；多账户时加全局 `--account <账户id>` 指明作用的账户，id 取自 `GET /api/accounts`，不填按会话或默认账户）、`cli skills list|show`（`--resource` 读附加资源）、`cli doctor` 检查初始化与账号连接、`cli migrate-strategies` 迁移旧策略（`--apply` 保存到当前登录账号；只迁移定义、按内容去重、不启动监控）。
- 云端 Runtime 有两个入口（2026-10-11）：桌面客户端、打包 CLI/MCP 直连 `https://ai-runtime.qilinshuzhi.com:8443`；网页版走官网同源中转 `https://qilinshuzhi.com/trader-runtime`（只放行 80/443 的网络也能用）。两者是同一个 Runtime、同一套接口，登录各自独立。
- 连接信息来自本机 0600 的运行时连接文件。凭据由程序读取，不能查看连接文件、读取 Keychain 或把令牌放进模型参数；不向模型提供密码或 Key。
- 配置外部 OIDC 的部署遇到格式无效令牌会受控拒绝（401），需重新认证；不返回内部 500，也不要绕过认证重试业务写入。
- 外部 Agent 不因此获得额外交易授权：急停、风险检查和实盘关闭同样生效；接口与 CLI 用同一能力目录、均需认证；切换模型不改变能力与权限。实盘始终关闭，不存在的能力要明确报告，不能用任意脚本、DOM 注入或鼠标模拟绕过业务边界。

本站模拟持仓读取：`GET /api/positions`（含 `paperusd:…`）行情中断仍返回 200 和最近撮合账本仓位；必须连同 `dataStatus`、`isCached`、`ageSeconds` 解读，价格与盈亏可能沿用最近快照。首次装配最多等 2.5 秒；超时 `snapshotAvailable: false`、`items: []`、`dataStatus: unavailable`，不能报告为确认空仓。引擎账户条目报错时同样只展示最近成功快照；快期读取及交易执行校验不变。

## 能力目录与统一调用

- 使用 `app_capabilities` / `app_call`（CLI 与内置模型同一套）。先读本次连接的能力目录，再以 `operation` 查所需接口的完整参数定义，不照抄旧版本字段。界面命令某个字段的完整定义与说明可用 `operation: "ui:<字段>"`（如 `ui:disclosure`）单独读取。内置 AI 自己读到的是同一目录的紧凑索引（按技能分组的操作、界面字段一行一个，可带 `query` 关键词过滤），不常用的工具按技能挂上后才出现（2026-10-14）；外部 Agent 的目录不变。内置 AI 自己经 `app_call` 读 `GET /api/app/help` 且不带 `query.topic` 时拿到的是目录（分组与各主题 title/group/summary），全文按 topic 读一个主题，带 `query.search=<关键词>` 拿提到该词的句子；它上一回合读到的工具结果再带一回合时每条截到 4000 字符——外部 Agent 读这个接口仍返回完整 HelpSnapshot。
- `operation` 保留目录中的 `{路径参数}` 占位符，实际值放 `path` 的同名键，如 `{"operation":"GET /api/app/ui/windows/{window_id}","path":{"window_id":"实际UUID"}}`。已读定义在同一构建和登录会话内复用；不能把 MCP/CLI 的结构化参数与内置模型的 requestJson 字符串封装混用。
- 内置技能注册表：内置 AI 的每项能力都是一个技能（每个技能一个 SKILL.md，随 Runtime 打包）。按渐进披露使用：先 `list_skills` 看当前账号可用的技能（停用或档位未开通的不出现），`activate_skill` 读完整手册，`read_skill_resource` 读技能目录内 `references/` 相对路径。HTTP 等价 `GET /api/agent/skills`（含每个技能的可用状态与不可用原因 `disabled`/`not_in_plan`/`owner_only`、`aiFeature`）、`GET /api/agent/skills/{id}`、`…/{id}/resource?path=…`。
- 技能可有一个上级（`parent`，仅一层）：上级停用或档位未开通时子技能一并不可用，可用状态沿层级判断。主账号的全局停用只管 AI：`disabled` 的技能对外部 AI 不可用，即使界面上用户自己还能点；不要引导用户绕开，也不要绕过 `app_call` 直接调它的接口。只有 `aiFeature: true` 的技能停用后用户本人也用不了。
- 帮助与解释口径读取 `GET /api/app/help`（两层结构）：解释功能先用人读层（summary/steps/faq），细节在 `detail`；解释策略术语优先引用 `strategy-glossary` 的 `terms`，与模板参数 `help` 口径一致。`?topic=<id 或旧 id>` 只返回该主题，未知 404。

## 界面命令与快照

- 顶栏标签只列手动钉住的合约；普通 `symbol` 切换不修改收藏。顶栏未显示当前标签（未钉住或折进“更多合约”）时，窄图表的合约按钮保留当前名称；顶栏收成下拉时显示当前合约。新闻 `pinnedSymbol` 是阅读品种，可与图表不同；读当前图表以快照 `state.symbol` 为准。

- `GET /api/app/ui/windows` 读在线窗口、状态与 revision。MCP 默认筛选本机设备，内置 AI 默认筛选发起对话的窗口；明确需要其他设备才用 `query: {"deviceId":"*"}` 并固定 `windowId`。多窗口时按已知环境选择，无法确定才询问用户。检查 `device.platform/version/build` 与 `connection.build/compat`。1.7.2 起正式桌面的 `device.build` 与快照 `context.connection.build` 均回报实际源码提交；先筛选在线目标窗口再核对发布 SHA。旧客户端的缺省、空值或 `dev` 不构成来源证明，`compat: ok` 只证明版本兼容。外部 Agent 请求可带 `X-AI-Trader-Client: agent/<版本>`，Runtime 在每个 `/api/` 响应回 `X-AI-Trader-Client-Compat`（只判客户端是否过旧；网页刷新由网页客户端对照 version.json 判断）。网页窗口快照 `context.webUpdate: {available, banner}`：有新版本时页面在回到前台且空闲时自动刷新，忙时显示“新版本已就绪 · 刷新”提示条；刷新与“检查更新”是用户操作，没有界面命令——用户问“网页怎么还是旧版”时让其点提示条的刷新或 设置 → 关于 / 手机我的页底部的“检查更新”。

### 策略与回测

- 外盘策略（外盘三期，2026-10-20）：合约写 `CME.<MT5 月份>`（如 `CME.GCEZ26`），适用范围写品种 `CME.GCE`；根代码可带数字（外汇 `CME.EU6Z26` / 范围 `CME.EU6`，微型罗素 `CME.M2KZ26` / `CME.M2K`）；外盘图表符号 `KQD.m@COMEX.GC` 传给模板、回测、试参数时由 Runtime 换成主力月份。外盘策略的保存、回测、试参数、上线与 `start_strategy_monitoring` 都自动落到美元子账户（`paperusd:` 编号），人民币账户的会话里调用也一样，不用先切账户；实例出现在美元子账户的 `GET /api/strategies/{id}/monitor` 与运行列表里。金额（单笔预算、当日亏损上限）按美元。分钟到小时周期与日线的回测与实时判定都用该月份合约的 MT5 行情（最多 1 万根，1 分钟约近一周；日线由小时线按 CME 交易日合成，约近 100 个交易日）；手续费按每手每边 2.5 美元。交易日与时段按 CME（美东 18:00 换日），`tradingSchedule.dayRule="cme"`（合约目录 `GET /api/instruments` 的外盘主连带；2026-10-21 起可交易外盘主连图表的行情快照——`GET /api/markets/{symbol}/workbench` 各周期、`GET /api/market/{symbol}`、推送——也都带：`quote.tradingSchedule` 是这个品种的 CME 时段（`cmeHours`：globex（金属、能源）与 equity / rates / fx（股指、美债、外汇，平日时段相同、只是节假日停盘时刻不同）北京时间夏令时 06:00–次日 05:00 写作 `06:00`–`29:00`；grains 美豆/豆粕/豆油/玉米/小麦两段，夏令时 `08:00`–`20:45`、`21:30`–`26:20`（芝加哥 19:00–次日 07:45、08:30–13:20）；livestock 瘦肉猪 `21:30`–`26:05`（芝加哥 08:30–13:05）；冬令时各晚一小时），`marketSessionStatus` 按它判定，休市时 `quote.sessionClosedFor` 是 intraday（同一交易日两段之间）/ break（交易日之间的每日停盘）/ weekend / holiday（CME 节假日：全天休市、提前收盘或节日当天停盘，美国节日当天的盘属于下一个交易日）、`quote.sessionReopensAt` 是下次开盘；日线 K 线是 MT5 主力月份的小时线按 CME 交易日合成（2026-10-21 起），周线的 K 线是快期外盘主连，报价与 `ageSeconds` 都是主力月份的 MT5 实时报价（`quote.source` 如 “MT5 · ENQZ26”，与下单、撮合同一份），直接读快照判断开没开与新不新鲜）。`GET /api/app/activity?symbol=<外盘合约>` 在人民币本站模拟账户上带美元子账户同一品种的委托、成交与保护单（每条 `accountId` / `currency: USD`，`foreignAccount.status`）；`GET /api/trade-review?symbol=<外盘合约>` 同样带美元子账户同一品种的回合（每条 `accountId` / `currency: USD`，金额汇总、`currency`、`costSource: foreign` 取子账户的，`foreignAccount.status`），不带 symbol 的整账户复盘不混入美元。

### 私人记忆

- 每个账号一份长期记忆，三层：profile 画像、rule 约定（只收用户亲口说的话）、lesson 经验（用户原话 + 程序统计算出的）。接口都要登录、按账号隔离，别人的 id 一律 404“没有这条记忆”。
- `GET /api/memory?includeInvalid=false` → `{enabled, items, changes}`（items 每条 id/layer/layerLabel/text/source/evidence/tags/status/createdAt/updatedAt；changes 是最近 20 条变动）。`POST /api/memory` body `{layer, text, quote?, products?, via: settings|chat}`：`via=chat` 必须带 quote（用户原话 ≤200 字），服务端与最近 7 天用户消息比对（两边去空白与中英文标点），对不上 422“没在你最近的对话里找到这句原话”；text ≤120 字；命中授权句式（“直接帮我下单”“不用确认”“授权”等）422“记忆不能当授权用”；`chat.memory` 关闭时 409。`via=settings` 不做原话核对——但这条豁免只认用户自己的请求：经 `/api/agent/call` 转发的调用（AI 走能力目录）一律按 `via=chat` 处理，body 里写 settings 也不豁免原话核对与开关，PUT/DELETE/undo 的审计 actor 记 ai。来源只由调用身份决定（经 `/api/agent/call` 的嵌入 agent、MCP `app_call`、打包 CLI 都算 AI 调用），模型不能靠 body 改来源。`PUT /api/memory/{id}` body `{text, quote?}` 改文本：AI 调用必须带 quote（同上核对，依据改为这句原话），没带或对不上 422、`chat.memory` 关闭 409；AI 的撤销在 `chat.memory` 关闭时也 409（撤销会把记忆带回来），AI 的 `DELETE`（忘掉）照常可用；设置页人工新增/修改/删除/撤销不受开关限制。`DELETE …/{id}?via=` 失效（不物理删除）；`POST /api/memory/changes/{change_id}/undo` 撤销原变动所对应的状态：可连续撤销/恢复，重复请求且状态未再变化时复用结果、不重复写入；已有后续编辑或旧审计依据不足时 409，重读文档后由用户决定，不盲重发旧撤销。
- 每日自动整理（北京时间 06:00，前 24 小时有活动的账号；`chat.memory` 关闭整个跳过）：①程序统计（不调模型）按近 90 天已平仓交易算画像与经验（含忙闲日对比 `stat:busy-days`：按平仓笔数取最忙与最闲的四分之一交易日，只看人民币合约，两边各 ≥5 笔且忙日每笔平均差出 30% 以上才记），按 statKey 就地更新，规律不再成立标失效，用户删掉的统计条目不再自动加回，用户在设置里改过文字的统计条目（evidence.userEdited）不更新、不失效、不并排另记；费率来源是账户（没有逐笔费率）时统计按毛收益、复盘同一层费用遮罩，evidence.pnlBasis 注明 gross/net。②从用户原话提炼（一次便宜模型调用，只读用户自己的话与交易补充——用户消息在 SQL 里过滤，AI 回复再多也不挤占窗口，最多 5 个操作，逐条程序校验：原话必须真在材料里、不能是授权、只能改模型实际看过且写入时仍是原版本的 source=user 条目，不与已有重复；等待期间人工纠正、删除恢复、A→B→A 都使旧候选失效，结果计入 words.rejected，同批合法操作沿已成功的新版本继续）。统计与提炼共用同一个采纳前复核：写入的短事务里重读 `chat.memory`、本次整理认领与材料来源，等待/计算期间开关关闭或整理被取消、接手时整段不写（`stats`/`words` 为 `{skipped: "disabled"|"cancelled"}`），原话所在会话被删、补充被改或删时该候选拒为“原话已删除或已改”；用户删掉的记忆只挡删除前的同一材料，删除后新说的话可以再记。整理状态：失败（任一段报错、取消）记 error 并可重试（每日整理同一天最多 3 次，之后由下一天带着失败那次的材料窗口补整理，最多回看 72 小时），全部完成才记 done。手动触发 `POST /api/memory/consolidate`（同一账号 10 分钟内重复 429；`chat.memory` 关闭 409；接手当天认领，失败如实记 error）。
- 记忆不构成任何授权（见交易与安全边界）。内置 AI 工具 remember / forget / recall_memory（技能归属 preferences）。对话每轮自动带少量记忆，语音通话只带画像；问“你记得我什么”读 `GET /api/memory` 回答。

### 我的流程

- 用户把一串固定做法存成有名字的流程（2026-10-06），每人最多 5 个、每个最多 10 步、名称 1–12 字。步骤 `{kind, text}`，kind：read 读（今日判断/调研/简报/持仓账户）、draw 画线、backtest 回测、margin 算保证金与可开手数、card 出开仓/平仓卡（只出卡）、alert 到价提醒、watch 盯异动（加进 AI 简报订阅）、review 复盘。
- `GET /api/routines` → `{items: [{id, name, steps: [{kind, kindLabel, text, manner?}], stepCount, createdAt, updatedAt, lastRunAt}], limits, kinds}`。`POST /api/routines/drafts {name, steps, routineId?, sessionId?, turnId?}` 出一张流程卡（`card.routine`，草稿，不落成流程；同名或带 routineId 即改那一个）；名称、步骤或用户刚说的话含免确认下单、自动下单、改风险设置、自主执行开关时卡为 `status: refused`、没有保存按钮。超 10 步、已有 5 个时新建 → 422。
- 保存只能是用户本人在界面上：`POST /api/routines {draftId}`（流程卡的“保存”）或 `{name, steps}`、`PATCH /api/routines/{routine_id}` 对 agent 一律 403——不要试图替用户保存或改名，告诉用户点卡上的“保存”。`DELETE /api/routines/{routine_id}` 只在用户明确说删时用。
- 运行：用户整句就是流程名或“跑一下 / 运行 + 名称”时 Runtime 直接运行；agent 要替用户运行用 `POST /api/routines/{routine_id}/run {sessionId, quote}`（quote＝用户含流程名的原话，服务端核对），在那段对话里排队发出“跑一下<名称>”，额度与普通对话相同；运行的就是路径里这个 id 的流程（界面的“运行”同样在消息里带 `routineId`），不会因别的流程名字像而跑错，排队期间被删则回答“这个流程已经不在了”、不运行别的。不要自己启动流程。提醒 / 画线 / 盯异动步骤的原话含“看看有没有必要 / 要不要 / 需要的话”时，那一步没有写入工具、只给建议（步骤 `manner: advisory`，卡上标“只给建议”）；原话另带“需要就设 / 有必要就设 / 该设就设 / 合适就设”这类执行从句时是有条件执行（`manner: conditional`，标“需要时执行”，判断后可以设）；普通步骤没有 manner。拟卡时步骤文本保留用户原话，不要自行追加执行从句；对话里的流程卡保存、改名、删除后，下一轮的系统说明会写明现状。
- 运行期间：每一步只给这一步类型的工具，整个流程没有任何直接下单、撤单、止损、自主执行、策略上线或改设置的工具（AI 自主执行开着也一样）；出卡步骤的卡等用户确认，语音的“免口头确认”不替流程的卡确认（chat:send 结果 `routine: true`）。进度卡 `card.routine_run`（同一 cardId 原地更新）：每步 `status` waiting / active / done / confirm（出了卡等确认）/ failed / skipped 与一行 `result`，卡 `status` running / completed / stopped（某步失败，后面不做）/ cancelled，`elapsedSeconds`、`confirmCount`。
- 界面：设置 → 记忆（手机 我的 → AI 与记忆）的“我的流程”分区，`settingsPage: memory`；某行“删”的二次确认 `disclosure: routine-delete`（id＝流程 id）；快照 `routines` 带列表。内置 AI 工具 propose_routine / list_routines / run_routine（技能 routines）。

## 与内置 AI 对话（外部 agent 专用）

- `chat:send`（目录名 chat_send）：body `{"text":"…"}` 发一句话并等到本轮结束（默认 120 秒，timeoutSeconds 5–600，非数字 422），返回 `data.reply`、`toolSteps`（每项带 name 中文标签与 `tool` 原始工具名）、`model`（本轮实际模型 slug）、warnings、runStatus、sessionId、`accountId`（这个对话绑定的账户，本轮出的卡在它上面成交；省略 sessionId 时新会话绑到请求头指明的账户，没带头才落默认账户）；reply/toolSteps/warnings 只算本轮自己的内容——等待期间落进同一会话的提醒消息或别轮回答不会混进返回；确认“真的联网了/真用了某个模型”看 `toolSteps[].tool` 与 `model`，不看 Runtime 日志。省略 sessionId 新建会话，带上即续聊；`timedOut=true` 时用同一 sessionId 再问“上一轮结论”，不重发原话。
- 底层接口：`POST /api/sessions`（query `{"chat":true}`）、`POST /api/sessions/{session_id}/messages`（返回 runId）、`PUT /api/sessions/{session_id}/account`、`GET /api/models`、`PUT /api/models/preference`（切换本人模型偏好，下一轮生效）。事件流与删除会话不开放。

## 游客模式

- 支持游客的服务端中，游客是免手工登录的短期身份（`POST /api/auth/guest` 引导，`/api/guest/*` 是唯一游客业务入口；身份一小时失效，服务端重启也结束会话），与测试档、普通会员共用同一工作区，不另设游客页面；额度按实际访客来源地址计算；同一来源地址共享来源额度，不同来源地址分别计算。旧服务端或关闭游客时保留原登录入口。

## 米家遥控器 2 Pro（本机）

设置 → 语音保留启用、连接状态与连接/断开；`settingsPage: "remote-keys"` 打开按键设置，`settingsPage: "remote-diagnostics"` 打开测试与诊断，二者返回语音页。语音命令“打开遥控器按键设置”“打开遥控器诊断”对应相同页面。

| 表面 | UI 命令 | 观察 |
| --- | --- | --- |
| 语音 / 按键设置 / 测试与诊断 | `settingsPage: "voice" / "remote-keys" / "remote-diagnostics"` | `state.settingsPage`、页面文字与控件 |
| 遥控器本机设置 | `remoteSettings: {enabled?, bindings?, resetBindings?, diagnostic?, disconnect?}` | `state.remoteSettings`：enabled、phase、supported、platform、deviceName、error、keyError、bindings、availableKeys、diagnostic、lastKey、frames、level |

布尔字段只接受布尔值；bindings 为按键到动作的对象。按键：up/down/left/right/ok/back/home/menu/tv/volumeUp/volumeDown/voice/power；动作：none/ptt/cancel/chat/settings/scrollUp/scrollDown/focusPrevious/focusNext/activate。ptt 仅语音键可用；none 停用该键，resetBindings:true 恢复全部默认。activate 不自动提交交易。诊断必须先打开 remote-diagnostics，再 diagnostic:true；离开自动停止，不保存或上传录音。连接必须用户亲自点击“连接遥控器”并选择硬件，AI 不能代选。

仅按键配置按本机设备保存，不同步账户；启用与连接须在当前窗口明确开启，不自动启用或连接。Mac 客户端按设备识别按键；Web 只可靠隔离 ATVV 语音键，其余键显示“浏览器不支持，Mac客户端可用”，仍可预配；连接期间 F5 暂为遥控语音保留，断开恢复刷新；其他普通键盘不受影响，普通 F5 不会录音。Windows 客户端暂未实现。游客不开放语音设置与本机遥控器命令。

Mac 须允许输入监控；仅客户端前台接管 VID2717/PID32b8 的 13 键，按设备临时 UserKeyMapping 静音原系统功能，失焦、断开、退出恢复既有映射；有其他遥控映射冲突或无法安全接管时，连接失败并显示原因，先关闭其他遥控软件或补齐权限后重试。诊断启动要求 ready，不能同批停用或断开；断开不能同批启用；恢复默认与 bindings 不可同批。空对象与 null 字段拒绝。resetBindings 回执以 state.remoteSettings.bindingsDefault 为准。

会员模型可通过 `GET /api/models` 与 `PUT /api/models/preference` 选择 Kimi K3.1 Pro（`k3.1-pro`），由档位控制权限；Runtime 复用 Kimi Code 密钥直连，原 GPT 偏好在读取时兼容映射，不使用 GPT 专用代理。
